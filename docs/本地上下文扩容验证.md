# 本地上下文扩容验证

日期：2026-11-07。使用同一份 24 页离线日志材料，对本机 Qwen3.5 9B 的轻量会话进行实测。
本次调整运行配置，未修改 Agent 的调查、整理、工具或答案登记逻辑。

## 条件与解释边界

- Linux、RTX 4060 Laptop 8GB、16GB 系统内存；llama.cpp b12186。
- Q4_K_M 文本权重、CPU 视觉投影器、单槽、全层 GPU、Q8 K/V、Flash Attention；
  batch 512、ubatch 128、8 个 CPU 线程、关闭思考，沿用原采样参数。
- 扩容测试将主存提示缓存设为 `--cache-ram 1024`，此前 32K 会话使用默认设置。
  该参数控制主存提示缓存，不改变 GPU KV 缓存精度。
- 推理服务 `-c` 与灵枢模型的 `context_window` 同步。每档使用新会话，
  通过浏览器上传相同材料；成功读取第 5 页、第 18 页后，在模型请求进行中发送补充消息。
- 32K 对照来自前一轮，两条补充消息都在后段发出；各档仅一次完整调查实验，
  没有固定随机种子或控制所有系统负载。因此不能将成功率和耗时差异全部归因于窗口。
- 显存与主存每 5 秒采样一次，记录的是监测最大占用，不是硬件瞬时峰值。
  配置容量与服务实际报告的输入 token 分别记录，没有将窗口全部填满的压力测试。
- 本机启用了交换空间，各轮都有系统级换页活动；不是无交换环境下的内存保证。
  推理进程、浏览器与其他本机负载没有完全隔离。

## 已完成的真实会话

| 窗口 | 最大实际输入 token | 显存监测最大值 | 最低空闲显存 | 调查结果 |
| --- | ---: | ---: | ---: | --- |
| 32K，前轮 | 18,744 | 约 5,756 MiB | 未连续采样 | 24 个分页调用成功，随后否认早先关键事件；主动停止 |
| 64K | 42,833 | 6,436 MiB | 1,454 MiB | 保留了正确的主体、对象与关联号，随后反复回读相同的历史片段；主动停止 |
| 96K | 65,137 | 7,116 MiB | 774 MiB | 正确答案登记后自然结束；早期信息出现编造，报告缺项 |
| 128K | 73,643 | 7,796 MiB | 94 MiB | 登记了与夹具真值一致的答案并自然结束；证据报告未满足全部要求 |

64K 会话有 61 次模型调用、32 次工具调用。两次补充消息约 28.5 秒、51.2 秒后
入模并公开确认。末尾需要的收据位于历史工具消息约第 3800 个字符处，模型却连续
重复 `history_read` 的前 2000 个字符，没有使用返回的 `next_offset`。已经保存的
原文仍可读取，问题在模型没有正确续读；停止前最长连续相同工具参数调用为 4 次。

96K 会话有 42 次模型调用、33 次工具调用，成功执行 24 个分页读取，约 18 分 30 秒后
自然结束并登记正确答案。两次补充消息约 32.8 秒、68.3 秒后入模并公开确认，继续了当前
分页。未出现连续完全相同参数的工具调用，但登记时曾复用旧验证回执被拒绝，随后补做
验证；这不代表不存在语义重复或已经解决长期循环。系统可用内存最低约 3,414 MiB。

96K 的公开进展和答案复核文本编造了首两页中不存在的采集点编号；最终报告漏掉真实
收据、采集点和两个补充消息标记。验证脚本只断言模型自己填写的答案常量，没有回查
原始日志，因此正确答案登记不等于完整验收通过。最终浏览器检查到 12 个节点、11 条
连线，节点详情与黑板原记录一致，刷新保留，未发现页面脚本错误。

长会话结束后，在同一 96K 服务上独立执行真实 `view_image` 烟测，正确识别颜色、
图形及图片校验码，约 7.45 秒返回。该图片请求实际输入仅 426 tokens，不是长历史与
图片混合的满窗口压力测试。包含这次烟测的显存监测最大值为 7,118 MiB，最低空闲 772 MiB。

128K 会话有 58 次模型调用、30 次工具调用，成功执行 24 个分页读取，并在一次
复核拒绝后执行验证调用、登记正确答案、自然结束。两次补充消息约 30.8 秒、80.6 秒后
入模并公开确认。浏览器检查到 10 个探索节点、9 条连线，详情与黑板匹配，刷新保留。
本机显存最低仅剩 94 MiB，不能由单次无 OOM 推断日常负载仍有足够余量。

128K 的完整验收仍未通过：报告没有保留要求的早期收据、采集点和两个补充消息标记；
验证脚本只对模型自己填写的常量做断言，未独立回查原始证据。64K、96K、128K 的模型证据笔记
revision 都为 0，观察黑板正常持久化不代表模型已经主动维护关键发现。

此外，24 个分页命令成功不等于全部日志行都已进入模型。轻量 shell 在采集预览与
模型展示阶段分别限幅；本例有一条关键事件存在于完整落盘日志中，却不在发送预览里。
`history_read` 回读的是原始工具消息，消息本身若是预览，仍须继续读取完整产物。
扩大总窗口不会自动取消这层单次结果限幅。

较长输入也增加了消息等待时间。96K 会话中，一次输入 61,240 tokens 的请求仅报告
3,508 个缓存输入 tokens，首个流式片段等待约 35.9 秒，整次请求约 40.9 秒。
这是单次请求的现场记录，不是吞吐排名；后续还应分别改进历史读取和提示前缀复用。

## 同一历史的只读回放

对前一轮同一个 33 条工具结果的检查点，保持原文不变，仅替换容量预算：

| 容量 | 整理后的估算 token | 发送视图保留的完整工具消息 |
| --- | ---: | ---: |
| 32K | 21,215 | 7 / 33 |
| 64K | 42,263 | 17 / 33 |
| 96K | 63,496 | 27 / 33 |
| 128K | 73,147 | 33 / 33 |

这是离线投影统计，没有调用模型，也不证明推理或报告正确；“完整工具消息”仍可能包含
明确标记的输出预览。结果确认扩大窗口可以减少历史归档，但分页回读、完整产物读取、
证据笔记和报告完成条件仍需要分别验证。

## 本机保留的配置

本机保存 96K 作为下一阶段的试用容量：llama.cpp `-c 98304`，灵枢对应模型
`context_window: 98304`。继续使用单槽、Q8 K/V、Flash Attention、CPU 视觉投影器，
并将主存提示缓存设为 `--cache-ram 1024`。启动脚本与模型清单已同步，备份仅保留在本机。

选择依据是较大的历史保留空间和显存余量，不代表 96K 已通过全部调查验收。
128K 作为本机边界实验记录，暂不作为日常配置。其他显卡、Windows 显存占用、
不同量化或投影器部署需要重新测量；队友初次部署仍从较小窗口验证连通与工具。
具体调整步骤见 [Windows 轻量测试](Windows轻量测试.md#增大上下文)。

原始审计、会话数据库、个人模型配置和截图仅保留在本机，不随测试仓库发布。
