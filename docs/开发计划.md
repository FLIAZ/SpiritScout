设计书第三章及附录中的【经验总结/一方观点】内容按合理工程判断落地，取舍如下（理由随附）：

| # | 文档条目 | 取舍决策 | 理由 |
|---|----------|----------|------|
| J1 | ATT&CK「15 战术（新增 Stealth TA0005 / Defense Impairment TA0112）」（附录B称已访问官网确认） | **入库但标注版本待核验**。种子数据按文档给定 ID 入库，schema 中保留 `attack_version` 与 `last_verified` 字段，支持季度同步与 deprecated 标记 | 文档自身要求「以 attack.mitre.org 为准并做版本同步」（3.3.6）；研发环境无法复核官网，故按文档入库 + 版本化机制兜底 |
| J2 | 15 条可借鉴设计点（3.2.4） | 全部采纳，但其中「Neo4j 知识图谱」「CyberBattleSim 自训练底座」列为**可选扩展，不进 MVP** | 文档 3.5 亦将 Neo4j 标为「可选」；CyberBattleSim 与核心链路无耦合 |
| J3 | AWE「3 条路线按漏洞类绑定流水线而非 LLM 自由发散」 | **采纳为默认实现**：路线生成器内置「漏洞类→工具→参数→判定特征」模板，LLM 仅在模板槽位内做参数级发散 | 与 PenForge「工具误用是主失败因」结论互证，工程上也更易测试 |
| J4 | SRC P0~P4 分级与 weight 自动判定（附录C §5.2） | 采纳为合规引擎默认权重表，但**规则引擎输出必须可人工覆写**（终审权在主 Agent/人工） | 与 4.1.1「漏洞终审」、9.1「人工终审入口」一致 |
| J5 | 「仅中危及以上进收录池，低危仅记录」（3.4.6 第 1 条） | 保留该基线为**默认策略**，平台规则库中仍存低危规则（`recommend_submit=false`），可在冲量/公益 SRC 场景经配置开启 | 文档明确「保留该规则但默认不推荐提交低危」 |
| J6 | 6 类攻击路径模板（3.3.4/附录B §四） | 全量结构化为种子数据；路径中含钓鱼（路径 5）与数据外泄（路径 6）条目**默认禁用**，仅在授权声明显式开启对应 scope 后可选 | 钓鱼/外泄属高敏操作，按「默认安全」原则落地 |
| J7 | 调研中「未能核实」的 3 个项目（Vultur / gpt-pentester / AIIS） | 不纳入任何设计依据与知识库语料 | 文档自身标注「未能核实」 |
| J8 | ByteSRC「禁自动化、只手工」等平台红线 | 入库为硬规则：当目标平台 `auto_test_allowed=false` 时，系统**拒绝启动自动探测**，仅允许生成人工测试清单 | 合规优先于功能；防止误用导致违规 |
| J9 | HackSynth「CTF 语境 prompt 防拒答」+ ARTEMIS「in-scope 边界 prompt」（3.2.4-14） | 采纳：三种模式各有 system prompt 模板，显式声明授权范围与禁止事项 | 既防拒答又防越界，与 C5 护栏联动 |
| J10 | 分支健康度公式（6.5）与赛制优先级公式（6.7） | 按文档公式实现，系数做成**可配置项**（默认值 = 文档值） | 公式系数是经验值，需可调参 |
| J11（M2 补充） | 默认 3 条路线 vs 弹性 1~8 条（6.2） | 路线模板固定产出默认 3 条（C2）；**情报驱动的动态追加路线**（如侦察线索跟进）在 `max_routes` 硬上限内放行，不经默认条数截断 | 黑板线索是跨 Agent 协同的核心载体，若被默认 3 条截断则线索永远无法消费 |
| J12（M2 补充） | 健康度剪枝误杀长字典枚举路线 | 保持公式不变；**确认命中的步骤给足价值分**（0.8），使有产出的路线健康度稳定在阈值上；无产出路线仍被快速剪枝 | 字典枚举类路线前进步骤天然零价值，纯按公式会在第 2~3 步误杀已命中路线；调价值分而非改公式，符合 J10「系数可配、公式稳定」 |
| J13（M2 补充） | LLM 收敛建议与 DAG 未竟任务的冲突 | 主 Agent 复盘节点中，**DAG 存在未完成任务时规则引擎否决 LLM 收敛建议**（审计留痕 `llm_stop_vetoed`） | 「模型是建议者、规则引擎是裁决者」（4.9.5）的直接落地；否则 Mock/保守模型会在依赖任务未执行时提前收工 |
| J14（M3 补充） | CTF 定向路径枚举路线被健康度剪枝误杀 | 同 J12 原则：**CTF 定向路径（CTF_SOURCE_PATHS）确认命中按高价值计分**（0.4），页面普通命中 0.1；公式与系数不变 | 赛题源码路径枚举前 2~3 步均为低价值探测，纯按公式在宽限期后即被剪枝，永远走不到 /flag.txt；与 J12 同属「调价值分而非改公式」 |
| J15（M4 补充） | Chroma 语义检索需要 embedding 模型（3.5） | 默认 `hash` embedding（blake2b 签名哈希投影 ASCII 词元 + CJK 二元组 → 512 维 L2 归一化），**离线零依赖**；`openai_compatible` provider 经 `embedding_base_url + api_key + model` 接云端推理；chromadb 为可选依赖，未装时语义检索显式报 `ConfigurationError` 并附安装指引 | 与「模型一律走 base_url+api_key、不依赖本地模型部署」的硬约束一致：hash embedding 语义能力弱（近似关键词扩展），只作召回增强；真实语义质量由用户配置云端 embedding 获得。未安装 chromadb 时不静默降级为关键词检索，而是明确报错给两条出路 |
| J16（M4 补充） | 附录C-2.2 P4 级「直接判无效不入库/不提交」未指明在核验流水线哪一环节执行 | P4（weight=0）判定放在**初筛（screen）阶段**而非合规阶段：命中即 `REJECTED_SCREEN`，不再消耗复现/PoC 资源 | 附录C-2.2 标题语义即「直接判无效」；若在合规阶段才拦截，self_xss 等无复现方法的类型会先被复现阶段以「未复现」误拒，理由失真；前置到初筛既忠实文档又省算力 |
| J17（M4 补充） | 平台红线规则的单一事实来源 | 运行时 `_PLATFORM_PRESETS` 硬编码删除，平台规则一律由知识库 `base_vuln_standards` 装载聚合（`platform_rule_view`）；未知平台回退通用视图（允许自动化、无报备项） | 设计书 3.4 将 7 平台规则定义为知识库内容；硬编码 preset 会造成两处事实源漂移。未知平台给通用视图是显式默认而非静默降级——CLI 输出与审计均标注所用规则视图来源 |
| J18（M5） | 投票分歧时的裁决归属：4.9.3-2「分歧降级复核」未指明是否改变漏洞收录状态 | 分歧**不改变裁决状态**：`compliance["review_required"]=True` + 审计留痕，收录/拒绝仍由规则引擎（4.3.2 基线）独立裁决；投票仅适用 6.10 限定的不可逆高影响判定（高危/严重收录） | 「模型是建议者、规则引擎是裁决者」（4.9.5）的直接推论；若让模型投票否决规则裁决，等于裁决权让渡给模型，违背系统最根本的护栏设计。「降级复核」的工程语义是**标记人工复核**，不是自动拒绝 |
| J19（M5） | 6.5 风险分完整化（探测频率/拦截信号）上线后，CTF 源码审计路线在抵达 /flag.txt 前被剪（健康度 0.198 < 0.2 阈值） | 源码路径命中价值分 0.4→0.45，**只调价值分不改公式/阈值** | J14 定 0.4 时对剪枝阈值的余量仅 0.0045；新增频率风险分量（2 步约 0.007）恰好将其推过线。价值分本来就承载「命中目标物的信号强度」语义，微调它是系数调参（J10 可调原则），而改公式或豁免 CTF 模式都会破坏健康度机制的一致性 |
| J20（M5.5） | 设计书监控面板技术栈为 Vue + ECharts（4.7/第七章/交付物#4），A5 原将其后置 | 修订 A5：**FastAPI + uvicorn（新增二依赖）+ 无构建单页前端**（内联 CSS/JS、零外部资源、内网离线可开）；实时推送用 **SSE 跟随审计 JSONL**（行号游标 + Last-Event-ID 续传 + 心跳），不用 WebSocket；形态为 Codex 式会话操作台（左栏会话列表 + 新建对话框 + 六 Tab 数据面） | 用户明确要的是「会话隔离的任务管理台」，不是可视化大屏：SSE 单向推送已够（无客户端上行流），无需 WebSocket 双向复杂度；无构建单页免除 Node 工具链依赖，与设计书「内网隔离环境可运行」（CTF 网络隔离硬约束）一致；ECharts 大屏留作后续迭代 |
| J21（M5.5） | Web 控制台/CLI status 等读进程与运行中写提交并发时，SQLite 瞬态 `database is locked` | 黑板连接统一开 **WAL + busy_timeout=5000**（读不堵写、写等 5s） | SQLite 默认回滚日志模式下读写互斥；WAL 是单文件库并发读写的标准解法，不改存储引擎与一致性语义（写仍串行、版本号乐观锁不变） |
| J23（M5.7） | 用户反馈：「不要在后端加这么多约束，不然我的 agent 根本跑不起来。合约范围那些只需要在 web 前端由用户告诉主 agent 就可以了，让主 agent 自己决策下发任务给子 agent；把功能点在 web 端都做上（如模型配置）」——Web 建会话被 CTF 必填赛题等模式门 422 卡住 | **任务式启动（mission-first）**：① `LaunchRequest.mission` 自然语言任务意图——目标/范围由 launch 层**确定性正则提取**（`https?://` URL 优先、裸域名兜底，中文标点剥离），不靠 LLM 猜；给出 URL 时 SRC 门放松（`--target` 可省），只给域名不给 URL 仍 422 并说明「请写明 http(s):// 地址」；提取出的 URL/域名**并入授权范围**——用户口述的合约边界由网络层 ScopeGuard 原样执行；② mission 原样注入主 Agent system prompt 与规划/复盘请求（「用户任务意图…你据此自行决策并下发任务给子 Agent」），主 Agent 自主规划、未知战术仍过滤（调度裁决不外包）；③ CLI `--mission` 与 Web 同源（J17）；④ Web 功能补全——新建对话框任务描述优先（目标可留空）、报告/审计 JSONL 下载端点+按钮（等价 CLI 报告落盘与 export-audit）、系统设置面板（白名单四键：轮次/双预算/请求超时，原子写回+新会话生效） | **不放松的底线（4.9.5 护栏）**：G1 授权勾选照旧 422；空范围仍由 runtime ScopeViolation 拒绝；预算硬顶/健康剪枝/核验收录裁决照旧——放松的只是「模式必填字段」这类装配层刚性，不是合规与裁决。CTF/渗透赛的结构化清单门不放松（报错提示改用 SRC+任务描述），因为赛题清单是结构化裁决输入（方向分类/禁端口扫描/flag 判定），自然语言描述无法等价替代。设置面板不开放在线改并发上限（信号量扩容涉在途会话竞态）与合规/路径键——不静默降级为「改了不生效」 |

### 4.3 模型接入约定（与硬约束 C9 一致）

- 所有模型经 `configs/models.yaml` 注册：`alias → {provider, model, base_url, api_key(env 引用), tier, cost, rate_limit, capabilities}`；
- 任务侧只引用 `alias` 或档位（flagship/fast/code/rigorous/light），路由由网关完成；
- **`mock` 后端**：`provider: mock` 的模型别名用于全部单测与冒烟（确定性规则应答），CI 与开发验证不消耗任何真实 API；
- 密钥只从环境变量读取，禁止入库/入日志（审计日志对 api_key 自动脱敏）。
