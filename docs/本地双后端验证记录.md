# 本地双后端验证记录

日期：2026-11-07。以下是本批代码的定向验证，包含失败结果；不是完整回归、
Windows 实机认证或不同 Agent 的性能排名。原始会话、审计、截图和个人配置不随副本发布。

## 环境与参数

- Linux，RTX 4060 Laptop 8GB，系统内存 16GB。
- Ollama 0.32.6，已有 Qwen3.5 9B Q4_K_M 本地模型。
- llama.cpp b12186，Qwen3.5 9B Q4_K_M、匹配的 F16 视觉投影器。
  文本全层 GPU，视觉编码器 CPU；32768 上下文、单槽、Q8 KV、Flash Attention，
  batch 512 / ubatch 128、8 个 CPU 线程，关闭思考，top_k 20 / top_p 0.9 / min_p 0 / repeat_penalty 1.05。
- 使用兼容的独立 GGUF 与投影器；原 Ollama 缓存文件直接加载出现架构元数据不兼容，未修改权重强行绕过。
- llama.cpp 权重来源：[unsloth/Qwen3.5-9B-GGUF 固定修订](https://huggingface.co/unsloth/Qwen3.5-9B-GGUF/tree/3885219b6810b007914f3a7950a8d1b469d598a5)。
  文件分别为 `Qwen3.5-9B-Q4_K_M.gguf` 与 `mmproj-F16.gguf`，下载后核对 SHA256。

| 项目 | 实际结果 | 范围 |
| --- | --- | --- |
| llama.cpp 工具协议 | 经真实 LiteLLM 网关收到原生流式工具调用；`tool_choice=required` 独立请求通过 | 本机已安装版本与上述模型 |

也没有重复采样和控制所有变量。

## 长会话未通过完整验收

使用 24 页离线日志夹具，要求每回合最多读一页，处理中补充主体归一化规则。

修改前的 llama.cpp 会话发生 68 次模型调用，只有一次实际工具调用且路径错误；
模型反复说明要解压，却没有执行。中途消息有约 9 秒的入模回执，仍未改变行为。

将纯 llama.cpp 候选的无工具恢复请求改为原生 `tool_choice=required` 后，
新会话完成 24 页实际读取，记录 42 次模型调用、33 次实际工具调用。
未出现连续完全相同的工具参数调用，但这不能证明没有语义重复。
服务报告的最大单次输入为 18744 tokens；最终原始历史约 7.9 万 tokens、
发送视图约 2.1 万 tokens 是离线估算，不能和服务报告值混为一谈。

本次仍失败于证据保持：模型之后否认已经读到的关键事件，并尝试解码用户明确要求
不要直接解包的数据。观察黑板持续更新，但模型证据笔记 revision 仍为 0；
没有正确生成最终报告或登记答案，测试在失败明确后主动停止。
因此只能确认本次恢复约束改善了“只说不做”，不能宣称长会话循环、记忆与结束问题全部修复。
正常结束、继续会话不重读、模型主动写入并回用关键证据，仍需后续修复和真实验证。
