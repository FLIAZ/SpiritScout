# 部署与配置

[返回 README](../README.md)

## 管理员登录

本地回环访问且尚未配置管理员时，可以免登录。监听非回环地址必须配置管理员凭据。
复制 `.env.example` 为 `.env`，修改 `SPIRITSCOUT_ADMIN_USERNAME` 和
`SPIRITSCOUT_ADMIN_PASSWORD`。旧版 `SPIRITSCOUT_SERVER_PASSWORD` 仍可使用。

启动时凭据导入工作区的 `admin.db`，密码保存为 scrypt 加盐哈希。
忘记用户名或密码时，修改 `.env` 中的凭据并重启服务即可恢复；恢复后移除环境变量，
数据库中的凭据仍然有效。远程访问请在反向代理上配置 HTTPS。

## 模型调用与依赖兼容

模型网关固定使用 LiteLLM `1.102.0`，MCP SDK 约束为 `>=1.28.1,<2`。
LiteLLM 较新的 MCP 支持面向 2.x，不要单独升级这一项。

连通性测试会让模型只回复 `ok`，显示请求完成耗时；它不覆盖任务里的流式输出和工具请求。
若测试成功、任务却立即失败，请查看完整错误，而不只看界面截断的 `APIConnectionError`。

例如 `cannot import name 'CacheableResult' from 'mcp.types'` 是本地依赖不兼容，
会在请求路径初始化时失败；修改密钥或反复测试网络不会解决它。按照项目约束重新安装，
或执行 `python deploy.py up` 重建镜像。仅重启旧镜像不会更新依赖。

依赖升级前需验证真实 SDK 的普通请求、流式输出、工具参数和 MCP 连接。
仓库的本机 HTTP/SSE 回归不访问付费供应商；真实模型测试需另行授权。

## Docker 构建

Windows、Linux、macOS 统一使用 Linux 容器，要求 Compose 2.20+。镜像使用 Debian
Bookworm 的 Python/Chromium，未强制 CPU 架构。本次验证 Windows 与 amd64 Linux；
macOS/ARM64 保留兼容代码路径，未完成实测。
Windows/macOS 安装 Docker Desktop 并启动；Linux 安装 Docker Engine 与 Compose 插件。
需要内核允许容器内的 bubblewrap/Chromium 命名空间，不能以宿主直跑替代沙箱。

推荐在仓库根目录执行 `python deploy.py up`（Windows 也可用 `py -3`，Unix 可用 `python3`）。
首次自动创建 `.env`，生成随机密码，不打印密码、不覆盖已有凭据。`doctor` 检查 Docker
与 Compose，`status` 查看状态，`logs` 跟踪日志，`down` 停服并保留卷。
没有 Python 时手动复制 `.env.example`、设置凭据，再运行 `docker compose up -d --build --wait`。

默认端口只绑定本机回环；应用带 HTTP 健康检查与优雅退出等待。镜像内保留源码，
不自动挂载整个宿主项目；修改代码、依赖后均需重新构建。数据保存在 Compose 项目隔离的卷：

| 卷 | 用途 |
| --- | --- |
| `spiritscout-data` | `.spiritscout/` 会话、审计、密钥、管理员和资源数据库 |
| `spiritscout-config` | 主配置、模型与编队配置；首次从镜像初始化，重建不覆盖用户配置 |
| `browser-profile` | 可选 SRC 浏览器的持久配置档案和登录态 |

Linux 数据卷避免 Windows/macOS 共享目录对 SQLite、文件锁和大量小文件的影响。
空配置卷会创建空的 `models.yaml`，随后从控制台添加模型。镜像构建排除本机 `.env`、
模型清单、编队配置、运行数据和工具缓存。构建期 apt/pip 下载使用缓存，并重试 apt 网络请求。

可以在 `.env` 中设置以下构建参数：

```dotenv
# 按需更换依赖源
PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
# 安装 pwntools、z3、scapy、binwalk、sqlmap 等工具
INSTALL_TOOLKIT=1
```

修改后执行 `python deploy.py up`。端口冲突时可在 `.env` 中设置 `SPIRITSCOUT_PORT`
和 `SPIRITSCOUT_BROWSER_PORT`；多套部署同时使用不同端口及 `--project-name`。
Compose 默认使用 Docker 的 DNS，不强制指定公共 DNS；Linux Engine 也配置了
`host.docker.internal:host-gateway`，便于外接宿主 CDP 服务。

### 升级与数据迁移

旧版把项目目录挂进 `/app`，工作区仍在宿主 `.spiritscout/`。新版不会删除或自动接管
原数据；升级前需要迁移，否则新卷会呈现一个空工作区。先完成或停止运行中的任务，
关闭所有原生实例及旧容器，保留原目录作为备份：

```bash
docker compose --profile src-browser down
docker compose build spiritscout
python deploy.py migrate
python deploy.py up --no-build
```

`migrate` 以二进制流复制宿主 `.spiritscout/` 和 `configs/` 到对应卷，适用于 PowerShell，
不经过会损坏二进制归档的文本管道。目标数据卷必须为空，拒绝覆盖已有数据和归档链接；
原文件不改动。使用自定义 project name 时，迁移和启动都传相同的 `--project-name`。
迁移前必须停止其他项目名或原生进程中仍在使用原目录的实例，不能复制正在写入的数据库。

后续升级保留已有配置卷；上游主配置新增字段时，根据 `configs/system.example.yaml`
合并到卷内配置，不直接用模板覆盖模型配置。可用 `docker compose cp` 导入/导出配置。
备份请停服后导出三个卷，密钥与数据库必须一起保留。`down` 不删除卷，`down -v` 会删除卷。

### 显式源码开发模式

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

开发覆盖将宿主源码、`configs/` 与 `.spiritscout/` 挂回容器；配置与数据不再来自生产卷。
Fedora 使用 `:z` 标记项目绑定目录；默认生产部署只使用命名卷，不需要重标记源码目录。
不要让原生与开发容器同时写同一个工作区。Windows/macOS 的共享目录性能较低，日常运行
优先使用默认数据卷。跨平台环境需各自创建 venv，不要把 Windows `.venv` 作为 Linux 工具层。

## 原生平台范围

| 环境 | 控制台、模型/资源管理、MCP | shell/Python 工具沙箱 |
| --- | --- | --- |
| Linux 原生 | 支持；安装 Python 3.11+，浏览器功能另需 Node.js 22+/Chrome | 需要 bubblewrap 和命名空间权限 |
| Windows 原生 | PowerShell `launch.ps1`；使用 `.venv/Scripts`、Windows 文件锁和 npm JS 入口 | 使用 Docker 或 WSL 中的独立部署 |
| macOS 原生 | `launch.sh`；使用 `.venv/bin`，停止/重启使用系统 lsof | 使用 Docker 中的独立部署 |
| 三平台 Docker | 完整功能；可选 `src-browser` 人工操作页 | 在 Linux 容器内执行，不退回宿主 |

Windows/macOS 原生控制台遇到沙箱调用会返回明确的 Docker 部署提示。Windows 的
数据库执行锁位于 SQLite 自身锁区之外，不扩展文件，也保留硬链接别名互斥。
进程启动和超时清理使用各平台入口，npm/npx 在 Windows 通过 Node.js 的 JS CLI 执行，
不把任务参数拼入 `cmd.exe`。Chrome 自动查找 PATH 与 Windows/macOS 标准应用位置，
仍可用 `SPIRITSCOUT_CHROME_EXECUTABLE` 指定其他路径。

CI 覆盖 Linux 全量回归、Windows 原生兼容用例，以及 amd64 Linux 镜像构建。
这些检查不等于已在所有主机、Docker 安全策略或第三方浏览器上完成实际任务测试。

## 浏览器

网页优先通过 HTTP 获取。会话内响应正文保存在 `http-responses/`：`body.bin` 保留 HTTP
内容解压后的原始字节，`body.txt` 为按响应编码解码后的 UTF-8 阅读副本，元数据保存响应头、
最终地址、哈希、时间及原执行编号。CTF 短页面直接呈现源码，长页面仅给首尾预览和 `body_ref`；
用 `http_response_read` 按字符偏移或起始行读取，或搜索原文字面量。读取不触网，单行压缩 JS
也可续读；沙箱可只读访问源码文件，直接解析长数组，避免手抄。已有内部检测器保留原正文窗口。

`executor.http_max_body_bytes` 默认 `8388608`（8 MiB），限制解压后正文大小，与展示窗口独立；
触限时 `download_complete=false`，不能声称完整源码已保存。`preview_truncated` 只说明展示
有省略，HTTP 206 另标 `response_is_partial=true`，不等于取得整个资源。快照随会话保存，
缓存复用沿用同一份快照；独立复测的多次本地读取仍只算原来的一次 HTTP 执行。

`chrome` MCP 按用户选择的任务模式装配：智能体/CTF 模式使用会话独立的无头浏览器，
无需启动 CDP 调试端口，也不读取用户已有登录态；SRC 模式复用 CDP 浏览器，首次实际调用浏览器工具时，本机未运行则自动启动带独立配置档案的 Chrome。
会话初始化只连接 MCP 并获取工具目录，不再通过列出标签触发浏览器启动；目录就绪不代表浏览器连接已经验证。
网页正文、源码和接口响应优先使用轻量 HTTP 工具；需要 JavaScript 渲染、页面交互或用户登录态时再按需使用浏览器，用户明确要求浏览器时遵循其要求。
实际调用中的连接失败会返回明确诊断。冗长错误和超长 MCP 返回会保存到会话的 `mcp-results/`，模型接收诊断或首尾摘要及原文路径，必要时再读原文，避免整段启动日志反复占用上下文。

源码环境使用浏览器功能时需安装 Chromium 或 Google Chrome；可通过
`SPIRITSCOUT_CHROME_EXECUTABLE` 指定浏览器可执行文件。Docker 镜像包含 Chromium。
以下 CDP 配置与人工接管说明仅适用于 SRC 模式。

### SRC 可选：随 Docker 部署可操作浏览器

项目包含 Chromium、虚拟桌面与 noVNC，按需启用 `src-browser` profile：

```bash
docker compose --profile src-browser up -d --build --wait
```

准备好 `.env` 中的控制台密码后执行上述命令，等待浏览器健康检查通过再下发 SRC
任务。控制台地址为 `http://127.0.0.1:10010`，浏览器操作页为
`http://127.0.0.1:10011`，两者使用 `.env` 中配置的管理员用户名和密码。
收到登录、验证码或滑块提问时，在操作页完成后回会话回复「已完成」。

默认 `docker compose up -d --build` 只启动主服务，智能体/CTF 的无头浏览器在主服务内
独立运行。共享浏览器不作为主服务的启动依赖；其故障不阻止主服务启动。
启用 profile 后，SRC 默认通过 Compose 内网的 `http://browser:9223` 连接浏览器。
CDP/VNC 不发布到宿主机，两个网页端口只绑定本机回环；远程使用时可通过 SSH 转发
`10010`、`10011`，或配置支持 WebSocket 的 HTTPS 反向代理。

SRC 浏览器的持久登录态保存到 Docker 卷 `browser-profile`，重启和重建容器后保留；
`docker compose --profile src-browser down -v` 会删除该卷。不同 SRC 会话共享这个
浏览器，避免同时操作同一页面；智能体/CTF 的隔离浏览器不读取这个卷。
内置浏览器为标准 Chromium，不含商业指纹管理能力。首次构建需要联网下载依赖。

Fedora 等启用 SELinux 的主机在开发模式使用项目挂载的 `:z` 选项设置容器共享标签；浏览器日志
直接输出到标准错误，不通过 `/dev/stderr` 的 proc 路径创建日志文件。无需关闭 SELinux
或导入宽泛的放行策略。该挂载会重标记当前项目目录，源码与运行数据仍保存在宿主机。

### SRC 可选：已有 Chrome / 指纹浏览器

`chrome` MCP 通过 Playwright 连接已有浏览器的 CDP 调试端口，
复用该浏览器的配置档案和登录态。源码部署的本机回环 CDP 未运行时，适配器会自动启动
Chrome/Chromium，无需用户预先打开浏览器。启动使用独立的持久配置目录
（默认工作区根目录下的 `browser-profile/`，可用 `SPIRITSCOUT_CHROME_PROFILE_DIR` 指定），
不读取或改写日常 Chrome 的配置档案。关闭会话或断开 MCP 不会关闭这个浏览器进程。

Agent 可搜索并调用 `mcp__chrome__browser_login(url, question)`：显示页面并通过会话提问
等待用户操作；用户在浏览器完成登录、验证码或滑块后，回到会话确认。工具随后自动最小化
窗口，让浏览器留在后台并保留登录态。用户取消或会话停止也会收起已显示的窗口。
其他路线在人工接管期间等待，不同时控制浏览器。答复不会被直接认定为登录成功，
Agent 仍须重新读取页面核对；各站点的登录过期规则仍然生效。

- `configs/system.yaml` 已启用 `chrome`，原来的无头 `playwright` 改为可选关闭。
  默认授权给业务体验 Agent 与 CTF Web Agent，其他支持动态 MCP 的角色可在
  `allowed_agents` 中显式加入；SRC 危险操作仍需逐次审批。
- 本机有桌面且已安装 Chrome/Chromium 时可自动启动；服务未继承 Linux 显示变量时，
  会尝试恢复当前用户的桌面连接。远程 CDP、WSL 宿主和无桌面容器不由源码进程代启，
  仍须启动外部浏览器或 Docker `src-browser` 服务。使用转发器时也须先启动转发器。
- 使用外部浏览器时，在 `.env` 中设置
  `SPIRITSCOUT_CHROME_CDP_URL=http://实际可达IP:9223`，无需启用 `src-browser` profile。
  Docker 会自动解析 `host.docker.internal` 为 IP；源码部署在 WSL 中使用自己的默认
  网关，其余环境使用本机回环。不能把 WSL 网关直接当成 Docker 网关。
- Docker 镜像内置 Node.js 22、Chromium 和固定版本的 MCP，无需在运行时下载浏览器。源码部署
  需安装 Node.js 22+；默认通过 npx 安装固定版本，已有 MCP CLI 时可设置
  `SPIRITSCOUT_CHROME_MCP_CLI` 为其 `cli.js` 路径。
- `--caps storage` 提供 `mcp__chrome__browser_cookie_list` 等 Cookie 工具，能读取
  HttpOnly Cookie；不要用 `document.cookie` 代替完整登录态读取。手动完成验证后，
  在会话提问处回复 Agent，由它重新检查页面与 Cookie。

该接入使用的是共享的浏览器配置档案，登录态会随原浏览器保存；它不提供会话之间的
自动隔离。同一浏览器应由一个任务操作，避免与其他 Agent 同时控制同一页面。
指纹配置由原浏览器提供，灵枢不改写浏览器指纹、代理或已有配置。

### 外部浏览器的启动与人工接管

1. 本机源码部署可由适配器自动启动 Chrome；远程部署先启动外部浏览器及所需的 CDP 转发器。
2. 在项目根目录执行 `docker compose up -d --build spiritscout`，打开
   `http://127.0.0.1:10010`。源码部署按 README 启动，另需准备 Node.js 22+。
3. 在 SRC 模式下向业务体验 Agent 下达浏览器任务，例如：
   「打开已授权站点，遇到登录或验证码时调用 browser_login 等我操作，完成后重新读取登录态再继续。」
4. 收到 Agent 提问后，在外部浏览器中完成登录、验证码或滑块，再在会话中
   回复「已完成」。使用 browser_login 时窗口会自动最小化，浏览器进程和登录态保留。
   Agent 会重新检查页面和 Cookie，确认成功后继续；浏览器中的变化
   在下一次工具读取时可见，不会自动推送 Cookie。

截图等浏览器产物写入当前会话的 `workspace/browser-output/`。Cookie 属于登录凭据，
只在当前任务需要时读取，避免复制到项目记忆、报告或聊天分享中。

### 连接排查与升级说明

- 若 SRC Chrome MCP 不可达，先在实际运行灵枢的环境中访问
  `http://实际可达IP:9223/json/version`，确认返回浏览器版本与
  `webSocketDebuggerUrl`；Windows 本机连通不代表 WSL 或 Docker 内也能连通。
  修正转发器或 `SPIRITSCOUT_CHROME_CDP_URL` 后重新启动服务。
- 源码首次使用需通过 npx 下载固定的 `@playwright/mcp@0.0.83`；离线环境可预装
  并用 `SPIRITSCOUT_CHROME_MCP_CLI` 指向运行环境内可访问的 `cli.js`。
- 升级已有部署时需重建 Docker 镜像以加入 Node.js、Chromium 与 MCP；SRC 内置
  可操作浏览器用 `docker compose --profile src-browser up -d --build --wait` 构建启动。
  使用自定义配置的用户请参考 `configs/system.example.yaml` 添加并启用 `chrome`；原无头 `playwright`
  可按需保留，但它不共享这个 Windows 浏览器的登录态。

## 配置文件

| 文件 | 用途 |
| --- | --- |
| `configs/system.yaml` | 主配置：工作区、执行器、MCP 服务器、网关、总线、黑板 |
| `configs/models.yaml` | 供应商与模型注册表（也可在控制台「模型」页维护） |
| `configs/agent_models.yaml` | 角色到模型的指派（「编队」页维护） |
| `configs/system.example.yaml` | 带注释的配置示例 |
| `Dockerfile` | Docker 部署：镜像构建（Python 3.11 + bubblewrap 沙箱） |
| `docker-compose.yml` | Docker 部署：端口发布、管理员凭据注入、独立配置与数据卷 |
| `docker-compose.dev.yml` | 显式开发覆盖：宿主源码、配置和工作区挂载 |
| `deploy.py` | 三平台部署检查、首次凭据生成与旧数据迁移 |
| `.env` / `.env.example` | 管理员用户名/密码与构建参数（启动时导入 `admin.db`；`.env` 不入库） |

模型以“供应商＋模型 ID”共同确定配置身份。不同供应商可以启用相同模型 ID，
同一供应商内仍不允许重复。模型页面的编辑、删除、测试、命名候选链和编队绑定
均携带完整配置标识；界面显示原始模型名和供应商，发送给端点的模型 ID 不变。
旧裸模型名在唯一匹配时兼容；通过页面新增同名模型前，系统会固定已有指派和
备用关系，供应商或模型改名时同步迁移引用。手写配置出现歧义时需重新选择供应商，
不能依赖列表顺序猜测。

### 会话存储清理

侧栏底部的「清理存储」可按占用大小查看全部会话；会话详情也提供同名入口。
扫描只读，选择会话、查看范围并点击「确认清理所选内容」后才会执行。

- **精简并收缩数据库**：删除已成功投递的旧通知，DAG 快照保留最近 64 个版本；
  清理无依赖的旧检查点，保留每个恢复键的最新检查点及完整增量依赖链。
  检查点格式或密钥校验异常时保留检查点并提示。清理过的历史版本无法回溯。
- **清理依赖下载缓存**：只清理会话沙箱各角色目录下的 `.cache/pip`、`.cache/uv`、
  `.npm/_cacache`，不跟随符号链接。后续可能重新下载依赖。

两项均保留会话、对话、报告、Flag、附件、脚本、已安装依赖、浏览器登录态、工具调用
记录和其他事实历史。运行中、仍有报告或经验提炼待完成的会话不可清理；清理期间不能
续传或删除该会话。同一时间执行一个清理任务，关闭弹窗不取消后台清理。

数据库删除记录后还需收缩文件才会归还磁盘空间。精简前检查事务日志需要的临时空间，
不足时不修改数据库；收缩前再检查空间，不足时保留可复用的数据库空闲页并提示。
释放量以完成后的实际磁盘占用为准。此功能不会自动
清理已有会话；运行时会跳过未变化的 DAG 写入、限制 DAG 历史数量、移除成功投递的
通知，并在建立新完整检查点基线后淘汰旧链，减少冗余增长。


### 共享资源目录

共享资源默认保存于 `<workspace>/resources/`，可用 `resources.root` 指定持久目录。
`resources.freshness_hours` 控制“近期观测”提示（默认 24 小时），不会把历史标记为本次已验证。
`resources.npm_registry` 默认为 npm 官方仓库，可指向组织内仓库。MCP 配置变更对
新启动的会话生效，运行中的连接不会被替换；Skill 首次打开读取当前版本，同一任务／路线的已打开技能保留版本快照。

### Agent 使用 Skill

主控 JSON 决策与 SRC 子 Agent 使用 `skill_requests` 作为只读工具往返，业务走访、独立复测、
CTF 各方向使用原生工具声明；只读秘书也可通过 JSON 通道查阅参考，无现场工具或审批权限。
用户明确指定技能时优先读取，否则由模型结合任务语义与描述自主判断；普通任务可以不调用技能。
后端不按关键词强制选择，也不添加固定解题流程、回合顶或生产费用熔断。

| 工具 | 内容 |
| --- | --- |
| `skill_search(query, domain, offset, limit)` | 检索已启用技能的适用说明；支持分页，空查询可浏览；尚未读取正文 |
| `skill_open(skill_id, reread)` | 完整读取根目录 SKILL.md，并返回该技能版本的文本文件目录 |
| `skill_read(skill_id, path, start_line, end_line, reread)` | 读取包内指定文本；可显式指定行范围处理大文件 |

初始发现信息只包含自定义技能的 ID／description／类型／版本，以及内置技能按类型分组的全部 ID；
不会默认装入整份技能正文。206 个内置 description 的占位已从各自原文适用场景补齐；旧覆盖记录
没有有效说明时，展示沿用新版内置说明，不覆盖用户的真实描述。技能检索结果只给候选与适用条件，
模型选中后再读取完整指令与所需引用；`kb_search` 仍可发现候选，但不再注入前几条正文片段。

版本快照与已读内容由各任务／路线／决策记忆持有，不用进程级“已读”标记跨 Agent 省略正文。
当前上下文保留了同一版本、同一文件及行范围的原文时，重复读取只回引用；需要重显可设置
`reread:true`。JSON 通道用已有 DecisionMemory 增量发送新读内容，重建决策段时保留已读原文，
并将版本快照持久化到原检查点；CTF 已读原文保护标记及快照随路线对话恢复。新任务首次打开
读取最新版本；技能被停用或删除后拒绝新读取，已经进入模型上下文的内容不会自动消失。
业务走访与复测的原生技能状态与各自当前工具对话共存，按它们已有的生命周期管理。

会话里的“使用技能”来自成功读取的实际工具回执，子任务摘要附近显示技能 ID、版本和已读文件数；
仅检索命中或模型声称使用不会生成成功标记。审计记录 `skill.loaded`／`skill.file_read`，带当前
Agent、任务／路线（或复测候选）以及文件、版本和内容指纹，便于区分各分支的实际来源。
资料仅为参考，不能作为独立漏洞复现证据；技能文本不会改写用户授权或绕过既有审批。

目前适配管理页保存的文本技能：包含 SKILL.md、references、脚本文本和配置文本；不自动安装依赖、
不自动执行脚本，图片／二进制资源仍沿用导入时明确提示未导入的边界。脚本执行继续使用已授权的
原工具通道。渐进加载和无重复正文的结构测试、离线脚本联调不代表真实模型一定更准确或费用一定
下降；真实效果需结合任务成功率、误选／漏选、引用读取完整性及实际端点用量继续验证。

### MCP 卡片目录

MCP 首页与 Skill 使用同一套卡片、启用／未启用分组和绿色滑杆，默认显示已启用连接。
可组合筛选名称／命令／地址／Agent 关键词、传输类型（STDIO／HTTP／SSE）、来源
（配置文件／管理页保存）、默认风险等级、额外授权 Agent、首次添加日期和时间记录状态；
支持最近／最早添加、最近修改、名称排序。筛选在分页之前执行，两组数量反映当前条件的全部匹配。
“沿用角色默认范围”表示未配置额外授权角色，不代表所有 Agent 均可使用。

管理页或助手新建 MCP 时记录首次添加时间，编辑和启停不改写；旧记录与配置文件连接显示
“时间未知”，不会用修改时间补造导入日期。日期使用北京时间自然日，截止日包含当日全部时间。
配置文件连接被管理页编辑后来源显示“管理页保存”，首次添加时间仍保持未知。

点击卡片打开接入配置编辑器，保存前读取最新配置版本，环境变量和请求头仍使用独立密钥输入框。
卡片地址摘要隐藏账号、查询参数和片段；卡片不展示环境变量或请求头的值。
删除前会确认并校验版本：管理页新增的 MCP 删除本地保存内容；配置文件连接保留本地移除标记，
刷新及重启后不会重新出现，不改写原配置文件，不卸载本地程序。
添加、修改、启停及删除均在新启动的会话生效，不热替换运行中的连接。

Exa 搜索配置与资源助手位于目录下方，按需展开；现有密钥保存、受控搜索和助手确认流程保持不变。

### Skill 目录与文件浏览

Skill 首页按卡片展示，默认进入“已启用”，可切换到“未启用”；两组数量反映当前筛选条件下的
全部匹配记录，分页只加载当前组。绿色滑杆表示启用，灰色表示未启用，并同时显示文字；点击后
技能转入另一组。资源助手在卡片下方折叠展示。

支持组合筛选名称／描述关键词、类型（`domain`）、来源（内置参考／压缩包导入／手动或助手添加）、
首次导入／添加日期范围和“时间未知／已记录时间”；支持最近或最早添加、最近修改、名称排序。
日期按北京时间自然日计算，截止日期包含当日全部时间，未知时间不进入日期范围。类型选项来自
实际目录，不自动推断技能类别；可在技能配置中修改 `domain`。清除筛选保留当前启用状态分组，
筛选在服务端执行后再分页，避免漏掉尚未加载的技能。

新添加或导入的自定义技能记录首次时间，后续编辑和启停只更新修改时间。旧数据缺少首次时间时
显示“时间未知”，不使用修改时间倒填。内置参考不标记导入时间，即使修改或停用也保留内置来源。

点击卡片进入该 Skill 的项目式文件浏览器，左侧展开根目录及子目录，右侧阅读 Markdown 或
查看其它文本；Markdown 可切换源文件并通过相对链接跳转已保存的包内文件。原始 HTML 转义，
脚本仅作为文本展示。新导入包保留 `files`（相对路径到 UTF-8 文本的映射），根文件为 `SKILL.md`；
编辑配置时以这些文件生成参考正文，保持页面与检索内容一致。历史技能只保存了合并正文时，
仅以 `SKILL.md` 展示该正文，不补造原目录。目录列表不传输文件正文，单项详情按需读取。

卡片“删除”会先确认并校验配置版本。自定义技能的保存内容被删除，可重新导入；内置技能使用
持久移除标记，重启后也不会重新出现。删除对象退出目录和后续参考检索，已有任务历史、报告及
已经进入上下文的内容不改写。Markdown 可在文件浏览器内编辑保存，未增加单文件上传／移动／删除操作。

### 直接编辑渲染后的 Markdown

点击技能卡片，在文件浏览器中打开 `.md` 文件，选择“编辑正文”，即可直接修改渲染后的标题、
段落、粗体／斜体、列表、表格单元格、代码块和引用。工具栏支持选中文字加粗／斜体和新增段落，
列表内回车创建下一项；点击“保存修改”才写入资源库。“切换源码”和“切换渲染编辑”共用当前草稿。
复杂扩展语法可用源码编辑；其它文本文件仍只读。

采用分块编辑：没有编辑过的块原样回写，不对整篇 Markdown 做 HTML 反转。渲染编辑保留隐藏的
YAML frontmatter、未修改的代码围栏、链接、列表结构及原始换行符；被修改的块按 Markdown
结构保存。源码模式可编辑文件完整原文。单文件保存保留技能 ID、description、类型、首次添加
时间和其它文件；这些目录配置仍通过“编辑配置”维护，不从正文重新推断。

保存会重新生成该技能的参考正文并递增版本，新任务的技能读取立即使用保存结果；已经固定版本
的运行中任务仍沿用原快照。内置技能的修改保存在当前资源库，不修改仓库内置种子；旧技能仅有
合并正文时，以 `SKILL.md` 保存为本地文件覆盖。

关闭／Esc、切换文件和打开配置编辑前会提示尚未保存的修改；刷新或离开页面使用浏览器的离开
确认。取消编辑放弃草稿，保存失败或版本冲突保留草稿，可切换源码复制。发生冲突时先保留需要的
文字，再取消并重新打开技能读取最新版本，不能强行覆盖他人修改。保存期间禁止继续输入、切换
文件或关闭窗口；粘贴只接受纯文本，不加载粘贴 HTML、图片或执行脚本。文件大小限制沿用导入
和技能正文限制，超过限制时明确报错，不截断保存。

### 导入 Skill 压缩包

在控制台「Skill 管理」点击「导入压缩包」，可一次选择多个文件，每个文件分别报告结果。
原生支持 ZIP、TAR、tar.gz / tgz、tar.bz2、tar.xz；RAR、7z 及其它 libarchive 可识别格式
需要运行服务的系统安装 libarchive（Debian/Ubuntu：`libarchive13`，Fedora：`libarchive`；
macOS/Windows 需提供可由系统动态库搜索路径发现的 libarchive）。Docker 镜像已加入该依赖，
已有镜像需重建；本次未实测 macOS/Windows 动态库加载。

包内可有包装目录或多个技能目录，每个技能通过 `SKILL.md` 识别。YAML frontmatter 中的
`name` 作为唯一标识（缺省使用技能目录名，限字母、数字、下划线和短横线），`description`
作为说明，可选 `domain` 作为类型（默认 `custom`）。保留目录与 SKILL.md 原文，并将该技能目录下的 UTF-8 文本参考资料（含 references 与
脚本文本）按相对路径合并为正文；嵌套技能的资料归最近的技能目录。不执行脚本、不安装依赖，
图片等非文本文件在结果中提示未导入。现有编辑、停用和参考检索同样适用于导入技能；
导入内容属于参考资料，不会扩大任务测试授权。

每包上传不超过 20 MiB，展开内容不超过 32 MiB，最多 1000 个条目，单文件不超过 2 MiB；
每个技能合并后的正文沿用 100000 字符限制。损坏、加密、不安全路径、链接及特殊文件会被拒绝。
同一压缩包原子保存：若任一技能无效、ID 重复或与已有技能（含内置）冲突，整包不写入；
可编辑已有技能，或修改包内 name 后重试。多个压缩包之间独立保存，成功结果不会因其它包失败撤销。

模型默认使用 `prompt_caching: provider_default`，不附加缓存参数。确认端点支持
Anthropic Messages 显式缓存后，可在模型编辑页选择 `anthropic_ephemeral`。
可按实际美元报价配置 `cost_cached_input_per_mtok` 与 `cost_cache_write_per_mtok`；
未配置缓存单价时费用仍按普通输入单价估算。缓存命中收益需以端点实际返回用量评估。

自定义 MCP 可用 `allowed_agents` 指定额外执行角色，例如 `[business_context, ctf_web]`（当前支持业务体验和 CTF 各执行角色）；空列表沿用原有工具范围。该配置不会授予灵枢、秘书或报告角色执行权限，也不会扩大任务授权范围，工具审批仍按会话模式执行。

## 搜索与费用

SRC 和普通 CTF 的 `web_search` 优先复用有效缓存，再使用 Exa 官方免密搜索；免费服务不可用时，通过 curl 获取公开搜索引擎结果。模型也可设置 `source: public` 直接使用公开引擎，并在关键词中组合精确短语、`site:` 和版本/错误特征。公开结果的时效与适用版本仍须核对。

付费 Exa API 仅用于特别困难且明显阻塞进度的问题。模型须基于实际证据自行判断，显式给出 `paid: true` 和 `blocker`，说明已尝试的方法、免费资料为何不足以及关键缺口如何影响下一步。免费额度耗尽、限流或普通查询失败不会自动触发付费请求；有效的旧付费结果可以免费复用。MCP 管理页保存的密钥只供这一受控路径使用。智能体模式禁止所有上述网页搜索路径。

搜索输出先在本地去除 HTML 脚本/样式/导航噪声、重复段落和追踪参数，再合并重复 URL，返回固定字段的紧凑 JSON（每条摘要最多 480 字符，整份最多 4,800 字符）。缓存命中逐字复用结果正文；旧版已付费缓存就地清理并保留原检索时间，格式升级不触发重新检索。缩短结果降低输入量，实际模型缓存命中率仍以端点返回用量为准。

## 数据与备份

用量逐笔写入会话目录的 `usage.db`（SQLite WAL 事务），首次打开时导入旧
`usage.json`，保留原文件；备份运行中的数据库请使用 SQLite 备份接口，
或停服后复制。旧版程序无法读取新增的数据库计量，回退前需另行导出。
读取结果按数据库/WAL 文件版本缓存，单文件仅保留最新快照。
资产库启动导入按历史记录游标增量执行；`POST /api/assets/sync` 可全量重扫历史会话。
会话列表与状态由单一调度器兜底刷新，隐藏页面降频，SSE 继续提供即时事件。
