# 部署与配置

[返回 README](../README.md)

## 选择安装方式

**Windows 推荐在 WSL2 内源码部署，Linux 推荐直接源码部署。** 项目日常开发采用源码运行，便于检查配置、安装外部工具和排查问题。已有 Docker 环境、希望统一容器依赖或运行多个独立实例时，可选择 Docker。

首次安装按 [README 快速开始](../README.md#快速开始) 操作；交给 Agent 部署时先读 [Agent 安装指南](../AGENTINSTALL.md)。推荐顺序不代表所有发行版或用户机器均已实测，安装后仍需验证实际使用的模型与工具。

源码部署准备好系统依赖后，在仓库根目录执行 `./install.sh`，再用 `./launch.sh` 启动。安装脚本创建或复用 `.venv`、安装并检查核心依赖、补齐缺失配置，保留已有配置和数据。

### WSL2 源码部署要点

- 在 Windows PowerShell 用 `wsl --list --verbose` 确认目标发行版的 `VERSION` 为 `2`；Python、Git、pip、bubblewrap 和启动命令在该发行版的 Linux 终端中运行，宿主 Windows 不必另装 Python 或 Docker。
- 项目、`.venv`、配置和 `.spiritscout/` 放在 WSL 的 `/home/...` 下，避免放在 `/mnt/c`、`/mnt/d`；不复用 Windows 虚拟环境。参见 [微软文件存储建议](https://learn.microsoft.com/en-us/windows/wsl/filesystems)。
- 使用 Python 3.11–3.14 和 bubblewrap；浏览器功能另需 Node.js 22+、Chromium/Chrome，CyberChef 需要 Node.js 24–26。控制台启动成功后，还须验证项目实际的 shell/Python 沙箱和所需 MCP。
- 常规控制台默认为 `http://127.0.0.1:8000`，可从 Windows 浏览器访问；本地轻量控制台默认 8001。模型或 CDP 浏览器运行在 Windows 时，默认 NAT 模式使用宿主地址，已启用 mirrored 模式时可使用 `127.0.0.1`；从 WSL 实际测试接口，不照搬 Docker 的宿主地址。参见 [微软 WSL 网络说明](https://learn.microsoft.com/en-us/windows/wsl/networking)。

## 管理员登录

本地回环访问且尚未配置管理员时，可以免登录。监听非回环地址必须配置管理员凭据。
复制 `.env.example` 为 `.env`，修改 `SPIRITSCOUT_ADMIN_USERNAME` 和
`SPIRITSCOUT_ADMIN_PASSWORD`。旧版 `SPIRITSCOUT_SERVER_PASSWORD` 仍可使用。

启动时凭据导入工作区的 `admin.db`，密码保存为 scrypt 加盐哈希。
忘记用户名或密码时，修改 `.env` 中的凭据并重启服务即可恢复；恢复后移除环境变量，
数据库中的凭据仍然有效。远程访问请在反向代理上配置 HTTPS。

## 侧栏与会话列表

左侧功能菜单与右侧会话列表独立排列。菜单顶部的箭头可收起标题、仅显示图标，
再次点击恢复；图标悬停可查看名称。菜单底部的会话按钮只收起或展开会话列表，
菜单仍然保留。两种折叠互不影响，并在当前浏览器记住选择；切换布局保留项目折叠和列表滚动位置。
窄屏使用图标菜单，会话按钮展开目录面板，选择会话、点击关闭或按 Esc 后返回内容区。
系统通知、界面动效、语言、主题、版本和存储操作统一放在菜单底部的「设置」中。

## 界面动效偏好

打开菜单底部的「设置」后，「界面动效」可选择跟随系统、柔和、快速或关闭。
设置立即生效并保存在当前浏览器，同源标签页同步，不影响任务执行速度。
快速模式缩短过渡并停用持续呼吸；关闭模式直接呈现变化。跟随系统使用浏览器的
`prefers-reduced-motion` 媒体查询：报告 `reduce` 时所有模式都停止动画，报告
`no-preference` 时自动档采用适中的节奏。页面不读取 KDE 等桌面配置，也不推算或
映射桌面的动画速度档位；柔和、快速由用户自行选择。页面切到后台也会暂停动画。

## 模型调用与依赖兼容

模型网关固定使用 LiteLLM `1.102.0`，MCP SDK 约束为 `>=1.28.1,<2`。
LiteLLM 较新的 MCP 支持面向 2.x，不要单独升级这一项。

连通性测试会让模型只回复 `ok`，显示请求完成耗时；它不覆盖任务里的流式输出和工具请求。
若测试成功、任务却立即失败，请查看完整错误，而不只看界面截断的 `APIConnectionError`。

例如 `cannot import name 'CacheableResult' from 'mcp.types'` 是本地依赖不兼容，
会在请求路径初始化时失败；修改密钥或反复测试网络不会解决它。按照项目约束重新安装，
或执行 `python deploy.py up` 重建镜像。仅重启旧镜像不会更新依赖。

依赖升级前需验证真实 SDK 的普通请求、流式输出、工具参数和 MCP 连接。
仓库的本机 HTTP/SSE 回归不访问付费供应商；真实模型测试需另行授权。

## Docker 构建

本节用于已选择 Docker 的部署；Linux/WSL2 源码安装不需要先构建镜像。

Windows、Linux、macOS 统一使用 Linux 容器，要求 Compose 2.20+。镜像使用 Debian
Bookworm 的 Python/Chromium，未强制 CPU 架构。本次验证 Windows 与 amd64 Linux；
macOS/ARM64 保留兼容代码路径，未完成实测。
Windows/macOS 安装 Docker Desktop 并启动；Linux 安装 Docker Engine 与 Compose 插件。
需要内核允许容器内的 bubblewrap/Chromium 命名空间，不能以宿主直跑替代沙箱。

选择 Docker 后，在仓库根目录执行 `python deploy.py up`（Windows 也可用 `py -3`，Unix 可用 `python3`）。
首次自动创建 `.env`，生成随机密码，不打印密码、不覆盖已有凭据。`doctor` 检查 Docker
与 Compose，`status` 查看状态，`logs` 跟踪日志，`down` 停服并保留卷。
没有 Python 时手动复制 `.env.example`、设置凭据，再运行 `docker compose up -d --build --wait`。

默认端口只绑定本机回环；应用带 HTTP 健康检查与优雅退出等待。镜像内保留源码，
不自动挂载整个宿主项目；修改代码、依赖后均需重新构建。数据保存在 Compose 项目隔离的卷：

| 卷 | 用途 |
| --- | --- |
| `spiritscout-data` | `.spiritscout/` 会话、审计、密钥、管理员和资源数据库 |
| `spiritscout-config` | 主配置、模型与编队配置；首次从镜像初始化，重建不覆盖用户配置 |
| `browser-profile` | 可选 SRC 浏览器的持久配置档案和登录态 |

Linux 数据卷避免 Windows/macOS 共享目录对 SQLite、文件锁和大量小文件的影响。
空配置卷会创建空的 `models.yaml`，随后从控制台添加模型。镜像构建排除本机 `.env`、
模型清单、编队配置、运行数据和工具缓存。构建期 apt/pip 下载使用缓存，并重试 apt 网络请求。

可以在 `.env` 中设置以下构建参数：

```dotenv
# 按需更换依赖源
PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
# 安装 pwntools、z3、scapy、binwalk、sqlmap 等工具
INSTALL_TOOLKIT=1
```

修改后执行 `python deploy.py up`。端口冲突时可在 `.env` 中设置 `SPIRITSCOUT_PORT`
和 `SPIRITSCOUT_BROWSER_PORT`；多套部署同时使用不同端口及 `--project-name`。
Compose 默认使用 Docker 的 DNS，不强制指定公共 DNS；Linux Engine 也配置了
`host.docker.internal:host-gateway`，便于外接宿主 CDP 服务。

### 升级与数据迁移

旧版把项目目录挂进 `/app`，工作区仍在宿主 `.spiritscout/`。新版不会删除或自动接管
原数据；升级前需要迁移，否则新卷会呈现一个空工作区。先完成或停止运行中的任务，
关闭所有原生实例及旧容器，保留原目录作为备份：

```bash
docker compose --profile src-browser down
docker compose build spiritscout
python deploy.py migrate
python deploy.py up --no-build
```

`migrate` 以二进制流复制宿主 `.spiritscout/` 和 `configs/` 到对应卷，适用于 PowerShell，
不经过会损坏二进制归档的文本管道。目标数据卷必须为空，拒绝覆盖已有数据和归档链接；
原文件不改动。使用自定义 project name 时，迁移和启动都传相同的 `--project-name`。
迁移前必须停止其他项目名或原生进程中仍在使用原目录的实例，不能复制正在写入的数据库。

后续升级保留已有配置卷；上游主配置新增字段时，根据 `configs/system.example.yaml`
合并到卷内配置，不直接用模板覆盖模型配置。可用 `docker compose cp` 导入/导出配置。
备份请停服后导出三个卷，密钥与数据库必须一起保留。`down` 不删除卷，`down -v` 会删除卷。

### 显式源码开发模式

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

开发覆盖将宿主源码、`configs/` 与 `.spiritscout/` 挂回容器；配置与数据不再来自生产卷。
Fedora 使用 `:z` 标记项目绑定目录；默认生产部署只使用命名卷，不需要重标记源码目录。
不要让原生与开发容器同时写同一个工作区。Windows/macOS 的共享目录性能较低，日常运行
优先使用默认数据卷。跨平台环境需各自创建 venv，不要把 Windows `.venv` 作为 Linux 工具层。

## uv 本地环境

[uv](https://docs.astral.sh/uv/) 与 pip 共用同一份 `pyproject.toml`；`uv.lock` 记录当前
依赖解析结果，供本地开发、CI 与 PyInstaller 构建复用。安装 uv 后在项目根执行：

```bash
uv sync                                  # 运行依赖
uv sync --extra dev                      # ruff / pytest
uv sync --extra dev --extra toolkit      # 开发检查 + pwntools、z3、scapy 等 CTF 工具库
uv sync --extra build                    # PyInstaller 打包
uv run python -m spiritscout --help
```

多个 extras 需在同一条命令中组合；单独执行后一次会按当前参数同步环境。
`uv sync` 在项目根创建 `.venv`，与 `launch.sh`、`launch.ps1` 使用同一路径；运行期
本身不依赖 uv。

- 修改依赖后执行 `uv lock` 并提交 `uv.lock`；验证锁文件与声明一致可用
  `uv lock --check`。
- 不使用 uv 时，原 venv + pip 流程继续有效；Docker 镜像仍按 Dockerfile 使用 pip 构建。
- 依赖 LiteLLM 1.102.0，Python 范围为 3.11–3.14；`uv sync` 会自动选择兼容解释器，
  也可显式使用 `uv sync --python 3.11`（或 `3.12`）。

## 原生平台范围

| 环境 | 控制台、模型/资源管理、MCP | shell/Python 工具沙箱 |
| --- | --- | --- |
| Linux 原生 | 支持；安装 Python 3.11–3.14，浏览器功能另需 Node.js 22+/Chrome | 需要 bubblewrap 和命名空间权限 |
| Windows WSL2 源码（推荐） | 在 WSL Linux 文件系统中安装，使用 `.venv/bin` 和 `launch.sh` | 需要 WSL2、bubblewrap 和可用的命名空间；安装后实测 |
| Windows 原生 | PowerShell `launch.ps1`；使用 `.venv/Scripts`、Windows 文件锁和 npm JS 入口 | 原生不支持；优先使用 WSL2 源码，也可选 Docker |
| Windows 打包版 | `scripts/build-exe.ps1` 生成 `SpiritScout.exe`，目标机不需要 Python | 使用 Docker 或 WSL 中的独立部署 |
| macOS 原生 | `launch.sh`；使用 `.venv/bin`，停止/重启使用系统 lsof | 使用 Docker 中的独立部署 |
| Linux 打包版 | `scripts/build-elf.sh` 生成 `spiritscout`，目标机不需要 Python | 需要目标机 bubblewrap；工具层放在程序旁 `.venv` |
| 三平台 Docker | 完整功能；可选 `src-browser` 人工操作页 | 在 Linux 容器内执行，不退回宿主 |

Windows/macOS 原生控制台遇到沙箱调用会返回明确的 Docker 部署提示。Windows 的
数据库执行锁位于 SQLite 自身锁区之外，不扩展文件，也保留硬链接别名互斥。
进程启动和超时清理使用各平台入口，npm/npx 在 Windows 通过 Node.js 的 JS CLI 执行，
不把任务参数拼入 `cmd.exe`。Chrome 自动查找 PATH 与 Windows/macOS 标准应用位置，
仍可用 `SPIRITSCOUT_CHROME_EXECUTABLE` 指定其他路径。

CI 覆盖 Linux 全量回归、Windows 原生兼容用例，以及 amd64 Linux 镜像构建。
这些检查不等于已在所有主机、Docker 安全策略或第三方浏览器上完成实际任务测试。

## 免安装可执行文件

`scripts/build-exe.ps1` 与 `scripts/build-elf.sh` 使用 PyInstaller 生成单文件控制台，
目标机器不需要 Python 环境：

| 平台 | 产物 | 构建命令 |
| --- | --- | --- |
| Windows | `dist/SpiritScout.exe` | `.\scripts\build-exe.ps1` |
| Linux | `dist/spiritscout` | `./scripts/build-elf.sh` |

构建环境使用 Python 3.11–3.14，可用 `-PythonVersion`（PowerShell）或 `BUILD_PYTHON`
（Bash）覆盖。推荐安装 uv：脚本会自动获取指定版本、创建隔离的 `.venv-build` 并安装
`.[build]`；没有 uv 时退回系统兼容 Python 与 pip。`.venv-build` 与正常运行的
`.venv` 分离，不会改动开发环境。打包配置在 `scripts/spiritscout.spec`，内置前端静态
资源、知识库种子数据、报告模板、配置模板和常用 tiktoken 词表。

**首次启动与数据位置**

单文件包运行时会解压到临时目录，配置和工作区不能写回临时目录。冻结版启动后把工作
目录切换到可执行文件所在目录，并按以下顺序初始化：

1. 缺失时从内置模板生成 `configs/system.yaml`，已有配置不会被覆盖。
2. 缺失时创建空的 `configs/models.yaml`，模型随后可在控制台添加。
3. 复制 `configs/*.example.yaml` 与 `.env.example` 便于参考，不创建 `.env`。
4. 工作区、审计、密钥库和会话保存在程序旁 `.spiritscout/`。

Windows 双击 `SpiritScout.exe` 后，控制台窗口会打印地址，默认
<http://127.0.0.1:8000>；也可传入 `--port 8001`、`--host` 或 `--config`。
冻结模式下相对路径按程序目录解析，迁移时应把可执行文件、`configs/` 和
`.spiritscout/` 一起移动。远程访问仍需在 `.env` 配置管理员凭据并使用 HTTPS。

**能力边界**

打包版覆盖 Web 控制台、模型与资源管理、知识库、报告、会话与审批。以下能力仍依赖
外部环境，不在单文件内：

- shell/Python 沙箱需要 Linux bubblewrap；Windows 使用 Docker 或 WSL 部署。
- `executor.backend=docker` 仍需要本机 Docker。
- 外部 MCP、IDA/Yakit、Node.js 与 Chromium/Chrome 不随包分发。可在程序旁放置
  `.venv` 或 `.tools`，或改用 Docker 部署；配置中的内置 Chrome MCP 子进程在冻结版
  由主程序转交，仍需 Node/Chrome 可用。
- Linux ELF 的 glibc 下限取决于构建机；需在目标发行版兼容的环境中构建或运行。

**验证**

2026-11-05 实测：Windows `dist/SpiritScout.exe` 与 WSL Ubuntu `dist/spiritscout`
均可由 `--version` 输出 `0.20.0`；复制到空目录启动后自动生成 `configs/`、
`.spiritscout/` 与 `.env.example`，Windows 与 Linux 的 `/login` 均返回 HTTP 200，
Windows 终端无 tiktoken 预热警告，Linux 标准错误为空。以上验证只覆盖单文件首次启动
与本机环境，未覆盖其他发行版、glibc 版本或真实模型任务。

## CyberChef 编码解码

SRC 执行角色与 CTF 各方向 Agent 内置 `cyberchef_operations`（查询官方操作与位置参数）和
`cyberchef_bake`（执行配方），由统一工具注册表执行并留审计。
使用 [GCHQ CyberChef](https://github.com/gchq/CyberChef) 官方 Node API，
锁定依赖见 `deploy/cyberchef/package-lock.json`，许可证为 Apache-2.0。
不需要额外 MCP 服务、网页或 API Key，也不在任务中自动下载依赖。
SRC 的知行、鉴真通过原生工具调用，斥候、破壁、听风、贯甲、深耕通过 JSON 决策中的
本地工具请求调用同一注册表；不授予通用 shell 权限。鉴真可用解码辅助分析，
但本地转换不能作为新的独立复测或对照。灵枢主 Agent、秘书和报告角色仍通过执行角色取得结果。

Docker 镜像构建时安装独立 Node.js 24 与 CyberChef 运行时，已有镜像需重建。
Linux 源码部署需要可用的 bubblewrap、Node.js 24–26 和 npm：

```bash
python scripts/setup_cyberchef.py
# 系统 Node 仍为 22 时，可指定已经安装的独立 Node 24–26：
python scripts/setup_cyberchef.py --node /path/to/node24
```

安装器默认将依赖与独立 Node 副本保存到 `.tools/cyberchef/`，使用锁文件安装，
禁用 npm 生命周期脚本，并显式执行官方所需的 `fixCryptoApiImports.mjs`。
额外固定 `terser`，补齐该版官方 Node API 的运行依赖；安装结束执行真实 Base64 验证。
自定义目录用 `--directory`，并在服务环境设置 `SPIRITSCOUT_CYBERCHEF_ROOT`；
需要覆盖 Node 路径时设置 `SPIRITSCOUT_CYBERCHEF_NODE`。不会修改系统 Node 或用户配置。

先查询准确操作名及 `args` 顺序，再执行，例如：

```json
{"query":"From Base64"}
```

```json
{"input":"X192ZXJpZmljYXRpaW9uVG9rZW4=","recipe":[{"op":"From Base64","args":["A-Za-z0-9+/=",false,true]}]}
```

`input` 为不去空白的 UTF-8 字符串；也可用 `input_file` 读取本会话附件、
`sandbox/`、`artifacts/` 或 `http-responses/` 原文，`offset`/`length` 按字节选择范围，
两种输入只能选一个。配方由模型决定，不自动识别、纠正变量名或提取 Flag。
注意 `http_response_read` 返回的是字符偏移，不能未经换算直接当作这里的字节偏移。
CyberChef 的宽松解码选项仍按官方语义工作；示例显式关闭忽略非法字符并开启严格模式。

每次执行只挂载系统运行库、工具依赖、本次输入和独立输出目录，隔离网络、进程与环境变量，
不挂载会话控制文件和宿主 HOME。没有 Linux/bubblewrap 时返回错误，不在宿主降级执行；
Windows/macOS 使用 Docker。超时或会话取消会终止执行进程。
单次输入/保存结果上限为 16 MiB，默认超时 60 秒，可指定 1–300 秒，Node JS 堆上限 512 MiB；
这是单次工具资源限制，不是会话预算或解题回合上限，也不是进程总内存或磁盘硬配额。

完整结果保存到 `artifacts/cyberchef-*/result.bin`，另存配方、引擎版本、输入输出 SHA-256
及来源调用编号。模型只接收有界预览，非 UTF-8 结果用 Hex 展示；后续脚本直接读取
`output_file`，避免把解码结果重新手抄成相似变量名。参数说明较长时完整保存为
`catalog.json`，可缩小查询、分页或通过沙箱读取。部分浏览器专用操作以及配方中的流控制
不受官方 Node API 支持，失败会明确回报；需要复杂计算时可继续使用 Python 沙箱。

## 浏览器

网页优先通过 HTTP 获取。会话内响应正文保存在 `http-responses/`：`body.bin` 保留 HTTP
内容解压后的原始字节，`body.txt` 为按响应编码解码后的 UTF-8 阅读副本，元数据保存响应头、
最终地址、哈希、时间及原执行编号。CTF 短页面直接呈现源码，长页面仅给首尾预览和 `body_ref`；
用 `http_response_read` 按字符偏移或起始行读取，或搜索原文字面量。读取不触网，单行压缩 JS
也可续读；沙箱可只读访问源码文件，直接解析长数组，避免手抄。已有内部检测器保留原正文窗口。

`executor.http_max_body_bytes` 默认 `8388608`（8 MiB），限制解压后正文大小，与展示窗口独立；
触限时 `download_complete=false`，不能声称完整源码已保存。`preview_truncated` 只说明展示
有省略，HTTP 206 另标 `response_is_partial=true`，不等于取得整个资源。快照随会话保存，
缓存复用沿用同一份快照；独立复测的多次本地读取仍只算原来的一次 HTTP 执行。

`chrome` MCP 按用户选择的任务模式装配：智能体/CTF 模式使用会话独立的无头浏览器，
无需启动 CDP 调试端口，也不读取用户已有登录态；SRC 模式复用 CDP 浏览器，首次实际调用浏览器工具时，本机未运行则自动启动带独立配置档案的 Chrome。
会话初始化只连接 MCP 并获取工具目录，不再通过列出标签触发浏览器启动；目录就绪不代表浏览器连接已经验证。

服务启动（包括 `./launch.sh start`）后，在后台对已启用 MCP 执行 initialize 和 tools/list 预检，不调用业务工具或模型，不阻塞控制台启动。成功默认静默，失败在服务终端输出脱敏诊断；`/api/mcp/health` 可查看本进程的预检状态。stdio 成功启动日志仅保留有界诊断尾部，系统不支持非阻塞管道时仍使用 SDK 默认 stderr。目录可用只证明握手及工具目录可用，不保证外部应用、登录状态和具体工具调用始终成功。

普通 MCP 的预热连接独占交给首个配置完全匹配的会话，复用握手结果；后续会话仍建立独立连接，避免跨会话混用可变状态。配置或凭据变化不复用旧连接，已断开的连接重新建立；短时间内预检失败直接反馈已有诊断，避免立即重复启动。`chrome` 只预检目录后关闭，任务仍按模式和输出目录单独连接，首次实际调用时准备浏览器。会话调用不追加模型健康检查，实际错误继续沿原工具错误通道反馈。
网页正文、源码和接口响应优先使用轻量 HTTP 工具；需要 JavaScript 渲染、页面交互或用户登录态时再按需使用浏览器，用户明确要求浏览器时遵循其要求。
实际调用中的连接失败会返回明确诊断。冗长错误和超长 MCP 返回会保存到会话的 `mcp-results/`，模型接收诊断或首尾摘要及原文路径，必要时再读原文，避免整段启动日志反复占用上下文。

源码环境使用浏览器功能时需安装 Chromium 或 Google Chrome；可通过
`SPIRITSCOUT_CHROME_EXECUTABLE` 指定浏览器可执行文件。Docker 镜像包含 Chromium。
以下 CDP 配置与人工接管说明仅适用于 SRC 模式。

### SRC 可选：随 Docker 部署可操作浏览器

项目包含 Chromium、虚拟桌面与 noVNC，按需启用 `src-browser` profile：

```bash
docker compose --profile src-browser up -d --build --wait
```

准备好 `.env` 中的控制台密码后执行上述命令，等待浏览器健康检查通过再下发 SRC
任务。控制台地址为 `http://127.0.0.1:10010`，浏览器操作页为
`http://127.0.0.1:10011`，两者使用 `.env` 中配置的管理员用户名和密码。
浏览器首页使用相对重定向，进入 `vnc.html` 时保留当前访问地址和发布端口。
收到登录、验证码或滑块提问时，在操作页完成后回会话回复「已完成」。

默认 `docker compose up -d --build` 只启动主服务，智能体/CTF 的无头浏览器在主服务内
独立运行。共享浏览器不作为主服务的启动依赖；其故障不阻止主服务启动。
启用 profile 后，SRC 默认通过 Compose 内网的 `http://browser:9223` 连接浏览器。
CDP/VNC 不发布到宿主机，两个网页端口只绑定本机回环；远程使用时可通过 SSH 转发
`10010`、`10011`，或配置支持 WebSocket 的 HTTPS 反向代理。

SRC 浏览器的持久登录态保存到 Docker 卷 `browser-profile`，重启和重建容器后保留；
`docker compose --profile src-browser down -v` 会删除该卷。不同 SRC 会话共享这个
浏览器，避免同时操作同一页面；智能体/CTF 的隔离浏览器不读取这个卷。
内置浏览器为标准 Chromium，不含商业指纹管理能力。首次构建需要联网下载依赖。

Fedora 等启用 SELinux 的主机在开发模式使用项目挂载的 `:z` 选项设置容器共享标签；浏览器日志
直接输出到标准错误，不通过 `/dev/stderr` 的 proc 路径创建日志文件。无需关闭 SELinux
或导入宽泛的放行策略。该挂载会重标记当前项目目录，源码与运行数据仍保存在宿主机。

### SRC 可选：已有 Chrome / 指纹浏览器

`chrome` MCP 通过 Playwright 连接已有浏览器的 CDP 调试端口，
复用该浏览器的配置档案和登录态。源码部署的本机回环 CDP 未运行时，适配器会自动启动
Chrome/Chromium，无需用户预先打开浏览器。启动使用独立的持久配置目录
（默认工作区根目录下的 `browser-profile/`，可用 `SPIRITSCOUT_CHROME_PROFILE_DIR` 指定），
不读取或改写日常 Chrome 的配置档案。关闭会话或断开 MCP 不会关闭这个浏览器进程。

Agent 可搜索并调用 `mcp__chrome__browser_login(url, question)`：显示页面并通过会话提问
等待用户操作；用户在浏览器完成登录、验证码或滑块后，回到会话确认。工具随后自动最小化
窗口，让浏览器留在后台并保留登录态。用户取消或会话停止也会收起已显示的窗口。
其他路线在人工接管期间等待，不同时控制浏览器。答复不会被直接认定为登录成功，
Agent 仍须重新读取页面核对；各站点的登录过期规则仍然生效。

- `configs/system.yaml` 已启用 `chrome`，原来的无头 `playwright` 改为可选关闭。
  默认授权给业务体验 Agent 与 CTF Web Agent，其他支持动态 MCP 的角色可在
  `allowed_agents` 中显式加入；SRC 危险操作仍需逐次审批。
- 本机有桌面且已安装 Chrome/Chromium 时可自动启动；服务未继承 Linux 显示变量时，
  会尝试恢复当前用户的桌面连接。远程 CDP、WSL 宿主和无桌面容器不由源码进程代启，
  仍须启动外部浏览器或 Docker `src-browser` 服务。使用转发器时也须先启动转发器。
- 使用外部浏览器时，在 `.env` 中设置
  `SPIRITSCOUT_CHROME_CDP_URL=http://实际可达IP:9223`，无需启用 `src-browser` profile。
  Docker 会自动解析 `host.docker.internal` 为 IP；源码部署在 WSL 中使用自己的默认
  网关，其余环境使用本机回环。不能把 WSL 网关直接当成 Docker 网关。
- Docker 镜像内置 Node.js 22、Chromium 和固定版本的 MCP，无需在运行时下载浏览器。源码部署
  需安装 Node.js 22+；默认通过 npx 安装固定版本，已有 MCP CLI 时可设置
  `SPIRITSCOUT_CHROME_MCP_CLI` 为其 `cli.js` 路径。
- `--caps storage` 提供 `mcp__chrome__browser_cookie_list` 等 Cookie 工具，能读取
  HttpOnly Cookie；不要用 `document.cookie` 代替完整登录态读取。手动完成验证后，
  在会话提问处回复 Agent，由它重新检查页面与 Cookie。

该接入使用的是共享的浏览器配置档案，登录态会随原浏览器保存；它不提供会话之间的
自动隔离。同一浏览器应由一个任务操作，避免与其他 Agent 同时控制同一页面。
指纹配置由原浏览器提供，灵枢不改写浏览器指纹、代理或已有配置。

### 外部浏览器的启动与人工接管

1. 本机源码部署可由适配器自动启动 Chrome；远程部署先启动外部浏览器及所需的 CDP 转发器。
2. 在项目根目录执行 `docker compose up -d --build spiritscout`，打开
   `http://127.0.0.1:10010`。源码部署按 README 启动，另需准备 Node.js 22+。
3. 在 SRC 模式下向业务体验 Agent 下达浏览器任务，例如：
   「打开已授权站点，遇到登录或验证码时调用 browser_login 等我操作，完成后重新读取登录态再继续。」
4. 收到 Agent 提问后，在外部浏览器中完成登录、验证码或滑块，再在会话中
   回复「已完成」。使用 browser_login 时窗口会自动最小化，浏览器进程和登录态保留。
   Agent 会重新检查页面和 Cookie，确认成功后继续；浏览器中的变化
   在下一次工具读取时可见，不会自动推送 Cookie。

截图等浏览器产物写入当前会话的 `workspace/browser-output/`。Cookie 属于登录凭据，
只在当前任务需要时读取，避免复制到项目记忆、报告或聊天分享中。

### 连接排查与升级说明

- 若 SRC Chrome MCP 不可达，先在实际运行灵枢的环境中访问
  `http://实际可达IP:9223/json/version`，确认返回浏览器版本与
  `webSocketDebuggerUrl`；Windows 本机连通不代表 WSL 或 Docker 内也能连通。
  修正转发器或 `SPIRITSCOUT_CHROME_CDP_URL` 后重新启动服务。
- 源码首次使用需通过 npx 下载固定的 `@playwright/mcp@0.0.83`；离线环境可预装
  并用 `SPIRITSCOUT_CHROME_MCP_CLI` 指向运行环境内可访问的 `cli.js`。
- 升级已有部署时需重建 Docker 镜像以加入 Node.js、Chromium 与 MCP；SRC 内置
  可操作浏览器用 `docker compose --profile src-browser up -d --build --wait` 构建启动。
  使用自定义配置的用户请参考 `configs/system.example.yaml` 添加并启用 `chrome`；原无头 `playwright`
  可按需保留，但它不共享这个 Windows 浏览器的登录态。

### 会话压缩与存储清理

会话存储默认使用无损压缩，不改变模型上下文、工具输出、证据、规划和执行次数。
检查点及工具参数/结果在加密前压缩；黑板历史和待投递通知的大记录也压缩保存，
读取时还原完整原文。黑板现值保留普通 JSON，兼容 SQL 查询。小记录和压缩收益不足
的记录保持原编码；旧数据库、旧审计与新压缩记录可以混读。

`audit.jsonl` 仍按行追加，事件头保留 `seq`、`ts`、`type`、`actor`；大 `detail`
以版本化的 `_detail_zlib` 字段存储。历史分页、SSE、续聊读取及审计导出均透明还原，
已经发布的日志行不重写，因此字节游标不变。需要自行解析审计的脚本应使用
`spiritscout.core.audit.read_record`，或读取导出的普通 JSONL。新记录不重复保存
已经有原文的工具参数加密副本，执行台账仍独立加密保存参数，旧副本仍可读取。

Web 服务启动后默认在后台串行维护**已结束且空闲至少 5 分钟**的会话，首次扫描
延后最多 30 秒，之后每 15 分钟扫描。维护复用下述数据库精简和收缩流程，并无损
重编码旧历史、检查点和工具记录；数据库未变化时跳过。不会自动删除会话、审计、
成果、附件或任何沙箱文件，也不会按存储大小限制 Agent 执行。运行中、暂停中或
报告/经验提炼尚未完成的会话跳过，无法取得运行锁时保留原数据并稍后重试。

可在系统配置中调整后台维护（关闭维护不影响新记录的无损压缩）：

```yaml
storage:
  auto_maintenance: true
  maintenance_interval_seconds: 900
  idle_seconds: 300
```

存储编码升级后，执行台账版本为 4；旧程序不能读取新压缩数据。更新时应一起升级
所有访问同一工作区的进程，不要将旧程序与新程序混用。迁移在 SQLite 事务内完成，
压缩前后校验原文字节一致；异常时回滚该次重编码，不为压缩额外生成整库备份。

菜单底部「设置」中的「清理存储」可按占用大小查看全部会话；会话详情也提供同名入口。
选中扫描出的会话后，可点击「查看会话」关闭清理窗口并打开对应会话内容，方便判断是否保留。
界面中的扫描只读，手动任务在点击「确认清理所选内容」后执行。

- **精简并收缩数据库**：删除已成功投递的旧通知，DAG 快照保留最近 64 个版本；
  清理无依赖的旧检查点，保留每个恢复键的最新检查点及完整增量依赖链。
  检查点格式或密钥校验异常时保留检查点并提示；保留的历史记录无损压缩。
  被淘汰的冗余 DAG/检查点版本无法回溯，其他事实历史不删除。
- **清理依赖下载缓存**：只清理会话沙箱各角色目录下的 `.cache/pip`、`.cache/uv`、
  `.npm/_cacache`，不跟随符号链接。后续可能重新下载依赖。

两项均保留会话、对话、报告、Flag、附件、脚本、已安装依赖、浏览器登录态、工具调用
记录和其他事实历史。运行中、仍有报告或经验提炼待完成的会话不可清理；清理期间不能
续传或删除该会话。同一时间执行一个清理任务，关闭弹窗不取消后台清理。

数据库删除记录后还需收缩文件才会归还磁盘空间。精简前检查事务日志需要的临时空间，
不足时不修改数据库；收缩前再检查空间，不足时保留可复用的数据库空闲页并提示。
释放量以完成后的实际磁盘占用为准。运行时会跳过未变化的 DAG 写入、限制 DAG 历史数量、移除成功投递的
通知，并在建立新完整检查点基线后淘汰旧链，减少冗余增长。


### 共享资源目录

共享资源默认保存于 `<workspace>/resources/`，可用 `resources.root` 指定持久目录。
`resources.freshness_hours` 控制“近期观测”提示（默认 24 小时），不会把历史标记为本次已验证。
`resources.npm_registry` 默认为 npm 官方仓库，可指向组织内仓库。MCP 配置变更对
新启动的会话生效，运行中的连接不会被替换；Skill 首次打开读取当前版本，同一任务／路线的已打开技能保留版本快照。

### Agent 使用 Skill

主控 JSON 决策与 SRC 子 Agent 使用 `skill_requests` 作为只读工具往返，业务走访、独立复测、
CTF 各方向使用原生工具声明；只读秘书也可通过 JSON 通道查阅参考，无现场工具或审批权限。
用户明确指定技能时优先读取，否则由模型结合任务语义与描述自主判断；普通任务可以不调用技能。
后端不按关键词强制选择，也不添加固定解题流程、回合顶或生产费用熔断。

| 工具 | 内容 |
| --- | --- |
| `skill_search(query, domain, offset, limit)` | 检索已启用技能的适用说明；支持分页，空查询可浏览；尚未读取正文 |
| `skill_open(skill_id, reread)` | 完整读取根目录 SKILL.md，并返回该技能版本的文本文件目录 |
| `skill_read(skill_id, path, start_line, end_line, reread)` | 读取包内指定文本；可显式指定行范围处理大文件 |

初始发现信息只包含自定义技能的 ID／description／类型／版本，以及内置技能按类型分组的全部 ID；
不会默认装入整份技能正文。206 个内置 description 的占位已从各自原文适用场景补齐；旧覆盖记录
没有有效说明时，展示沿用新版内置说明，不覆盖用户的真实描述。技能检索结果只给候选与适用条件，
模型选中后再读取完整指令与所需引用；`kb_search` 仍可发现候选，但不再注入前几条正文片段。

版本快照与已读内容由各任务／路线／决策记忆持有，不用进程级“已读”标记跨 Agent 省略正文。
当前上下文保留了同一版本、同一文件及行范围的原文时，重复读取只回引用；需要重显可设置
`reread:true`。JSON 通道用已有 DecisionMemory 增量发送新读内容，重建决策段时保留已读原文，
并将版本快照持久化到原检查点；CTF 已读原文保护标记及快照随路线对话恢复。新任务首次打开
读取最新版本；技能被停用或删除后拒绝新读取，已经进入模型上下文的内容不会自动消失。
业务走访与复测的原生技能状态与各自当前工具对话共存，按它们已有的生命周期管理。

会话里的“使用技能”来自成功读取的实际工具回执，子任务摘要附近显示技能 ID、版本和已读文件数；
仅检索命中或模型声称使用不会生成成功标记。审计记录 `skill.loaded`／`skill.file_read`，带当前
Agent、任务／路线（或复测候选）以及文件、版本和内容指纹，便于区分各分支的实际来源。
资料仅为参考，不能作为独立漏洞复现证据；技能文本不会改写用户授权或绕过既有审批。

目前适配管理页保存的文本技能：包含 SKILL.md、references、脚本文本和配置文本；不自动安装依赖、
不自动执行脚本，图片／二进制资源仍沿用导入时明确提示未导入的边界。脚本执行继续使用已授权的
原工具通道。渐进加载和无重复正文的结构测试、离线脚本联调不代表真实模型一定更准确或费用一定
下降；真实效果需结合任务成功率、误选／漏选、引用读取完整性及实际端点用量继续验证。

### MCP 卡片目录

MCP 首页与 Skill 使用同一套卡片、启用／未启用分组和绿色滑杆，默认显示已启用连接。
可组合筛选名称／命令／地址／Agent 关键词、传输类型（STDIO／HTTP／SSE）、来源
（配置文件／管理页保存）、默认风险等级、额外授权 Agent、首次添加日期和时间记录状态；
支持最近／最早添加、最近修改、名称排序。筛选在分页之前执行，两组数量反映当前条件的全部匹配。
“沿用角色默认范围”表示未配置额外授权角色，不代表所有 Agent 均可使用。

管理页或助手新建 MCP 时记录首次添加时间，编辑和启停不改写；旧记录与配置文件连接显示
“时间未知”，不会用修改时间补造导入日期。日期使用北京时间自然日，截止日包含当日全部时间。
配置文件连接被管理页编辑后来源显示“管理页保存”，首次添加时间仍保持未知。

点击卡片打开接入配置编辑器，保存前读取最新配置版本，环境变量和请求头仍使用独立密钥输入框。
卡片地址摘要隐藏账号、查询参数和片段；卡片不展示环境变量或请求头的值。
删除前会确认并校验版本：管理页新增的 MCP 删除本地保存内容；配置文件连接保留本地移除标记，
刷新及重启后不会重新出现，不改写原配置文件，不卸载本地程序。
添加、修改、启停及删除均在新启动的会话生效，不热替换运行中的连接。

Exa 搜索配置与资源助手位于目录下方，按需展开；现有密钥保存、受控搜索和助手确认流程保持不变。

### Skill 目录与文件浏览

Skill 首页按卡片展示，默认进入“已启用”，可切换到“未启用”；两组数量反映当前筛选条件下的
全部匹配记录，分页只加载当前组。绿色滑杆表示启用，灰色表示未启用，并同时显示文字；点击后
技能转入另一组。资源助手在卡片下方折叠展示。

支持组合筛选名称／描述关键词、类型（`domain`）、来源（内置参考／压缩包导入／手动或助手添加）、
首次导入／添加日期范围和“时间未知／已记录时间”；支持最近或最早添加、最近修改、名称排序。
日期按北京时间自然日计算，截止日期包含当日全部时间，未知时间不进入日期范围。类型选项来自
实际目录，不自动推断技能类别；可在技能配置中修改 `domain`。清除筛选保留当前启用状态分组，
筛选在服务端执行后再分页，避免漏掉尚未加载的技能。

新添加或导入的自定义技能记录首次时间，后续编辑和启停只更新修改时间。旧数据缺少首次时间时
显示“时间未知”，不使用修改时间倒填。内置参考不标记导入时间，即使修改或停用也保留内置来源。

点击卡片进入该 Skill 的项目式文件浏览器，左侧展开根目录及子目录，右侧阅读 Markdown 或
查看其它文本；Markdown 可切换源文件并通过相对链接跳转已保存的包内文件。原始 HTML 转义，
脚本仅作为文本展示。新导入包保留 `files`（相对路径到 UTF-8 文本的映射），根文件为 `SKILL.md`；
编辑配置时以这些文件生成参考正文，保持页面与检索内容一致。历史技能只保存了合并正文时，
仅以 `SKILL.md` 展示该正文，不补造原目录。目录列表不传输文件正文，单项详情按需读取。

卡片“删除”会先确认并校验配置版本。自定义技能的保存内容被删除，可重新导入；内置技能使用
持久移除标记，重启后也不会重新出现。删除对象退出目录和后续参考检索，已有任务历史、报告及
已经进入上下文的内容不改写。Markdown 可在文件浏览器内编辑保存，未增加单文件上传／移动／删除操作。

### 直接编辑渲染后的 Markdown

点击技能卡片，在文件浏览器中打开 `.md` 文件，选择“编辑正文”，即可直接修改渲染后的标题、
段落、粗体／斜体、列表、表格单元格、代码块和引用。工具栏支持选中文字加粗／斜体和新增段落，
列表内回车创建下一项；点击“保存修改”才写入资源库。“切换源码”和“切换渲染编辑”共用当前草稿。
复杂扩展语法可用源码编辑；其它文本文件仍只读。

采用分块编辑：没有编辑过的块原样回写，不对整篇 Markdown 做 HTML 反转。渲染编辑保留隐藏的
YAML frontmatter、未修改的代码围栏、链接、列表结构及原始换行符；被修改的块按 Markdown
结构保存。源码模式可编辑文件完整原文。单文件保存保留技能 ID、description、类型、首次添加
时间和其它文件；这些目录配置仍通过“编辑配置”维护，不从正文重新推断。

保存会重新生成该技能的参考正文并递增版本，新任务的技能读取立即使用保存结果；已经固定版本
的运行中任务仍沿用原快照。内置技能的修改保存在当前资源库，不修改仓库内置种子；旧技能仅有
合并正文时，以 `SKILL.md` 保存为本地文件覆盖。

关闭／Esc、切换文件和打开配置编辑前会提示尚未保存的修改；刷新或离开页面使用浏览器的离开
确认。取消编辑放弃草稿，保存失败或版本冲突保留草稿，可切换源码复制。发生冲突时先保留需要的
文字，再取消并重新打开技能读取最新版本，不能强行覆盖他人修改。保存期间禁止继续输入、切换
文件或关闭窗口；粘贴只接受纯文本，不加载粘贴 HTML、图片或执行脚本。文件大小限制沿用导入
和技能正文限制，超过限制时明确报错，不截断保存。

### 导入 Skill 压缩包

在控制台「Skill 管理」点击「导入压缩包」，可一次选择多个文件，每个文件分别报告结果。
原生支持 ZIP、TAR、tar.gz / tgz、tar.bz2、tar.xz；RAR、7z 及其它 libarchive 可识别格式
需要运行服务的系统安装 libarchive（Debian/Ubuntu：`libarchive13`，Fedora：`libarchive`；
macOS/Windows 需提供可由系统动态库搜索路径发现的 libarchive）。Docker 镜像已加入该依赖，
已有镜像需重建；本次未实测 macOS/Windows 动态库加载。

包内可有包装目录或多个技能目录，每个技能通过 `SKILL.md` 识别。YAML frontmatter 中的
`name` 作为唯一标识（缺省使用技能目录名，限字母、数字、下划线和短横线），`description`
作为说明，可选 `domain` 作为类型（默认 `custom`）。保留目录与 SKILL.md 原文，并将该技能目录下的 UTF-8 文本参考资料（含 references 与
脚本文本）按相对路径合并为正文；嵌套技能的资料归最近的技能目录。不执行脚本、不安装依赖，
图片等非文本文件在结果中提示未导入。现有编辑、停用和参考检索同样适用于导入技能；
导入内容属于参考资料，不会扩大任务测试授权。

每包上传不超过 20 MiB，展开内容不超过 32 MiB，最多 1000 个条目，单文件不超过 2 MiB；
每个技能合并后的正文沿用 100000 字符限制。损坏、加密、不安全路径、链接及特殊文件会被拒绝。
同一压缩包原子保存：若任一技能无效、ID 重复或与已有技能（含内置）冲突，整包不写入；
可编辑已有技能，或修改包内 name 后重试。多个压缩包之间独立保存，成功结果不会因其它包失败撤销。

模型默认使用 `prompt_caching: provider_default`，不附加缓存参数。确认端点支持
Anthropic Messages 显式缓存后，可在模型编辑页选择 `anthropic_ephemeral`。
可按实际美元报价配置 `cost_cached_input_per_mtok` 与 `cost_cache_write_per_mtok`；
缺少实际用到的缓存单价或缓存用量时，新的费用统计标为未知；旧 `cost_usd` 字段保留
按普通输入价估算的兼容口径，不作为完整任务成本。输入/输出单价为默认 0 时同样视为
未配置，不表示免费。缓存命中收益需以端点实际返回用量评估。

自定义 MCP 可用 `allowed_agents` 指定额外执行角色，例如 `[business_context, ctf_web]`（当前支持业务体验和 CTF 各执行角色）；空列表沿用原有工具范围。该配置不会授予灵枢、秘书或报告角色执行权限，也不会扩大任务授权范围，工具审批仍按会话模式执行。

## 搜索与费用

SRC 和普通 CTF 的 `web_search` 优先复用有效缓存，再使用 Exa 官方免密搜索；免费服务不可用时，通过 curl 获取公开搜索引擎结果。模型也可设置 `source: public` 直接使用公开引擎，并在关键词中组合精确短语、`site:` 和版本/错误特征。公开结果的时效与适用版本仍须核对。

付费 Exa API 仅用于特别困难且明显阻塞进度的问题。模型须基于实际证据自行判断，显式给出 `paid: true` 和 `blocker`，说明已尝试的方法、免费资料为何不足以及关键缺口如何影响下一步。免费额度耗尽、限流或普通查询失败不会自动触发付费请求；有效的旧付费结果可以免费复用。MCP 管理页保存的密钥只供这一受控路径使用。智能体模式禁止所有上述网页搜索路径。

搜索输出先在本地去除 HTML 脚本/样式/导航噪声、重复段落和追踪参数，再合并重复 URL，返回固定字段的紧凑 JSON（每条摘要最多 480 字符，整份最多 4,800 字符）。缓存命中逐字复用结果正文；旧版已付费缓存就地清理并保留原检索时间，格式升级不触发重新检索。缩短结果降低输入量，实际模型缓存命中率仍以端点返回用量为准。

## 会话暂停与继续

会话列表标题旁的铃铛只显示未读的解题结果与待答提醒；点击提醒进入对应会话后，
该条提醒自动隐去，刷新后也不再显示；弹层右上角可将当前提醒一键全部已读，
待答事项仍保留在会话中。系统通知开关位于菜单底部的「设置」中，以滑块显示开关状态，
仅主动开启时申请浏览器权限；关闭系统通知仍可使用铃铛与页面提醒。
浏览器页面关闭后不会推送，系统弹窗还取决于浏览器和操作系统的通知设置。

主页和会话页都可直接拖入文件或文件夹，附件先加入当前草稿，点击发送后才提交。
图片附件会立即显示本地缩略图，点击可放大查看，右上角的叉可从草稿移除；
预览不提前上传，文件选择与拖放使用同一套预览。
文件不限制格式；文件夹逐项上传并保留子目录、同名文件及空目录，无需压缩或解压。
每次最多 20 个附件（文件夹计为一个），单文件或单文件夹总大小不超过 50MB。
「设置」中的垃圾桶图标打开存储清理，门形图标退出登录；太阳表示亮色、月亮表示暗色，点击直接切换。

输入框右侧共用一个圆形主按钮：没有草稿时，执行中的方形按钮用于暂停，暂停后
切换为继续图标；输入消息或添加附件后切换为发送按钮。Enter 只发送消息，不切换
任务状态。暂停请求会等待在途调用返回，之后不再启动下一次工具调用；等待审批
期间暂停，审批通过后也要等用户继续才执行。继续沿用原任务实例与路线状态。

暂停不会取消任务、重发任务描述或新开一轮。仍可补充消息，随后点击继续推进。
“更多操作 → 结束任务”才会取消执行，记录与成果保留。任务结束后发送消息属于
新的对话轮次；进程重启后的恢复使用已有持久记录，不能恢复已经消失的进程内调用，
也不保证每次请求都携带全部历史原文。

终态会话续传时重新加载模型注册表与密钥，更新端点、轮换密钥或删除模型后，
新一轮使用最新配置；续传排队期间仍可通过会话模型按钮更改选择。

高风险 MCP 操作需要 SRC 用户审批时，模型须填写工具目录里的宿主审批说明字段
（默认 `_approval_purpose`）：说明对什么目标做什么操作、为什么需要、可能影响什么。
缺少说明时先返回给模型补充；函数名不能作为目的说明。该字段只供宿主审批展示，
不会传给远端工具。风险分类、具体参数与单次审批绑定保持不变，CTF／智能体仍自动授权。

## 并行扫描者（SRC / CTF）

原版 SRC/CTF 控制台在任务启动时准备扫描控制器，初始待命，不自动扫描或调用扫描模型。
主 Agent 在规划、复盘、实时督导及用户消息决策中，通过 `scan_control` 明确派遣扫描者，
指定目标、信息收集目标、工具与限制；派遣后与专项角色并行执行并共享黑板，不作为它们的
前置依赖。扫描者根据主控派遣、用户原话、范围、规则和现场证据判断环境信息是否足够，再选择
HTTP 探测、Nuclei 模板或 Metasploit 模块；不会要求所有版本信息齐全才继续。
可等待其他角色的新事实，等待期间不反复调用模型；也可以判断不适用并结束。
不会默认运行全模板扫描，环境指纹不会自动被认定为漏洞。

主 Agent 可通过 `pause/resume/stop/forbid/allow` 管理扫描者。暂停、停止、禁止会撤回在途
扫描并保留已产生证据；恢复根据当前黑板重新判断，不自动重放工具。禁止状态在会话续聊时
保留，解除禁止后仍须重新派遣。Nuclei/Metasploit 适配器执行前检查当前许可及所派遣工具。
收到新用户消息时先挂起扫描，由主控重新判断是否继续，模型处理失败不会自动恢复。
控制指令携带版本号，旧规划不能覆盖更新后的禁止决定。控制状态与回执写入黑板和审计。
实际派遣后，探索图显示主控派遣的扫描目标和扫描阶段，普通调用保留在阶段详情中；
待命不生成扫描节点。扫描任务保存派遣来源，历史回放保留该关系。

在系统 YAML 中可配置（省略时使用以下默认值）：

```yaml
scanner:
  enabled: true
  binary: nuclei
  templates_dir: .venv/share/nuclei-templates
  rate_limit: 5
  concurrency: 2
  timeout_seconds: 180
  metasploit_enabled: true
  metasploit_command: [msfconsole]
```

提前准备 Nuclei CLI 与本地模板；不会自动安装或下载。二进制和模板必须能从既有
bubblewrap 沙箱访问，例如二进制放在项目 `.venv/bin/`，模板放在
`.venv/share/nuclei-templates/`；`~/.local`、`~/go/bin`、`/usr/local` 默认被遮蔽。
相对模板路径以服务启动目录解析。工具或模板目录缺失时记录跳过，其他角色照常执行。
部署参数可参考 [Nuclei 官方文档](https://docs.projectdiscovery.io/opensource/nuclei/running)。

Metasploit 同样只使用已安装且沙箱可见的程序。`metasploit_command` 是可信部署
命令数组，可指定包装器或发行包 Ruby 与 framework/msfconsole 的完整路径；
避免使用首次运行会交互初始化数据库的包装器，运行参数包含 `-n`，不启动数据库。
不自动安装、下载模块或开新服务。可先执行 `info` 读取实际模块说明和选项；
支持模块的 `check` 和辅助模块的 `run`，不提供 `exploit` 或后台任务启动。
选项经 JSON 传入固定资源脚本，不将模型输出直接拼为控制台命令。

扫描者可在编队中单独指派模型（角色键 `scanner`）；未指派时跟随会话选模或默认路由。
派遣后才启动独立模型分支，会产生额外模型用量；并行执行不保证完全没有 CPU、网络或供应商
限流竞争。每种扫描器有自己的执行槽；Nuclei 模板并发和请求速率受上述配置约束，
单进程请求速率不超过当前授权声明，低于每秒一次时使用每分钟限速。
Metasploit 的并发和速率由模型按模块实际选项及规则选择，不声称 Nuclei 限速会覆盖
Metasploit。此限制仅针对工具调用，不是任务预算熔断。

完整 JSONL 保存在会话 `artifacts/scans/<scan-id>/results.jsonl`，包含扫描器返回的
命中证据；执行日志由沙箱留存。扫描状态、目标、模板选择、退出码和线索写入黑板
`RECON_CLUE`，角色状态写入 `TASK_STATE`。命中均标为 `unverified`。
模型判断某条真实命中属于漏洞候选时，引用 finding_id 提交 `VULN/candidate`，立即
进入现有独立复核队列。模板 ID、工具实际提供的 CVE/CWE、原始证据来源保留；
扫描者不能写入已确认或 PoC 已验证状态。重复交接同一命中不重置已有复核结论，
新实证则沿用汇聚机制重新复核。

前端漏洞板块明确区分待复核、复核中、确认、误报与证据不足；“PoC 与原始证据”
按需读取完整详情。Nuclei 原文拆为结果 JSON、请求、响应和复现命令附件，不对下载
文件截断；原工具未提供的字段明确标注，不编造 PoC。Metasploit 保存实际资源脚本、
模块信息和完整执行日志；HTTP 模块若支持 HttpTrace，请求/响应保留在日志中，
不将非 HTTP 模块输出伪装为 HTTP 包。工具采集上限或中断造成的不完整仍须核对。

独立 HTTP 复核还会交付其实际请求、响应正文原字节、响应头/采集信息，以及从实际
请求重建的复现命令（重建命令本身不冒充另一次执行）。响应正文是 HTTP 工具解压后
保存的内容，不是原始网络帧；达到下载上限时明确标注。证据文件使用同一会话访问
检查和路径校验；历史记录缺少原件时不会自动补造。

SRC 危险动作仍经 ApprovalBroker 对本次调用即时审批，等待只挂起扫描分支；CTF
沿用工具操作预授权和审计。扫描发现的资产不自动扩围。自动更新、模板下载及 OAST
外部回连关闭，代码、浏览器和 fuzz 模板未启用。轻量模式维持单执行者，AWDP 与
智能体模式当前不自动启动该扫描分支。

暂停在模型/工具边界生效，在途扫描按现有暂停语义运行；停止或主流程收尾时取消
未完成扫描并回收进程，已产生的完整线索和原始输出保留，标明取消或失败，不等待
扫描自然结束。正常收尾先停止扫描，再排空已经交接的复核候选，避免遗漏末尾候选。
不会在扫描结束前宣称信息收集完整。

## Agent 查看图像

执行角色可按需调用 `view_image(path, question)`，从本会话附件、工作目录或产出
目录读取 PNG、JPEG、GIF、WebP（单图最多 10 MiB），使用当前角色绑定的模型核对
图中信息。此调用会额外发送一次图文模型请求，计入原有模型用量；不另派 Agent。
当前模型/端点须支持视觉输入；错误或空回复会记录失败，不宣称已看懂图片。

每次读取先保存独立快照到 `artifacts/view-images/`，事件仅携带相对路径、文件名、
MIME、大小和 SHA-256，不把 Base64 写入工具调用事件。时间线“执行明细”和 Agent
工作台以“查看图像”显示，与命令和工具调用同级；图片可直接显示并点击放大，历史
回放使用同一快照。在线读取经过会话访问检查、目录描述符校验和摘要核对；原图
后续被修改不会改变已保存的输入快照，快照自身变化时显示加载失败。

仅读取会话内普通文件，拒绝符号链接与目录穿越；不直接加载远程图片 URL，也不
执行 SVG/HTML。Chat Completions 与 Responses 使用各自图像内容类型，Ollama
使用原生 `messages[].images`，不会把二进制编码误当作普通提示词。

## 数据与备份

题级沙箱目录按赛题 ID 区分。安全的 ASCII 短 ID 保持原目录；中文、含特殊字符、
首尾需裁剪或超过 80 字符的 ID 使用可读前缀加原文 SHA-256，避免规范化后串题。
工作目录和轻量模式的持久 `/tmp` 使用同一身份。升级前已存在的旧目录保留，
但不会自动迁移可能混有多题文件的目录；需要复用旧文件时，核对归属后复制到
工具实际返回的本题 `workdir`，不要将旧共享目录整体合并。

用量逐笔写入会话目录的 `usage.db`（SQLite WAL 事务），首次打开时导入旧
`usage.json`，保留原文件；备份运行中的数据库请使用 SQLite 备份接口，
或停服后复制。旧版程序无法读取新增的数据库计量，回退前需另行导出。
读取结果按数据库/WAL 文件版本缓存，单文件仅保留最新快照。
资产库启动导入按历史记录游标增量执行；`POST /api/assets/sync` 可全量重扫历史会话。
会话列表与状态由单一调度器兜底刷新，隐藏页面降频，SSE 继续提供即时事件。

### Token 统计口径

模型用量以端点返回的 usage 为准。流式响应按字段合并累计快照，重复快照不会重复相加；
同一调用中的 SDK 重试用量累加，失败或取消前已返回的用量也会持久化。
输入总量包含缓存读取与写入，缓存命中率只使用已提供缓存计量的输入；输出采用端点返回值，
不另行重复添加推理 Token。费用仍按配置单价估算，不代表供应商结算账单。

仪表盘的消耗摘要、构成、模型排行和趋势采用同一时间筛选，执行状态与累计成果另行标注。
计量不完整或历史未提供的记录会单列，未知用量不按正文长度补算；旧账本不会自动回填此前漏记的消耗。
后端重启后新调用使用该记账口径，刷新页面加载新版仪表盘。

只读导出任务结果、用量、缓存命中和费用覆盖率：

```bash
.venv/bin/python -m scripts.token_report --workspace .spiritscout --models-config configs/models.yaml
```

新调用的 `cache_diagnostics` 记录相邻请求首次变化的位置：模型/端点、请求选项、工具目录、
系统消息或历史消息，也区分纯追加、截短和首次观察；只保存哈希、位置和长度，不额外保存
提示词正文。`prefix_changes` 汇总原因。此比较针对网关规范化请求，SDK 的协议转换和供应商
缓存驻留不在本地可见范围内，不能把它当成服务端缓存失效原因。实际命中仍仅取 usage。
重启或诊断缓存淘汰后的首次观察不声称是服务端冷缓存；同名模型按供应商实例分别统计。

默认筛选当前代码版本，`--all-versions` 包含旧记录。输出的 `sessions` 关联任务和题目，
分别统计平台判对 Flag、本地已完成题目、已交付补丁和独立复测通过的漏洞；任务 `done`
仅表示执行结束。本地答案完成不等于独立验证，补丁交付不等于修复验证通过。
题目直接调用与主控/报告等公共调用分列；按成果均摊时包含会话失败尝试与公共调用，
美元和人民币分列。缺价格、用量、历史明细或成果来源读取失败时，完整均摊成本为 `null`。
历史正金额保留为旧估算，不按当前价格回填。成果是当前持久化快照，按版本筛出的部分调用
不能冒充其完整成本。HTTP 只读入口为 `GET /api/sessions/{session_id}/outcome-costs`。

`--models-config` 或 `GET /api/models/diagnostics` 对照已核对的官方参考与本机声明，
提示未声明的窗口/思考档位、档位差异和缺失价格，不调用付费端点、不修改配置。
新调用记录供应商身份、配置协议/窗口、请求的思考档位与传给后端的档位、调用时价格快照；
旧记录中的未知项不补猜。传给后端不代表供应商已接受该档位；真实兼容性仍需端点验证。
官方参考带来源和核对日期，仅适用于对应官方域名，不套用到代理或套餐报价。

### 供应商价格、登录与剩余额度

「添加供应商」左侧按厂商分组；有多个接入版本时展开选择按量 API、Coding / Token / Agent
Plan 及国内/国际版本。搜索名称或地址会展开匹配分组。预设只是协议和端点配置，不代表账户
已订阅，也不代表所有厂商支持 OAuth。火山、千问、MiniMax、百度、腾讯、小米等套餐可选
`other_token_plan`，单独记录用量；尚未适配的公开价格保持未知，不冒充免费或按量计费。

在「模型 → 编辑供应商」选择计费方案：GLM 按量 API / Token Plan、Kimi 按量 API /
Token Plan、DeepSeek 按量 API，或自定义/代理报价。旧配置默认保留自定义报价，不根据
模型名猜测账号套餐。`billing_scheme` 随供应商合并到所属模型，`billing_plan` 仅记录套餐档位。
上述 GLM / 国内 Kimi / DeepSeek 方案自动查询官方公开价目表；「刷新官方价格」可主动更新。公开价格缓存 24 小时，
落在 `$XDG_CACHE_HOME/spiritscout/official-prices.json`（默认 `~/.cache/spiritscout/`）；
网络失败或页面格式变化会保留旧快照并标记过期，新调用不拿过期报价当最新价。
刷新接口为 `GET /api/provider-pricing/{scheme}?refresh=true`，只访问预设官方来源，不携带密钥。

按量 API 使用调用开始时的价格快照，人民币与美元分别统计；上下文阶梯或节假日分时价格
不明确时保留估算区间。套餐订阅费单独展示，不摊入每次调用；套餐调用记录 Token，GLM
在已知积分规则与用量时另记积分估算。参考价、余额、额度都不等于实际结算账单，账号折扣、
资源包、套餐适用客户端和续费条件以供应商账户页为准。计费方案选择本身不会购买或激活套餐。

Kimi Code 可选择 `auth_method: kimi_oauth`，保存后点击模型页供应商标题旁的「登录 Kimi」，在官方
页面输入设备码授权。访问令牌与刷新令牌加密保存在本机 `vault.db` 的独立表中；调用前自动
刷新，刷新与退出使用跨进程锁互斥。取消登录不删除原有有效凭据；「退出账号」清除灵枢本机
登录，若需撤销供应商侧授权请到其账户页处理。登录失效不会自动退回按量 API Key。
当前 OAuth 适配国内 Kimi Code 的 OpenAI 兼容端点 `https://api.kimi.com/coding/v1`，
不把令牌发送到用户另填的代理地址。公开设备流程参考
[Kimi CLI](https://github.com/MoonshotAI/kimi-cli/blob/main/src/kimi_cli/auth/oauth.py)；
真实账号授权与套餐可用性仍需用户完成登录后核验。

GLM 套餐使用专用 API Key，当前未提供通用 GLM OAuth 登录按钮。标准 API、个人套餐、
团队套餐的 Key 不通用；OpenAI 套餐端点为 `https://open.bigmodel.cn/api/coding/paas/v4`。
官方说明套餐仅限其支持的工具/环境，灵枢的配置不能替代供应商授权，详见
[GLM 接入指南](https://docs.bigmodel.cn/cn/coding-plan/quick-start)。Kimi 套餐也可使用其专用 Key。

模型页每个模型右侧直接显示本机累计 Token、调用次数、已测缓存命中率，以及供应商账户的
共享余额/套餐剩余比例和重置倒计时。共享额度不会按模型累加；历史没有供应商身份的用量不
猜归属。点击额度刷新，页面可见时每分钟自动更新，同一供应商多个模型复用一次查询。
鼠标悬停可查看更新时间、错误和完整明细。`quota_query` 默认 `auto`，可改为 `disabled`
或指定适配器。后端按准确域名与区域匹配接口，凭据不下发浏览器，不随重定向转发。DeepSeek 调用
[`/user/balance`](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/)，展示可用总余额、赠金、
充值余额及币种；Kimi 和 GLM 展示供应商返回的剩余比例与重置时间。GLM 使用窗口单位分类，
不会按重置时间早晚猜测周额度；不明确的 Kimi 窗口保留通用标签。缺字段、无权限或网络失败
显示未知/失败，有旧数据时标注旧值和更新时间，不显示虚假的 0。实现参考
[CC Switch 额度适配](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/services/coding_plan.rs)。
GLM 国内按量方案查询可用余额；旧配置使用共用推理地址时，自动模式先查套餐，没有可识别的
套餐数据再查同账户余额，不据此修改计费方案。鉴权或网络失败不会触发口径切换。
余额接口沿用 [CC Switch 的公开实现](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/services/balance.rs)，
供应商尚未公开稳定契约，接口变动时显示无法查询。

额外适配 MiniMax 编程套餐、OpenCode Go 套餐，以及 Moonshot、硅基流动、阶跃星辰、
OpenRouter 账户余额；国内与国际域名分别查询，不跨站转发 Key。MiniMax 编程套餐当前沿用
`coding_plan/remains` 的可识别结构，只取编程额度，不混入视频额度；接口升级无法识别时显示未知。
部分厂商接口未公开稳定契约，实际可查询性以账号权限及服务响应为准。

火山个人 Agent Plan / Coding Plan 需在供应商配置中另填查询用 Access Key ID 与 Secret，
加密保存在 `vault.db` 独立表，不写入模型 YAML，不与推理 API Key 混用。后端签名调用
`GetAFPUsage` 或 `GetCodingPlanUsage`，展示 5 小时、周、月窗口；企业版席位查询尚未适配。
参见[火山官方额度接口](https://docs.volcengine.com/docs/ark/get-afp-usage-api?lang=zh)。
尚无适配的厂商仍可配置模型与查看本机用量，账户额度显示「暂不支持查询」。

### 正常解题上下文与完成证据

正常模式优先将大段连续重复的工具输出编码为可逆的文本与次数，保留不同内容、顺序和换行；
不额外调用模型。已知模型容量时，采用网关预留输出和整理空间后的实际输入阈值，
不再因固定 48K 门槛提前改写缓存前缀、丢失中间细节。只有未知容量使用 48K 整理参考值。
窗口确有压力时再按完整往返生成旧历史摘要，保留用户原话、系统契约和最近四组完整往返；
这些阈值不是回合或消费上限。升级后旧的发送归档从完整历史重建一次，原始历史保持不变。
持久化历史不截断，摘要提供原始消息编号，模型可用 `history_read` 分页读回参数、代码和输出。
正常模式回读支持 `view=content` 直接读取工具原文，`find` 精确定位指定文本并返回命中位置
附近的原文页，并一次给出全文命中总数、请求 offset 后的命中数及最多 16 个位置。
统计为区分大小写的非重叠精确匹配，位置列表截短不影响计数覆盖全文；它不代表语义判断。
后续分页沿用返回的 `view` 和 `next_offset`。回读同时提供原观察的执行证据 ID，避免把
历史编号当作完成证据。已经可见的原文可以直接引用，笔记与重复回读不作为完成前的额外步骤。
相同请求的完整结果重复出现时只提示已有观察，不据此强制停止或限制工具。

正常路线增加 `evidence_memory`：模型按需维护事实判断、待验证假设和排除路径，并决定
修订或删除的时机。工具观察提供原始消息编号；事实判断与排除路径须引用原文片段，
后端校验当前路线、引用原文和来源哈希。更新使用 `base_revision` 防止同回合旧修订覆盖。
最新笔记随会话检查点保存，在旧往返归档后仍保留；原始消息改变时标为 `stale`，旧归档也会失效。
`matched` 仅表示原文匹配，不表示语义正确、现场未变化或已经验证答案，笔记不替代完成证据。
每条路线最多保留 24 项、总计 24000 字符的结构化笔记；达到容量时返回缺口，由模型合并或删除，
不自动丢弃原始证据，也不影响继续执行任务。用户要求和最近四组往返仍按上述规则保留。

单题 `record_answer` 要求模型说明验收条件、推导及实际验证，并引用支持验证的执行记录。
后端核对当前题归属、执行成功状态、实际返回结果和黑板依赖版本；失效、跨题或无法解析的
引用返回缺口继续调查。多答案完成前再次核对已保存的证据。此校验证明来源可追溯，不代替
模型判断答案含义，也不把成功退出当成解题正确。

可只读回放历史，比较发送体积而不产生模型费用：

```bash
.venv/bin/python -m scripts.normal_mode_baseline .spiritscout/sessions/sess-example
```

输出只含体积和保留情况，不导出原始消息；估算值不代表真实账单或未来缓存命中率。

经用户授权后，可用已配置的官方 DeepSeek 模型运行受控真实对照：

```bash
.venv/bin/python -m scripts.normal_mode_eval --run-live --model deepseek-flash \
  --output .spiritscout/reports/normal-eval-new --repeats 3
```

不传 `--run-live` 不会调用付费模型，输出目录必须不存在。脚本只读取实际模型配置和密钥，
在独立目录运行，不改写配置；仅连接指定 DeepSeek 官方聊天端点，没有其他厂商备用。
按调用时官方价目表估算费用；未取得报价不启动，未返回用量的请求保持未知。
`full_history` 与 `projected_memory` 使用同一模型、参数和工具，交替先后顺序；后者使用生产
正常模式历史投影。报告包含正确登记、错误完成、未完成、重复调用、记忆准备、Token、实际缓存
命中和费用覆盖率，准备及失败重试均计入。测试专用的调用数/时间/输出限制不接入生产。
需要比较代码改动前后时，可用 `--baseline-dir /path/to/trusted-snapshot` 加载可信本机快照中的
`src/spiritscout/ctf/{agents,evidence_memory}.py` 和 `src/spiritscout/gateway/normal_context.py`，
参考臂为 `previous_normal`；报告记录文件哈希，原工具契约、回读及笔记实现都来自快照。
此方式会执行快照中的 Python，只用于自己的可信代码；不覆盖工作树，生产进程不加载该快照。
这是短任务、重复/非重复长历史、后续证据更正、跨文件协议、发布失败恢复和独立路线的受控工具环验证。
默认让模型自行决定是否记忆，不再强制增加准备轮次；`--memory-checkpoint` 单独开启记忆准备/恢复检查。
`comparison` 要求每类至少三对样本、答案正确、完成校验有效，并且中位耗时与调用数不增加；
未达到的项目明确列出。该评测不覆盖完整 DAG、真实靶场或 WriteUp 质量，不据此推断普遍成功率。
供应商缓存可能跨臂预热，应同时看绝对输入、未缓存输入和成功结果成本，不能只比较命中比例。

### 探索链路中的关键进展

探索图按公开意图和验证方法组织任务。模型在已有决策中报告足以改变判断的新发现、
关键验证的重大突破或有依据的方向转变时，可通过 `exploration.milestone` 开启新的
阶段节点；即使方法标题相同，也不会覆盖此前发现。普通请求、读取、重试和持续验证
留在当前阶段，画布不按工具调用次数增加节点。

关键进展节点展示简短结论和观察依据，点击后可查看下一步验证、证据引用及本阶段
公开说明和执行记录。阶段间的“推进”表示同一路线的公开推进顺序；漏洞是否确认
仍以原始事实和独立复核结果为准。不同并行路线的进展不会互相串接。

展示标记随既有模型调用输出，不额外请求模型，也不读取内部推理。旧会话继续执行时
追加新版展示约定；历史中没有记录的关键发现不会根据文字关键词或回合序号补造。

会话头部的项目按钮带下拉箭头，点击可切换项目归属。顶部“主控轮次”读取实时调度
快照，不等整轮并行任务完成才显示；子 Agent 的执行回合不累加为主控轮次。

### CTF 技术报告与复现脚本

正常模式单题 WriteUp 按题目原理、关键判断、实际验证和复现步骤组织正文；不再要求逐段
展示调用 ID，也不把 Agent 分工、路线状态或内部完成字段当作解题过程。关键事实可用
`[E1]` / `[S1]` 短编号引用，原会话调用和文件定位集中在文末证据索引。题目代码中的变量、
函数、协议字段与真实输出保持原文；便于复现而替换路径的命令需说明工作目录约定。
后台写作不可用时标记为待整理的解题记录，保留答案和技术证据，不把内部执行草稿当正文。

正常模式核对可追溯证据、实际验证说明及证据发布成功后才登记答案；完成确认失败会返回失败并继续处理，不能对外宣告完成。

普通 CTF WriteUp 和无提交接口的后台单题报告会汇总本会话执行台账中的真实调用参数、
退出码和输出节选，以及工作区 `attachments`、`sandbox`、`artifacts` 中的源码材料。
材料有容量限制，报告明确标注节选和证据缺口；Python 完整源码可附解析得到的函数／类
起止行号。其他语言的函数名、反汇编地址和偏移仅按已有代码、命令输出等证据引用。
报告中的解释应结合关键代码、命令和输出，不单靠文字复述路线笔记。模型写作不可用时，
回退报告仍附上已采集的技术证据，不补造缺失过程。智能体模式的竞赛短摘要保持原有口径。

需要多步骤复现时，写手在对应题目节内用 `exp.py` 标题和完整 Python 代码块展示脚本，
说明依赖、运行命令、输入参数与验证状态，直接嵌入 Markdown 报告，不另存脚本文件、
不增加下载入口、不自动执行。报告整理的新脚本明确标注未执行／未验证，不虚构输出。
已有脚本优先按真实来源引用；证据不足或单条命令已经足够时，不强制生成 `exp.py`。

## CVE 情报库

CVE 情报独立保存在 `.spiritscout/cve.db`，跨会话共享；不替换通用知识库，也不进入
现场漏洞证据池。无需安装 Node、`cve-mcp` 或新的 Python 依赖。默认配置：

```yaml
cve:
  enabled: true
  sqlite_path: .spiritscout/cve.db
  online: true
  nvd_api_key_env: NVD_API_KEY
  timeout_seconds: 25
  cache_ttl_seconds: 21600
```

路径相对于服务启动目录解析。自定义路径时，服务进程与维护命令必须使用同一配置、
同一启动目录，并具有数据库目录写权限。容器部署须持久化数据库及其 WAL 所在目录。
数据库、下载快照、API Key 均不提交 Git。下面命令在项目根目录执行；Windows 使用
`.venv\Scripts\python.exe`，Docker 中使用相同模块命令和容器内配置路径。

```bash
# 首次下载并导入官方全量 CVE List（数百 MB 下载，数据库需数 GB 磁盘）
.venv/bin/python -m spiritscout.cve bootstrap
# 索引已安装的本地 Nuclei 模板；不会下载或执行模板
.venv/bin/python -m spiritscout.cve templates
# CVE List 增量 + NVD 最近修改记录；之后从成功水位继续
.venv/bin/python -m spiritscout.cve sync
# 查看实际收录量、模板数量、快照日期和各来源同步水位
.venv/bin/python -m spiritscout.cve status
# 离线检索和详情
.venv/bin/python -m spiritscout.cve search 'Apache Log4j'
.venv/bin/python -m spiritscout.cve lookup CVE-2021-44228 --offline
# 明确需要补充 NVD 时，保留分页；下一页使用返回的 next_offset
.venv/bin/python -m spiritscout.cve search 'Apache Log4j' --source nvd --offset 0
```

全局 `--config` 写在子命令之前，例如
`python -m spiritscout.cve --config configs/system.yaml status`。
维护命令不加载模型，不调用付费模型端点。`bootstrap` 显式下载全量快照，校验资产长度
及官方提供的 SHA256，支持官方双层 ZIP；导入失败不标记全量完成，重新执行可复用已完成
的下载。发布 API 临时不可用时，可运行 `bootstrap --offline` 导入已校验的完整下载；
它不声明缓存是最新发布。`import /path/to/cvelistV5/cves` 可导入预先准备的官方 JSON 5 目录，也支持官方
ZIP 或 NVD JSON 文件。旧快照不能覆盖同来源较新记录，REJECTED 记录保留撤销状态。
不自动判定某台目标受漏洞影响。

建议每日运行 `sync`，模板更新后运行 `templates`；本功能不自动安装系统定时任务。
CVE List 使用官方滚动变更日志，整个批次成功才推进水位；若停更超过日志覆盖窗口，
明确提示重新运行 `bootstrap`，不把漏掉的时间段当成已同步。NVD 初次增量默认最近七天，
不代表历史 NVD 数据全量；可以用 `sync --source nvd --since 2020-01-01` 回填。
NVD 同步按不超过 120 天的时间窗分页，失败后从未完成窗口重试。可分别运行
`sync --source cvelist` 或 `sync --source nvd`。日常维护失败会返回非零退出码，
原有本地数据仍可检索。没有 NVD Key 也能访问，限速更保守；可通过环境变量
`NVD_API_KEY` 增加配额，不把密钥写入 YAML 或模型上下文。

智能体工具 `cve_lookup` 提供 `search`、`lookup`、`package`、`status`：

- `search` 默认本地 FTS 检索，支持 `offset`、`limit`；按相关性排序并合并同 CVE 多来源。
  `source=nvd` 可补充在线候选，也可传入已确认的完整 `cpe`。关键词命中不能代替版本匹配。
- `lookup` 按完整编号查询官方 CVE、NVD、EPSS 与 CISA KEV，关联本地模板。
  保留 CNA/ADP、原始版本条件、CPE 布尔树及来源时间，不把版本区间简化为产品名匹配。
- `package` 使用 OSV 的 `package`、`ecosystem`、`version` 查询包版本，保留
  `next_page_token`，后续通过 `page_token` 读取，不把首批结果当完整结果。
- 返回来源成功、缓存、过期、离线或失败状态。联网失败可保留旧缓存，但显式标注过期和错误；
  “查询失败”不表示“没有漏洞”。较大的完整 JSON 落在会话 `artifacts/cve/`，返回预览与路径，
  模型需要按需读取完整版本条件，不能依据预览确认影响。

专项 Agent、CTF 执行者、扫描者与独立复核者可使用该工具。扫描者以
`decision: cve` 调用，仍遵守主控派遣；查询情报不增加目标探测权限。
`competition` 模式强制只读本地记录与缓存，即使传 `refresh=true` 也不联网；
`cve.online=false` 可对所有模式禁用在线查询。情报不是目标现场证据，复核角色不能
用 `cve_lookup` 的输出充当独立复测或控制组，扫描命中仍交现有候选与复核流程。

数据接口参考：[官方 CVE List](https://github.com/CVEProject/cvelistV5)、
[NVD API](https://nvd.nist.gov/developers/vulnerabilities)、
[OSV API](https://google.github.io/osv.dev/api/)、
[EPSS API](https://api.first.org/data/v1/epss)、
[CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)。
