# AWDP 离线 9B 修复增强方案

状态：已落地真实 Web 轻量链路评测、`verify_patch`、原件引用与可按赛事调整的 tar.gz 补丁包；多样本基准、完整数据流证据包和专项训练仍是后续提案。接口、限制与实测见 [源码审计与补丁](AWDP源码审计与补丁.md)。

## 目标与约束

- 轻量模式运行时断开互联网，只使用本地 9B。规则、解析器、知识、模型和必要依赖提前准备；不配置云端回退。
- 比较最终补丁的实际效果：原漏洞是否被阻断、正常业务是否保留、部署脚本能否正确应用。发现数量和模型自评不能替代这些指标。
- 保持单一持久执行者；模型决定调查、调用工具、修补与结束时机。不新增固定解题阶段、运行回合上限或预算熔断。
- 断网不等于禁止题目授权的赛场局域网访问；服务测试仍依据用户范围和实际部署约定。
- “接近云端顶尖”是待验证目标，不是对任意语言、业务逻辑或未知漏洞的保证。

## 最初观察到的缺口与本批处理范围

1. 当前 `source_context` 提供结构导航；Ctags 引用、Python 调用名与别名候选还不是完整数据流证明。
2. 初期模型多次混淆原件、工作副本和部署路径。本批增加原件引用与保持层级的检出副本；部署映射仍由模型依据题目判断。
3. 9B 曾提出只拦截 `..` 的路径修复，独立回归确认绝对路径与链接仍能绕过。
4. 初期 `submit_fix` 只校验语法、路径或归档。本批引入绑定最终提交件/原件/测试的回执，拒绝挪用回执；回归通过仍只覆盖实际运行的用例。
5. 早期三个合成样本为工具级冒烟测试；本批改用真实 Web/Runtime 轻量链路，保留上下文投影、观察记录与重复行动复核。样本少且调试中条件变化，不能据此估算完整系统成功率或模型上限。

## 第一优先级：真实执行链路的评测与补丁验证

### 固定可复现基线

让评测复用实际轻量执行循环、工具发现方式、技能版本、证据记忆和重复行动复核。记录模型/量化配置、源码和工具版本、运行环境与全部结果。调试实验的请求限制与产品运行策略分开。

先积累 30–50 个可运行的小型样本，包含真实漏洞、合法复杂输入和无漏洞对照；覆盖已支持语言中能完整运行的部分。开发集与留出集按仓库/漏洞来源分离，同一漏洞的改名版本不能充当独立留出样本。不同实验使用同一工具条件，缺环境、超时、未完成分别统计。

指标包括有效修补率、正常业务通过率、安全对照误报数、提交件应用成功率、重复调查开销和耗时。扫描消警和编译通过单独记录，不算安全验证通过。没有相同条件下的云端基线时，不宣称性能等同。

### 新增可组合的 `verify_patch` 工具

模型提供候选脚本、原件引用、部署约定、正常测试和安全测试。工具负责执行与记录，模型继续判断测试是否覆盖真实根因。

- 创建独立原版与修补版副本，向后者实际解包最终 tar.gz 并执行其中的 `patch.sh` / `update.sh`；不复用开发目录的未提交修改。
- 运行原有业务测试、漏洞前后对照及必要变体。安全对照应在原版确实呈现漏洞、修后阻断；两边正常业务均应通过。
- 测试代码和预期保持版本固定，候选修补不能修改验收程序。零测试、跳过或依赖缺失不能变成成功。
- 失败反馈包含具体输入、期望、实际结果、退出状态、源码位置和执行引用，支持模型继续修补。
- 把原件、补丁、部署映射、测试及环境摘要的哈希绑定到验证记录；文件改变后旧记录不证明新提交件通过。
- 按实际平台检查脚本调用方式、权限、重复应用、构建、启动和健康状态；不推测服务名。

先实现已有脚本生成器支持的源码替换与本地可运行服务；特殊安装环境、二进制补丁和平台重启约定按适配器扩展，不假定统一部署方式。

`submit_fix` 区分“已生成候选”“有静态依据”“本次回归通过”“未覆盖”。模型仍决定是否交付，但“验证通过”必须引用与本次产物匹配的真实记录；没有环境时可明确交付未验证候选。

## 第二优先级：减少 9B 必须自行推导的事实

### 原件与产物使用稳定引用

建立原附件清单，为上传文件、归档成员、工作副本和修改件提供引用及哈希。编辑结果可携带经验证的原件来源，打包时不再要求模型反复拼接长路径。

引用只确定已知来源，不自动猜部署根目录。多份附件同名、来源不唯一或哈希不符时保留歧义；服务器目标仍由题面、Dockerfile/启动配置和模型判断确定。保持现有字符串路径接口兼容。

### 按候选生成源码证据包

扩展当前导航工具，让模型按函数或扫描候选读取一组相关材料：入口、危险调用、调用点与实参、包装函数、校验/鉴权，以及相关部署配置。原文、来源哈希和可继续回读的位置随结果保留。

先补 Python 已有 AST 中的参数传递与返回值线索，再按真实评测需要适配其他语言。动态分派、反射、重绑定或未解析边标记未知，不靠同名符号拼出“完整调用链”。

与现有证据记忆和重复行动复核连接：明确哪些文件内容未变、哪个结论被反例否定、下一次调查还缺哪个事实。提示模型调整方法，允许有新条件的重试，不用次数阈值强制结束。

## 第三优先级：按安全边界检验修法

参考资料增加适用条件、常见错误修法及反例，仍不写死解题步骤。例如路径读取关注的是实际文件是否属于授权目录，不能仅禁止某个字符串。

模型可据源码选择相对/绝对路径、链接、相似目录前缀、解码顺序等适用对照；正常样本同时包含合法子目录、非 ASCII 名称和其他允许输入，避免关闭功能也通过测试。对象归属则对照同身份正常访问与跨身份访问，不把前端隐藏当服务端授权。

复用现有测试并在需要时生成补充测试。生成测试仍可能误解业务，因此需要原版基线、已有测试和留出测试约束，不能把同一个 9B 的自评当独立证明。

存在修法取舍时，可让同一 9B 在分开的工作副本上提出候选；由执行证据比较漏洞阻断、正常行为和修改范围。额外采样会增加耗时，不设所有题目必须多候选的规则。独立审阅上下文可用于提出反例，但不能代替实际回归。

## 第四优先级：离线知识与专项训练

知识检索返回适合当前语言、框架、危险操作和失败原因的少量资料；记录来源与适用条件，支持读取完整原文。优先维护已经通过实际回归的修法和反例，禁止把未经验证的模型回答直接沉淀为成功经验。

在真实基线稳定后，再评估本地 9B 的专项微调。训练材料采用公开可复现补丁、验证通过的本地修补轨迹、安全对照和已证伪修法；不依赖云端教师。可优先训练工具选择、来源路径引用、错误修法识别与根据失败记录修改代码。

训练是否可行需另核对基础权重、部署格式、硬件和适配器支持；不在本次提案中下载权重或启动训练。验收使用未见仓库，不能用训练题的记忆表现宣称泛化能力。

## 可借鉴的开源实现

- [Agentless](https://github.com/OpenAutoCoder/Agentless)：定位、候选修改、复现测试与回归筛选。借鉴其可验证候选的机制，不将其固定流程移植为灵枢的强制计划。
- [Vul4J](https://github.com/tuhh-softsec/Vul4J)：真实 Java 漏洞、人工补丁及复现/候选评测工具。仅选能实际复现的样本；仅静态告警的条目不能当动态漏洞回归通过。
- [SWE-smith](https://github.com/SWE-bench/SWE-smith)：可运行修复任务和训练数据构建。其软件工程成绩不能直接外推到本地 9B 的 AWDP 安全修补能力。

这些是机制或数据来源；使用时准备可离线复用的必要部分，不要求比赛时访问其在线服务。

## 建议实施范围

先完成实际运行链路的基线与 `verify_patch`，再做原件引用和源码证据包；用新增证据确定后续技能、候选筛选和专项训练的投入。候选代码可分别落在 `awdp/verification.py`、原件清单模块及现有 `context.py/context_worker.py`；通过现有沙箱、审计和轻量工具分发接入。

第一批验收应能拒绝已观察到的路径黑名单弱修复，保留合法读取；准确区分未运行、执行失败与验证通过；提交的整个归档与验证过的归档一致；所有组件在断开互联网后仍可运行。
