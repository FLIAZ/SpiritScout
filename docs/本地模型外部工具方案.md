# 本地模型的外部工具使用方案

状态：分批实现。范围是可扩展的成熟工具目录，包含 IDA、pwntools、jadx、pwndbg 等，
不限定为两种工具。已补本机 CLI/Python 用法查询、失败恢复提示与执行日志分页回读；
统一能力探测、专用适配与持久调试仍为设计。现有 shell、MCP、后台任务和结构化读取通道继续可用。

现有通道的真实调用结果见 [本地外部工具调用验证](本地外部工具调用验证.md)：本机 9B
已实际使用 TShark、GDB、jadx、Z3 与 pwndbg 批处理；初轮 pwntools 出现错误参数循环。
这些实测不代表本文新增的统一目录和持久调试方案已经实现。

## 先解决能力不可见

当前独立 Ollama 轻量模板的 `mcp_servers` 为空，不会继承正常部署的 IDA。
单执行者已用 `command -v` 探测包括 jadx、apktool、gdb、pwndbg、r2、tshark 在内的
部分命令，但没有核对 Python 库、Java 运行时、调试器插件及其实际执行环境。
此外，`mcp_search` 自身位于按需工具目录，模型需要先发现入口，再发现实际工具。
本机安装了 pwntools / idapro，不等于沙箱或队友的容器已安装并能使用。

现有 `binary_inspect` 已封装 r2 的部分静态查询，CyberChef 等也有独立通道，
这些应复用。现有 `shell_start` 能启动后台作业，但没有向作业发送交互命令的接口，
不能将它直接算作已实现的持久调试会话。

MCP 不必然占满上下文，CLI 也不会自动节省上下文。决定开销的是实际发送的
工具 schema、结果体积及保留的历史。已有 `mcp_search` 默认每页返回三个工具，
应继续使用这种按需装载方式，不恢复全量工具 schema 注入。

## 建议的调用结构

```text
可用能力摘要 → 查询操作契约 → 模型选择调用 → 后台执行 / 已有工具通道
                                             ↓
                           结果文件 + 索引 + 本次观察 → 工作黑板
                                             ↓
                              按函数 / 地址 / 页码回读
```

每次会话提供一份短能力清单：工具名、用途、真实可用状态和查询入口。完整参数、
示例、操作列表只在查询后返回。优先扩展已有 `tool_lookup` / `tool_invoke`、
`mcp_search` / `mcp_call`、后台任务与产物读取通道，避免再建一套平行工具系统。

可用性来自部署探测：可执行路径、版本、Python 解释器与库版本、运行所在的主机或
容器、许可证是否可用。明确区分 installed / ready / unavailable / unknown；
不能把宿主机安装成功当作容器或沙箱可调用，也不能凭文件名猜测需要什么解题流程。

模型的选择原则应明确写入轻量提示：开始实现通用基础功能前，先查已就绪能力；
已有工具能直接完成当前操作时优先使用，缺失或确实不适用时再写替代实现并说明原因。
这只约束能力选择，不规定题型步骤，也不强制每道二进制题都调用 IDA。
目录要同时写用途关键词，例如 pwntools 的循环序列、ELF 与 ROP，避免模型只知道工具名。

首版改动落在 `SingleCTFAgent._inv_bootstrap` 的执行环境探测、轻量系统提示、
已有工具目录及结果通道。将探测结果缓存到当前部署的能力快照，查询或执行失败时更新状态；
不要每轮重新启动 IDA 检查许可证。初始上下文只带简短能力摘要，参数与示例按需展开。

## 可扩展工具目录

以下是纳入方案的候选范围，不是当前镜像的安装清单或已通过测试的承诺。
类别用于能力检索，不能变成后端按题型强制执行的步骤。相同能力由模型结合真实可用状态选择。

| 能力 | 候选成熟工具 | 拟接入方式与读取单位 |
| --- | --- | --- |
| Android / JVM 分析 | jadx、apktool、javap | CLI 批处理；保存反编译目录、类索引和资源，按类、方法或文件区间读取 |
| 原生程序静态分析 | IDA、Ghidra headless、radare2 / Rizin、readelf、objdump | 复用已有 MCP / 静态读取；需要时补 CLI；按函数、地址、交叉引用读取 |
| 动态调试 | GDB + pwndbg / GEF、LLDB | 批量检查与持久调试分开；按本次停止事件读取栈、寄存器、内存等观察 |
| 二进制操作与交互 | pwntools、checksec、ROPgadget、ropper、patchelf | CLI / Python 库；记录工具版本、目标摘要、脚本和运行日志 |
| 约束与密码计算 | Z3、SymPy、SageMath、PyCryptodome、gmpy2 | 在已探测的解释器或 CLI 中使用成熟库；保留输入、约束与验证结果 |
| 流量与协议 | TShark、Scapy | CLI / 库；完整结果落盘，按过滤条件、帧号或流读取 |
| 文件、固件与元数据 | file、7-Zip、binwalk、ExifTool、oletools | CLI / 库；保存文件清单、提取产物和来源偏移，按条目读取 |
| 内存取证与规则匹配 | Volatility 3、YARA | CLI / 库；同时探测符号与规则是否就绪，按进程、对象或命中结果读取 |
| Web 与服务测试 | Nmap、ffuf、Nuclei、sqlmap、ZAP / Burp 可用接口 | 复用现有扫描通道或 CLI / API；按本次目标、模板和实际结果留审计 |
| 编解码与数据转换 | CyberChef、已有格式解析库 | 复用当前通道；记录输入摘要、操作参数与输出产物 |

目录应采用可增补的描述清单，避免在 Agent 主循环中为每个工具新增条件分支。
每项至少描述用途与检索词、执行位置、接入类型、可用性探针、操作契约入口、产物格式，
以及是否持有进程、数据库或调试会话。新增普通 CLI 工具主要增加描述与探测；
特殊生命周期才增加适配代码。这些是待实现的数据契约，不是已经生效的配置项。

探测结果必须区分“路径存在”“能启动”“所需操作可用”。例如 Java 缺失时不能把 jadx
标为就绪；GDB 可执行不等于 pwndbg 已加载；Python 的库探测必须使用实际执行脚本的
解释器。目录中的路径与状态来自本次部署，不能将维护者机器的结果写进通用模板。
插件、模板和规则也是依赖，离线比赛前随运行环境准备并记录版本。

查询入口还要区分灵枢工具、外部 CLI 与库函数。外部命令按实际版本读取局部帮助；
Python 库按实际解释器获取函数签名与必要文档，不能把库函数名直接当作 `tool_lookup`
的已注册工具名。本机实测已出现 `cyclic_find` 猜参循环，通用技能检索没有提供正确签名；
现已增加按需 `tool_help`：先 `tool_lookup(name="tool_help")` 获取契约，再经 `tool_invoke`
查询 `kind="python", name="pwn.cyclic_find"` 或 `kind="cli", name="jadx"`。查询与实际
调用使用同一工具沙箱，Python 导入、签名与短文档来自该解释器；CLI 支持 `--help`/`-h`。
导入异常与缺依赖原样反馈，不在宿主导入附件代码、不安装工具。帮助信息不代表分析操作完成。
普通调用仍使用 shell/python，失败后给出用法查询入口；未增加固定回合上限或自动改写模型参数。

`history_read(view="output", message_index=来源编号)` 可搜索或分页读取该次执行的落盘日志，
与消息 `content` 中可能已经截短的预览区分。返回可复用的 `next_call` 和来源指纹；
续读文件变化、文件丢失、轮转缺失与非文本输出会明确说明。最近页位置与重复读页次数进入
工作黑板，回读日志页可被证据笔记引用，但不算一次新的候选验证。详见
[轻量稳定性与回读](轻量稳定性与回读.md)。

## 四类接入方式

| 类型 | 代表 | 生命周期与上下文处理 |
| --- | --- | --- |
| 批处理 CLI | jadx、apktool、TShark、readelf | 短命令用现有沙箱；长命令用后台作业；返回摘要、索引与产物引用 |
| Python / 数学运行库 | pwntools、Z3、Scapy、SymPy | 按实际解释器调用；模型编排脚本，复用库实现基础功能；脚本与结果可回读 |
| 持久交互工具 | GDB / pwndbg、LLDB | 维护会话 ID、进程状态及命令通道；每次只读取所需观察，不能每轮重开进程 |
| 服务与专用分析接口 | IDA MCP、已有 HTTP / RPC 工具 | 按需查询契约，复用连接和分析数据库；依照真实接口能力调用 |

工具可能同时提供几种入口。选择依据是可用性、状态需求和实际上下文开销，
不以 CLI / MCP 名称判定优劣，也不把所有工具的 `--help`、schema 或输出一次性注入模型。

### IDA 与 pwntools

| 工具 | 推荐接入 | 给模型的能力 | 上下文控制 |
| --- | --- | --- | --- |
| IDA | 可用时复用已有 idalib / MCP；新增批处理 CLI 作为无常驻服务的选项 | 建立分析数据库、函数索引、指定函数反编译、交叉引用、字符串及地址查询 | 先索引，再读指定函数；数据库与完整导出落盘，返回准确地址、来源和游标 |
| pwntools | CLI 加沙箱内 Python 库 | `checksec`、`cyclic`、汇编/反汇编，以及 ELF、ROP、tube 等库接口 | CLI 返回短结果；复杂交互保存脚本和日志，按区间读取；不自写替代成熟基础能力 |

IDA 的 `-A` 支持无交互运行，`-S` 可执行脚本，`-B` 会批量生成数据库和汇编。
实际适配须探测用户安装版本的可执行文件和许可证；不能假定存在 `idat64`。
脚本等待自动分析完成，输出结构化索引后显式退出。`-B` 的整份汇编文件不能直接
回填上下文。依据：[Hex-Rays 命令行说明](https://docs.hex-rays.com/9.0/user-guide/configuration/command-line-switches)。

pwntools 同时有命令行和 Python 库；CLI 适合已有小操作，复杂交互仍应使用
`pwnlib`，由模型编排业务逻辑。让模型写调用成熟库的脚本是正常用法，
不应误判为“手搓替代工具”。依据：[pwntools 命令行文档](https://docs.pwntools.com/en/stable/commandline.html)。

### jadx：反编译产物需要索引

jadx 有 CLI，支持输出目录与按类反编译，适合先把结果保存到会话产物目录，再查询所需
源码。适配器应记录输入摘要、实际版本、选项、退出状态、反编译错误及输出文件清单；
部分反编译失败不能标记为完整成功。类名与路径来自真实索引，不让模型猜类名反复重跑。
随后按文件和行区间读取，并保留原始字节码/资源对应关系；复用匹配输入和参数的产物。
官方接口依据：[jadx 使用说明](https://github.com/skylot/jadx#usage)。

### pwndbg：需要调试器状态

pwndbg 可通过自带启动器使用，也存在从 GDB 初始化文件加载的部署；仅探测
`command -v pwndbg` 会遗漏后一种情况。探针需要实际确认调试器版本、Python 环境、
插件命令及目标架构是否匹配。首批覆盖 GDB 路径，其他调试器入口单独验收。
部署依据：[pwndbg 官方安装方式](https://pwndbg.re/stable/setup/)。

单次 core / 批量检查可保存命令脚本执行；多轮调试应维护本会话专属的调试进程与目标，
提供打开、执行命令、读取观察、中断和关闭能力。控制接口可评估
[GDB/MI](https://sourceware.org/gdb/current/onlinedocs/gdb.html/GDB_002fMI.html)，
pwndbg 扩展命令的兼容性须单独实测，必要时使用受管的控制台/PTY。现有后台任务需要
补足交互输入、命令完成识别和中断回收，不能只换成 `shell_start` 就声称接入完成。

黑板记录会话 ID、目标摘要、运行/停止/退出状态、停止事件序号、断点和观察产物引用。
寄存器、栈和堆快照关联具体停止事件；继续执行后，旧快照不能当作当前内存。
脱离、停止目标进程和关闭调试器的语义需要分别定义，不误杀非本会话创建的进程。
用户中途消息到来时，长命令应可中断；应用重启后原进程若已丢失，要明确标记会话失效，
不能把保存的调试摘要当作仍然存活的进程。

## 执行与黑板契约

- 调用带输入文件摘要、操作名、参数及工作区；输入不覆盖，产物写入本会话目录。
- 长任务返回 job_id，复用进程与后台任务管理；用户中途消息在模型等待和工具返回后继续投递，
  取消时能停止对应子进程。任务超时返回实际状态，不把超时当作没有结果。
- 黑板记录工具版本、输入摘要、分析数据库/产物引用、已读函数与区间、实际失败原因、待验证项。
  工具观察与模型结论分开，不由后端自动判定题型、结论或下一步。
- 重复分析可复用与输入摘要、工具版本、分析参数匹配的数据库；这是产物复用，
  不是重放可能变化的网络结果。用户明确要求重新分析时支持强制刷新。
- 输出分页保留准确引用和完整文件路径；不以摘要替代证据，不制造已执行或已看过的记录。
- 缺依赖、缺许可证、端点不可达、反编译失败分别返回具体原因，由模型决定替代方法。
  不自动变成云端调用，不通过固定轮次或预算上限终止任务。
- 能力发现不构成目标授权；CLI、调试命令与服务接口沿用现有会话范围和动作审批语义，
  不能通过换一种工具入口跳过现有执行边界。

黑板不能只保存“已经调用了哪个工具”。模型选定的关键发现应通过现有 `evidence_memory`
带原文引用保存；待验证推断单独标记。后续作出否定结论或改方向前，模型应查询相关笔记
及产物索引，按需回读原文。2026-11-07 的真实 9B 长会话已经显示：观察和探索图持久化正常，
但模型不主动登记关键发现时，仍会遗忘中段证据。因此“主动写入并再次使用证据笔记”应是
本方案的验收项，不能用黑板数据库有记录或工具调用次数替代。

后续扩容实测还发现两类读取缺口：模型重复读取同一历史片段却不推进游标，以及把
shell 的截短预览当作整页数据。成熟工具的返回契约应明确完整性、完整产物位置，
并给出可复用的下一页调用参数；验收需核对结果中段的证据能被实际回读。
完整实验边界见 [本地上下文扩容验证](本地上下文扩容验证.md)。

## Windows 队友的部署边界

灵枢优先在 WSL2 内源码部署，pwntools 安装到同一 Linux 执行环境，也可选择 Docker。
Ollama / llama.cpp 可运行在 Windows，但需从实际的 WSL/容器环境验证模型接口可达。
IDA 商业安装与许可证留在队友机器，不打包进仓库。第一阶段复用其可用的 IDA
服务接口；CLI 路线需单独解决 Windows 主机执行与 WSL/容器的文件交接，不能把 Windows
可执行路径当作 Linux shell 中可直接运行的工具，也不要求为了测试再安装一套 Linux IDA。

jadx 可以部署在分析容器或已配置的宿主执行端，但 Java、输入文件和输出目录必须位于
同一个可访问的执行环境。GDB / pwndbg 首批覆盖 Linux 分析环境；Linux ELF、Windows
原生程序和远程调试目标分别报告支持状态，不能因模型服务运行在 Windows 就推断
调试器也具备 Windows 原生调试能力。调试所需权限与符号文件需在实际部署中验证。

当前 `INSTALL_TOOLKIT=1` 安装的是 `pyproject.toml` 的 Python 可选工具箱，不会因此
自动安装 jadx、Java、GDB / pwndbg 或完整取证生态。部署文档应列出各工具组的真实依赖
与检测结果，不把全部候选工具塞进基础镜像，也不在断网比赛中隐式下载依赖。

## 分阶段实施与验收

1. **通用目录与探测**：补可扩展描述清单、Python / Java / 插件探测和执行位置；在轻量
   初始摘要显示已就绪能力及查询入口。工具缺失仍能启动，明确报告缺口。
2. **首批覆盖不同类型**：jadx / apktool、GDB / pwndbg、pwntools、已有 r2 静态读取与
   IDA 按需 MCP，同时选 TShark 和 Z3 验证同一目录能够扩展到不同领域。
   先复用已有通道，再补产物索引和必要的适配器，不为形式统一重写成熟实现。
3. **状态与产物**：补持久调试命令通道、分析产物复用、按类/函数/区间回读、中途指令处理
   及失效恢复；不同工具族都使用相同的来源和完整性契约。
4. **其他工具组**：按真实部署补充文件、内存取证和 Web 工具描述，缺依赖明确标注；
   首批可用不代表整张候选清单已验收。
5. **真实本地 9B 对照**：同一材料与目标，对照现有链路及新目录，记录发现/选择工具的成功率、
   输入 token、重复调用、端到端耗时、结果正确性和消息响应延迟。

验收至少覆盖以下实际行为，不能只检查目录里出现了工具名：

- jadx：对已知 Java / Android 夹具使用真实反编译结果，按类回读；保留反编译失败信息。
- pwndbg：在同一受管会话跨多个工具回合继续调试，核对断点与栈/寄存器；中断、停止和
  目标退出都有真实状态，不能每回合悄悄重新启动目标。
- pwntools：使用实际库/CLI 完成小操作；缺库时返回实际解释器与依赖缺口。
- r2 / IDA：使用真实地址与交叉引用定位证据，数据库或产物复用可核对。
- TShark / Z3：使用相同目录和产物契约完成小型离线 PCAP / 约束夹具，验证可扩展性。
- 跨工具：工具缺失、Java 缺失、插件未加载、IDA 许可失败、离线依赖缺失、长输出分页、
  中途改目标、停止与恢复，以及容器到 Windows 执行端的文件交接。

在没有点名工具的任务中，还要验证本地模型能先发现并使用合适的成熟能力，
不退回自写反编译器、调试器或基础库替代品。工具已执行、关键结果被引用、
后续回合能再次回读及最终结论正确，是分开的验收项。
