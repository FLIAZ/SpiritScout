# AWDP 源码审计与补丁

轻量 AWDP 由同一持久执行者结合源码与本地扫描候选判断漏洞，提出根因修法，再按题面交付补丁。
扫描器不决定解题顺序，也不把命中自动登记为漏洞。任务模式、授权和完成判断仍沿用原有机制。

## 审计与参考技能

开场按当前资源库的启用状态提供四个技能的简短目录。已启用的 `awdp-fix-patterns` 会预载通用根因、
API 语义和兼容性反例，其余正文由 Agent 使用 `skill_open` 按需读取。停用和用户覆盖均保持有效：

| 技能 | 作用 |
| --- | --- |
| `awdp-source-audit` | 核对真实入口、攻击者可控输入、跨文件调用、权限/配置、防护反例与实际危害 |
| `awdp-scan-triage` | 研判扫描候选、检查覆盖和错误、回读完整报告，避免以零命中证明安全 |
| `awdp-fix-patterns` | 说明根因修法的适用条件，避免黑名单、错误路径比较和破坏正常功能的修复 |
| `awdp-patch-delivery` | 区分附件容器与提交格式，维护部署映射，并验证实际提交脚本 |

审计结论区分已复现、静态确认、待验证与证伪，说明位置、传播链、前置条件、实际影响、修法、
正常功能和漏洞回归的真实证据。缺依赖时保留未覆盖项，不把编译通过、工具成功或登记成功当成漏洞修复。

## 离线扫描

本机使用现有项目虚拟环境安装可选组件：

```bash
.venv/bin/python -m pip install -e '.[audit]'
```

普通 Docker 镜像通过 `--build-arg INSTALL_AUDIT=1` 加装；`docker-compose.light.yml` 默认启用此构建参数，
可用 `INSTALL_AUDIT=0` 关闭。需要重新构建镜像才生效。
固定版本见 `pyproject.toml` 的 `audit` extra，不影响未选该 extra 的核心依赖。
该构建参数也安装 `universal-ctags`，供下文源码导航使用。原生安装时由系统包管理器提供带 JSON
支持的 Universal Ctags（例如 Debian/Ubuntu 的 `universal-ctags` 包）；Python AST 导航不依赖它。

轻量 Agent 经 `tool_lookup(name="source_scan")` 获取契约，再调用 `tool_invoke`：

```json
{"name":"source_scan","arguments":{"action":"scan","path":"source","limit":6}}
```

`path` 是本题工作目录下的源码目录，也可使用本题附件、产物或持久 `/tmp` 的实际路径。
压缩包可以使用启动感知或 source_manifest.checkout 已检出的副本；超出快照支持范围时在沙箱安全解包。不自动执行安装脚本或运行附件。扫描使用现有沙箱、审计和逐次超时，
只载入随包规则，关闭遥测、在线版本检查和自动修复，不上传源码或请求在线规则。

17 条本地规则覆盖 Python、PHP、JavaScript/TypeScript、Java、Go、Ruby 的部分请求到危险操作路径，
以及 C/C++ 无界写入热点。各语言覆盖的类别不同；这是有限规则集，不是全漏洞分类覆盖。
社区引擎不提供完整跨文件分析，鉴权、对象归属、业务逻辑、动态分派及配置仍由 Agent 审计。
规则语义参考 [Semgrep 本地规则](https://docs.semgrep.dev/running-rules) 和
[污点分析说明](https://docs.semgrep.dev/writing-rules/data-flow/taint-mode/overview)。

扫描先生成只含适配源码的快照，避免附件自带 `.semgrepignore`、`nosem` 注释和 `tests/vendor` 路径隐藏文件。
原文件不会被改写；命中映射回真实路径、行号和该次内容的 SHA-256。完整清单、原始 JSON、stderr 与报告
存于 `artifacts/awdp-scans/<本题作用域>/<扫描编号>/`。报告页给出 `next_call`，使用 `action=read`
读取后续候选，不重复扫描。

`coverage` 区分可扫描数、实际扫描数、跳过数和错误。单文件 1 MiB、总快照 32 MiB、4096 个遍历文件的
容量限制及不支持的扩展、链接、解析错误都会留下缺口。按需要缩小范围补查；`complete` 仅描述本次扫描覆盖。
`unavailable`、`no_targets`、`failed`、`partial` 不表示安全；修后没有命中也不能替代实际漏洞回归。

## 小模型的源码导航与精确编辑

轻量 AWDP 提供源码导航和精确编辑，不把整个仓库灌入上下文，也不改变模型规划权：

| 工具 | 用途 | 不代表什么 |
| --- | --- | --- |
| `source_context` | 文件目录、函数定义、Python 调用/导入别名、原文分页和 SHA-256 | 索引不证明调用可达、数据流连续或存在漏洞 |
| `edit_source` | 校验原文哈希和唯一匹配，生成修改副本与完整 diff | 替换成功不证明语法、兼容性或漏洞修复 |

`source_context` 经 `tool_lookup` / `tool_invoke` 调用；常规 AWDP 工具视图直接提供 `source_manifest`、`edit_source`、`build_patch`、`verify_patch`，收缩视图时仍可按需发现。例如：

```json
{"name":"source_context","arguments":{"action":"index","path":"source"}}
```

返回本题 `artifacts/awdp-context/<作用域>/<编号>/index.json` 和第一批文件（含每文件最多 6 个定义摘要）；后续使用返回的 `index`。
`map` 分页列文件；`find` 携带 `symbol` 查定义；`references` 查调用/别名线索；`read` 携带 `file_id`
读取原文，也可直接调用定义/引用返回的 `read_call`。每页的 `next_call` 可继续回读；长行不会静默丢失。
默认 6 项结果、60 行原文，原文页最多 5000 字符；大函数可继续读取。需要查某个文件时用 `file_id` 限定范围。
已知实际文件路径时也可直接 `action=read,path=...`，工具为该文件创建快照并返回原文、哈希及续读索引。

Python 使用 AST 保留函数范围、装饰器、所属函数、调用点和导入别名。其他语言用 Ctags 定义与词法引用，
后者可能包括注释/字符串。别名可能被重绑定，同名函数可能属于不同模块，动态分派/反射仍需模型核对。
不构建附件或载入项目的 Ctags 配置，不联网下载解析器。UTF-8 配置和启动脚本也可回读；非 UTF-8、链接、
超限和解析失败明确留在索引中。快照限制为单文件 1 MiB、总计 32 MiB、4096 个遍历文件；结构记录最多
40000 条，单次查找最多返回 40000 条候选并标记截断，可缩小范围补查。`coverage.complete` 仅指本次
索引收集/解析过程没有报告缺口，不是安全覆盖率。没有 Ctags 时保留 Python AST 和文本回读并说明缺口。

索引对应当时的文件内容，修改后应重新索引。用 `read.content` 的精确原文与 `sha256` 编辑，例如：

```json
{"name":"edit_source","arguments":{"source_ref":"","path":"source/app.py","sha256":"实际读取的64位SHA256","edits":[{"search":"完整的旧语句","replace":"完整的新语句"}]}}
```

每个 `search` 必须在同一原件中唯一、非空且范围不重叠；所有编辑检查通过才写独立副本。哈希过期、原文
多处匹配或未找到时拒绝编辑，保留原文件。只接受 UTF-8 文本、单文件 1 MiB、最多 32 段编辑；返回 `patched`
供继续编辑、验证和 `build_patch` 使用，完整差异保存在 `diff_file`。`original_path` 是读入文件的实际路径，
不能直接填作 `build_patch.files.source`；`patched` 则保留返回的完整绝对路径。原件成员名不匹配时，打包错误
会提供实际附件路径示例供核对，不自动猜部署映射。不能生成副本后仍测试旧路径。

匹配失败会返回候选的行号、原文预览和绑定文件哈希的 `search_ref`，包括仅缩进/换行不同的候选。
核对范围后可把该项改为 `{"search": "", "search_ref": "候选引用", "replace": "修后原文"}`，
无需再次手抄长原文；非空 `search` 与 `search_ref` 二选一。
候选不自动应用，多处匹配由模型选择；原件变化或范围重叠仍拒绝编辑。

模型的 `build_patch` 入口先冻结修改内容，在断网沙箱检查 Python、Ruby、PHP、JSON 和 shell 文件语法，
再打包同一份字节。语法错误返回文件及编译器诊断，不生成提交包；未知类型或缺少解释器明确标为未检查，
不能据此声称构建成功。语法检查不加载应用、不安装依赖，项目构建和正常/安全回归仍需实际执行。

9B 模型可借此按需读取相关函数和调用者、减少猜测路径与重写整文件；模型规模本身不能保证检出率。
工具回归与真实模型评测应分开记录，真实效果应同时检查漏报、误报、正常功能、补丁可用性和实际模型用量。

## 原件引用与最终提交件验证

启动感知会为支持的附件建立私有原件快照，并检出保持原层级的工作副本。模型得到真实工作目录、前 8 个
成员的 `source_ref` 和有界文本预览（单项最多 2000 字符、总计 5000 字符），不再靠猜测定位解压结果。
材料只说明文件事实，不替模型选漏洞、修法或解题步骤。其余文件用 `source_manifest.list/read` 分页读取。
原件预览、成员列表和分页均返回带真实工具名及参数的 `read_call` / `next_call`。
附件原文通过 `source_manifest` 读取；`history_read(output)` 仅适用于保存过执行日志的消息，
选错来源会返回消息原文与附件原文的实际读取入口。
原件快照支持 ZIP、tar 系列、单文件、上传文件夹的已材料化文件；单文件 2 MiB、总计 32 MiB、4096 文件。
链接、路径穿越、重复成员和超限明确报错，不生成悄悄漏文件的“完整”清单。

`source_ref` 绑定题目、附件成员和内容，附件变化后失效。`edit_source` 可传 `source_ref + edits`，
`build_patch.files` 可传 `source_ref + patched`；原有路径/哈希调用兼容。原生工具使用平铺参数结构，
走兼容路径时填 `source_ref:""`，避免本地约束解码器对联合 schema 的兼容问题。后续修改副本仍用其实际路径及哈希。
编辑契约保持 `search` 在 `replace` 前，AWDP 请求保留工具字段顺序；参数报错会返回实际参数契约。
部署 `target` 必须依据题目确定；不会把本机绝对路径变成服务器路径，也不自动剥除归档外层目录。

`verify_patch` 接受本题 `build_patch` 生成且未改写的 `archive`，及 2–8 组 `{name, kind, code}`
或 `{name, kind, code_file}` 测试。已有脚本优先用 `code_file`，不要再次粘贴长代码或把测试加入补丁包。
Ruby、Node.js 等可改用 `{name, kind, command, expected_stdout}`：`command` 为程序参数数组，
在真实部署根直接调用应用，工具负责 Python 包装及输出断言，无需模型手写跨语言包装。
命令须正常退出；标准输出去掉末尾换行后与 `expected_stdout` 比较。预期异常在原生检查代码中捕获并打印
观测值，程序加载错误、非零退出或超时均视为运行错误，不能冒充修前反例。
`command` 与非空 `code/code_file` 互斥；未使用的 `command` 可省略或填空数组。
文件限于本题 sandbox、持久 `/tmp` 或 artifacts 内的普通 UTF-8 文件；工具冻结其内容，回执哈希绑定冻结版本。
`code` 和 `code_file` 二选一，未使用的字段可省略或填空字符串。输入先编译检查，语法错误直接返回 `invalid_tests` 及测试名、行号，
不创建验证回执或应用补丁；同类语法错误即使引号、空白不同，也会触发现有证据复盘机制。
`kind` 分 `functional` 和 `security`，`code` 为含实际执行 `assert` 的 Python 脚本，或
`unittest.TestCase`（不要调用 `unittest.main`）。普通断言脚本作为一例，记录实际执行断言数；
`try` 末尾 `assert False`、由指定异常类型捕获的负向检查也受支持，单独记录实际进入的异常检查次数；
未调用的函数或没有此失败断言的异常捕获不计作检查。
支持 `if __name__ == "__main__"` 调用断言脚本；只打印 PASS、仅定义未调用的测试函数或只调用 exit(1) 都不能证明测试成立。
测试的当前目录、导入路径及环境变量 `AWDP_ROOT` 都指向干净部署根；可驱动本机已有其他解释器，
不引用旧工作副本或外部临时文件。测试文件的 `__file__` 是测试自身路径；Python 通过正常 `import` 调用原应用，
不要用 `exec(open(源码).read())` 复用测试的全局环境，否则会改变应用依赖 `__file__` 的相对路径语义。
归档包含部署子目录时显式指定 `source_prefix`。

工具在两个独立 bubblewrap 工作区中运行冻结测试。修后环境先实际解包最终 tar.gz 并执行其中入口，检查所有文件的精确差异、
权限保持和重跑幂等，再执行同一组测试。正常功能须修前修后均通过；安全测试断言安全行为，须修前产生
断言失败、修后全部通过。无测试、导入/运行错误、跳过、预期失败、超时或测试改写原源码均为未验证。
此验证环境断网，不自动装依赖或重启宿主服务；缺环境要明确留为缺口。
测试无需自行解包或复制应用；修改测试中的程序源码会使验证无效。正常用例在原件上失败时，
反馈直接保留实际加载/断言错误，先核对测试与环境。工作黑板持续保留最近改件、最终包和验证回执的
实际路径、哈希及历史回读入口；新包与旧回执的哈希不匹配会明确标出，读取其他文件不会抹掉这些进度。
离线构建工具链、项目依赖缓存及真实沙箱验收见 [AWDP 离线编程环境](AWDP离线编程环境.md)。

回执位于普通模型沙箱不可见的控制目录，公开 JSON 报告在 artifacts。`verification_ref` 同时绑定
整个最终提交件、原件快照、测试、解包器和验证执行器哈希与环境结果。`submit_fix` 引用回执时检查最终发布件和声明文件映射；换归档、入口、修复文件、原件或
失败回执会被拒绝，公开报告改成 passed 也不能冒充通过。未提供回执仍可交付，但明确标为未获工具验证。
未通过的提交会返回回执中的具体问题；只修正测试时复用原包并重新验证，不靠改提交说明或重复打包改变状态。
`functional` 不应混入本次新增的拒绝行为；这些断言保留在 `security` 组，与正常对照分别验证。
审查后未确认需要修改时，模型可显式调用 `finish_challenge(complete=true, no_fix_needed=true, reason=审查范围与依据)`。
系统单独保存这一审查结论，不伪造补丁、答案编号或验证回执；它不等同于证明源码绝对安全。
已确认问题但尚未完成修补仍用 `complete=false` 说明缺口，两种结束状态不会混为一谈。
支持 builder 生成的 `patch.sh` / `update.sh`、包根或单层目录布局，以及显式选择的兼容裸脚本。
应用时用参数把部署根覆盖为干净副本，回执明确记录这一调用方式；真实服务器默认路径、命令白名单、
平台无参数启动和服务重启不由此证明。自行改写的提交件、编译/重启动作仍需另外验证，不能套用旧回执。

这些是所提供测试的回归证据，不是安全证明：模型可能写出不充分的测试，服务并发、竞态和真实部署环境
也可能不同。因此评测还会对最终发布件执行模型未见的独立边界检查。

## 真实轻量执行链路评测

`scripts/eval_awdp_local.py` 从真实 Web 上传和会话入口运行 Runtime、ModelGateway、SingleCTFAgent，
包括工具发现、上下文投影、观察记录和重复行动复核；不再用另一个手写模型循环替代产品运行。
默认只输出计划，已有授权后才传 `--run-local`：

```bash
.venv/bin/python scripts/eval_awdp_local.py
.venv/bin/python scripts/eval_awdp_local.py --run-local --case cross_file \
  --base-url http://127.0.0.1:8081/v1 --model qwen35-9b --context 98304 \
  --output /tmp/spiritscout-awdp-runtime-eval --keep-server
```

`--context` 应与现有本地服务实际窗口一致，不下载或重新部署模型。脚本创建独立配置和本机控制台，
打印实时会话 URL；`--keep-server` 在评测结束后保留控制台供查看。原用户配置和已有会话不受影响。
输出目录必须不存在。`--deadline` 是实验观察时限，到时停止测试会话并记未完成，不改变产品回合/预算策略。

评测仅接受本机 HTTP 模型端点，配置只有一个本地模型，无云端回退；宿主 Python 拒绝非回环连接，模型
沙箱断网。结果、关键实现快照/哈希和实际会话审计保存在输出目录。跨文件路径题隐藏回归检查正常/嵌套/中文/含点文件名、
相对和绝对路径越界、链接越界及同名前缀兄弟目录；对象归属题检查双方合法读取和互读拒绝。修补题必须有最终发布件、
绑定的 passed 回执和隐藏回归通过才算成功，不把模型自报或生成脚本算作通过。
三个合成样本仍不足以推算通用检出率；短会话通过也不证明长上下文、真实赛事或云端同等能力。

工具与交付稳定性可另外运行 `scripts/eval_awdp_reliability.py`。它复用同一真实执行链路，
用普通输入契约维护任务覆盖 Python 跨文件、Ruby 子目录与 CRLF、Node.js，以及无需修改的对照材料；
默认每类创建三次独立会话，包含 ZIP 与 tar.gz，不访问外部目标。生成的最终包另行解包应用并独立检查。

```bash
.venv/bin/python scripts/eval_awdp_reliability.py --run-local --rounds 3 \
  --output /tmp/spiritscout-awdp-reliability --keep-server
```

## 国内赛事补丁包交付

默认生成 `patch.tar.gz`，包根包含 UTF-8/LF、0755 的 `patch.sh`，`files/` 内仅放实际修改文件并保留原件层级：

```text
patch.tar.gz
├── patch.sh
└── files/
    └── bundle/src/app.py
```

这是一套可按赛事调整的默认值，不是所有国内赛事的统一标准。平台要求优先：

| 平台要求 | build_patch 参数 | 最终入口 |
| --- | --- | --- |
| 默认补丁包 | 无需额外参数 | patch.tar.gz 内 patch.sh |
| update.sh 在包根 | entrypoint="update.sh" | update.tar.gz 内 update.sh |
| update 外层目录 | entrypoint="update.sh", package_dir="update" | update.tar.gz 内 update/update.sh |
| 明确要求裸脚本 | format="shell_script" | patch.sh，修复字节内嵌 |

包内不额外放扫描报告、验证回执、密钥、缓存或未修改源码。下载保留 `patch.tar.gz` / `update.tar.gz` 名称。
[2024 Shieldtag 规则](https://shieldtag.hk-tag.org/Competition_rules_en)采用压缩包配可执行 `update.sh`；
具体入口、目录、命令限制及重启机制仍以本场题面为准。

源码以 ZIP、tar 系列、单文件或文件夹提供，均不决定提交格式。
工具不根据附件后缀推断部署位置，也不剥除外层目录。Agent 应读取 Dockerfile、启动脚本或平台说明，
建立原件与部署路径的映射。例如原包是 `bundle/src/app.py`，平台实际部署根目录是 `/srv/service`：

```json
{"name":"build_patch","arguments":{"files":[{"source_ref":"","source":"bundle/src/app.py","patched":"fixed/app.py","target":"app.py"}],"default_root":"/srv/service"}}
```

此工具可直接调用，也兼容 `tool_lookup` / `tool_invoke`。`source` 保留原附件成员路径；上传文件夹使用
`attachments/` 下完整相对路径；`patched` 指向本题修改副本；`target` 是部署根目录下相对路径，省略时与
`source` 相同。返回最终 `archive`、原件 `files`、映射、哈希、入口、格式及用法。来源歧义或内容未变会拒绝生成。

包内脚本需要 `sh`、`sha256sum`、`mktemp`、`cp`、`cat`、`rm`；兼容裸脚本另需 `base64`。
平台通常解包后直接无参数执行入口，因此 `default_root` 应依据实际部署填写，不能直接使用本机会话路径。
解包后的人工验证可用参数覆盖部署根：

```bash
sh patch.sh /实际部署根目录
```

无需给普通源码增加可执行权限；脚本保留目标原有权限，先核对所有目标的原件或修后哈希、拒绝链接，
再备份和写入。已修文件重跑不重复修改；写入失败尝试恢复，但不保证并发写入、强杀或磁盘故障下的事务回滚。
入口按自身位置读取包内修复文件，不依赖开发工作区或网络，也不依赖调用方恰好处于包目录。
生成器只替换已有文件，最多 64 个文件、修后字节合计 2 MiB；新增/删除文件、权限变更、特殊平台或更大提交件
由模型按规则另写并验证，不能复用 builder 的验证回执。

**构建和重启取决于实际服务。** 通用生成器不猜测服务名、端口或进程管理器。Agent 依据附件与题面明确
是否需要编译、服务重启或健康检查，并在最终提交件中按实际约定实现、重新测试；不能用无依据的进程查杀
代替服务管理。源码热加载、常驻进程、容器入口的处理可能不同。

交付前应将最终归档实际解包并应用到干净原始副本，核对变化范围、语法/构建、正常功能与漏洞前后对照；不能只测
开发副本或只跑 `sh -n`。`submit_fix` 的 `files` 始终填写原件路径，`description` 保存危害依据、修法、
部署映射/调用方法、实际回归与未覆盖项，并随可下载文件一起返回。
提交工具仅校验结构、原始路径和发布快照；不会执行脚本，也不能证明修复有效或平台接收。

公开验证报告使用与工具返回一致的 `results` 字段，并保留旧 `reports` 字段兼容读取。
同类验证错误再次出现时，轻量 AWDP 会归档较早的工具往返，保留最新错误、用户要求和原文引用；
失败类别不等于测试指纹，不作为相同结果、已修复或终止任务的判据。
