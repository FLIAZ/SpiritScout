# 灵枢（SpiritScout）项目文档

本目录是 SpiritScout 的系统化文档，面向三类读者：

- **新贡献者**：快速理解项目为什么这样设计、代码在哪里、改动会牵动什么。
- **评审/答辩/面试读者**：查看定位、架构、算法、创新点、价值与阶段判断。
- **部署与运营者**：理解安全边界、数据落点、能力上限与已知风险。

> 文档事实基准：`0.1.0` 版本、`main` 分支、2026-10-24 更新日志、2026-10-24 代码快照。
> 代码位置以 `src/spiritscout/...:行号` 形式标注，并尽量给出可点击的相对链接。
> 文中凡标注「推断」的内容，均为基于当前代码与文档的分析判断，不代表项目已排期承诺。

## 2026-10-26 功能更新

- 任务持续接收督导指令，已规划任务按空闲名额补位；会话工作台和右侧旁路对话显示执行进展。
- 上下文按任务、路线和模型协议复用，记录端点返回的缓存用量；SDK 重试和失败调用单独审计。
- 仪表盘按北京时间统计费用、Token、缓存和确认成果，柱体支持日期标签与悬浮明细。
- 搜索优先复用缓存和免费结果，付费检索限明显阻塞场景；智能体模式禁止公开网页搜索。
- CTF、智能体模式工具操作自动审批并留审计；SRC 危险动作仍逐次审批。
- SRC 可选浏览器容器支持新旧管理员环境变量；本地与容器部署共用登录和资源配置。

页面操作与配置详见 [README](../README.md)，各专题中的旧行号应以代码搜索结果为准。

## 文档写作约定

1. **代码是事实源**。当文档与代码冲突时，以代码为准，并在 09 的维护清单中登记修订。
2. **区分“机制”与“效果”**。每项设计尽量写清：用什么方法、达到什么目的、代码在哪、有什么代价或残余风险。
3. **不写死结论**。没有实测数据的地方不编造数字；商业价值与未来路线只给判断框架与前置条件。
4. **时间维度**。每个主题尽量回答：过去怎么来的、现在做到哪、未来可能往哪走。
5. **安全优先**。涉及授权、审批、沙箱、密钥的改动，先读 04 再动手。

## 一句话认识灵枢

灵枢是一个 **LLM 优先的多智能体安全测试系统**：主 Agent「灵枢」用动态 DAG 做元决策与派单，专项智能体集群以多路线并行执行，所有事实落进 8 层黑板，候选漏洞必须经独立角色「鉴真」复测后才能收录，最后生成报告并把可复用经验沉淀到跨会话经验库。它同时覆盖 SRC 漏洞挖掘、CTF 解题与智能渗透赛三种模式。
