# 独立自动任务与会话后台工作

## 独立自动任务

主页左侧「自动任务」直接创建希望自动完成的工作，无需先新建或选择已有会话。
填写名称、任务内容、执行模式、模型、可选项目与目标/范围、首次执行时间和频率。
支持单次、每小时、每天（间隔 24 小时）和每周；可停用、重新启用或删除计划。
输入时间使用浏览器本地时区，接口接收带时区的 ISO 时间，运行记录用北京时间展示。

每次触发都从保存的任务模板创建一个新的执行会话和独立工作区，分别保存上下文、产物与审计。
计划卡片展示最近五次运行及状态，点击「查看本次结果」进入该轮会话。
各轮不会持续往同一个旧会话追加消息；所属项目用于归类和正常项目规则注入。
模型留「自动」时跟随当前编队，显式选择时该轮所有角色统一使用所选模型。
任务内容可自行定义，执行能力和权限沿用灵枢已有运行模式，不因定时执行扩大授权范围。

只在同一计划的上一轮仍未结束时推迟新一轮，其他手动会话不会阻止独立任务触发。
错过多个周期时最多补一次，再前进到未来周期，避免积压多轮重复工作。
同一次触发使用确定的运行标识；启动响应丢失或服务恢复时不重复注册、入队同一执行会话。
停用影响后续触发，不取消已启动的一轮；重新启用已完成的单次计划表示再执行一次。

计划和运行目录保存在工作区 `scheduled-tasks/schedules.db`，Linux 服务需持续运行。
SRC 危险操作仍按 ApprovalBroker 即时请示，CTF/智能体模式沿用既有操作语义。
旧版绑定会话的计划保留兼容并标记为「旧版会话计划」，新建界面不再要求目标会话。

接口沿用控制台认证并禁用缓存：

- `GET /api/schedules`：任务模板、下次时间及最近五次运行。
- `POST /api/schedules`：`name`、`message`、`mode`、`model`、`project_id`、可选 `target`/`scope`，
  加上带时区的 `run_at` 和可选 `interval_seconds`（至少 60 秒）；独立任务不传 `session_id`。
- `GET /api/schedules/{id}/runs`：最近二十次执行的会话引用与状态。
- `PATCH /api/schedules/{id}`：`{"enabled": false}` 停用，`true` 启用。
- `DELETE /api/schedules/{id}`：删除计划，不删除已产生的结果会话。

## 会话内的并行后台任务

这与主页自动任务是两条独立链路。Agent 可以把耗时 Shell 放到当前会话后台，
立即获得任务编号，再推进其他独立工作；多项 Shell 可以同时运行。
会话「后台任务」页可查看最近五十项的名称、归属、状态、输出条件和 stdout/stderr，
也可以单独停止一项，不影响其他后台工作。结束后保留输出预览；服务重启后遗留运行态标记为中断。

| 工具 | 行为 |
| --- | --- |
| `shell_start(code, action, label)` | 在 Linux bubblewrap 沙箱启动后台命令，立即返回 `job_id`；行为声明与危险操作审批沿用现有策略 |
| `shell_watch(job_id, contains, stream)` | 注册输出条件后立即返回，Agent 可继续其他工作；命中或进程先退出时产生一次通知 |
| `shell_events()` | 一次性读取自己的未消费通知；正常决策回合已自动注入的通知不会重复返回，无需轮询 |
| `shell_status(job_id)` | 主动读取一项作业的状态及最近输出 |
| `shell_wait(job_id, contains, stream, timeout)` | 只挂起当前依赖分支，等待字面量命中或进程结束，其他 Agent/后台命令继续工作 |
| `shell_stop(job_id)` | 停止一项作业并回收沙箱进程组 |
| `task_wait(seconds / until)` | 当前分支定时挂起；两个参数二选一，ISO 时间须包含时区 |

例如，Agent 1 启动监听程序后注册 `shell_watch(contains="READY")`，可以先做其他独立检查；
通知会在它的下一决策回合以工具观测回灌，不伪装成新用户指令。
如果该分支已经没有独立工作可做，必须等 READY 才能推进，可调用 `shell_wait` 挂起这一分支；
Agent 2 和其他 Shell 不因此停止。依赖关系、是否先做其他工作仍由模型判断，不写死任务流程。

匹配为最多 4,096 字符的字面量，支持跨分块和 UTF-8 字符。进程先结束而未命中时明确返回
`matched=false`。可选等待超时不杀进程。用户仍手动暂停时，即使命中也要等暂停门放行。
Python 后台命令启用无缓冲输出，其他程序需自行刷新输出。

匹配使用最近 65,536 字符窗口，已注册条件在每次输出时检查；命中状态不被后续输出冲掉。
预览返回每流最近 2,000 字符，完整过程仍使用原沙箱日志轮转。条件通知和完成通知按 Agent
及题目隔离，仅消费一次；内存队列保存最近二百条通知，原审计仍保留事件。
后台任务不能通过参数改写宿主工作区，其他题目不能读取或停止它；控制台用户可管理本会话各任务。

等待不持有模型请求、不消耗重复模型回合。普通 `sandbox_exec` 超时不变，也不自动把所有超时命令
改成后台运行。当前整体运行结束、停止或服务关闭时回收后台作业；后台命令不在重启后自动重放。
Agent 收尾前需要根据事实决定等待、停止或报告后台状态，不能把「仍在运行」当成成功结果。

## 会话控制

「继续任务」会放行同一个运行实例；从已中断、停止等保留暂停态的会话显式继续时，
恢复执行后也会清除暂停门。普通暂停态下补充消息不等于解除暂停。

新建会话发送按钮旁选择模型后，该会话所有角色统一使用所选模型，覆盖编队中的角色指派，
不修改全局编队配置；选择「自动」恢复各角色原有编队路由。在途请求不重新发送。

用户消息存档点绑定会话目录；切换时清空旧标记，不从尚未清走的上一会话 DOM 推导新会话存档。
