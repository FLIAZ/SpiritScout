# 轻量稳定性与回读

本轮针对本地 9B 实测暴露的两类问题：已看到参数错误却反复原样调用，以及历史回读不推进、
把工具消息中的截短预览当作完整证据；同时修复续聊丢失工作状态和最新回执的问题。
没有修改模型权重，解题判断仍由模型负责，继续使用现有单执行者、工具沙箱与工作黑板。

轻量 AWDP 的源码审计、离线扫描候选、修复证据与 `patch.sh` 交付见
[AWDP 源码审计与补丁](AWDP源码审计与补丁.md)。扫描和脚本生成均可按需调用，不增加固定解题流程。

前缀相同时，不再逐字显示一遍后又收回；出现不同内容时立即展示，完整但较短的新回复也保留。
完整的相同说明合并显示，并标出额外重复次数。不同路线和用户消息之后的续记分别处理。

次数只表示公开说明重复，不代表工具没有执行，也不能证明模型已解决停滞；每次调用、工具结果
和原始审计仍保留。模型重试会发出对应输出的撤回事件，清掉旧片段；大块流式文本分片写入审计，
避免截断后被误判为另一段说明。以上修正不改变模型输入、工具选择或执行结果。

## 本机工具用法

`tool_lookup` 查询灵枢注册工具。Python 库函数不是注册工具，使用按需入口 `tool_help`：

```json
{"name":"tool_help","arguments":{"kind":"python","name":"pwn.cyclic_find"}}
```

上例是 `tool_invoke` 的参数，常用工具视图也可直接调用 `tool_help`。CLI 示例为 `{"kind":"cli","name":"pwndbg"}`。
查询在实际执行工具的沙箱完成，返回安装版本的签名、短文档或命令帮助；异常和完整输出照常落盘。
不会因查询而安装依赖，不把全部工具帮助加入每轮提示。参数报错和重复失败会提示查询用法再修正，
执行者仍决定重试、改变输入或方法；没有新增固定回合上限，也不缓存重放可能变化的执行结果。
Python 名称未解析时，会在本机包的导出项及有限范围的源码定义中定位候选，返回下一次查询参数；
不会把整个包的所有子模块导入一遍，也不把“模块路径猜错”判定为该库没有能力。帮助查询不计为答案验证。

## 历史消息与执行输出

`history_read` 支持四种视图：

| view | 内容 | find 的范围 |
| --- | --- | --- |
| index | 原始工具调用目录与读取入口 | 消息参数和消息文本；不搜索落盘文件 |
| message | 指定消息的 JSON | 该消息 JSON |
| content | 指定消息的文本 | 该消息文本，可能已含截短预览 |
| output | 指定执行留下的 stdout/stderr 合并日志 | 选择的完整日志代 |

用 `message_index` 定位来源；`output` 不接受任意宿主路径。`find` 为字面搜索，
`offset` 在目录中是消息编号，在文本中是字符偏移。`length` 是期望页大小；日志页会按实际
序列化体积缩短，必须使用返回的 `next_offset` 或直接调用 `next_call`。
搜索命中后的 `next_call` 连续读下一段，不自动跳到下一个命中而漏掉中间内容。

新执行的日志在落盘时计算指纹，首次回读便核对是否被改写；旧记录缺少执行时指纹会明确标注。
续读参数带 `expected_sha256`，来源变化时拒绝拼接。重复请求仍返回原请求的页，并提示续读，
不会暗中移动游标。最后一页没有 `next_call`；读到末尾不代表之前跳过的区间已经看过。
工作黑板保留最近回读位置、重复次数和续读入口，检查点恢复后仍可继续。

未知消息编号会返回实际编号范围、工具目录和用户原话的读取入口。连续失败触发专门的历史读取复盘，
不能靠反复请求同一不存在的编号获取内容；错误回执不会变成新的证据来源。

执行日志沿用现有轮转策略，只保留最近两代；已轮转、缺失或未完整捕获时不会声称源数据完整。
含 NUL 或无法无损按 UTF-8 解码的日志需用 Python 按真实编码/字节处理。
日志读取沿用本题沙箱与执行审计，拒绝被符号链接替换的日志。

日志页可作为 `evidence_memory` 的带原文引用来源；回读自身不计为新的验证执行。
回读结果的 `message_index` 定位原执行，`evidence_source.message_index` 才定位可引用的本页；
`source_sha256` 是日志指纹，不是笔记所引用消息的指纹。误用预览编号时，错误回执会列出
同一执行、已经回读且确实含有所引原文的页编号及消息指纹，不替模型改写笔记。
笔记仍由模型选择和维护，引用匹配只说明保存的文字确实存在，不代表推断正确。
笔记来源的可选 `expected_sha256` 为空时视为未提供，非空时校验格式和真实指纹；
不会把空字符串误报为来源发生变化。同内容更新返回 `changed:false`，修订号不增加，
并提示内容已保存。重复失败或无变化的笔记更新会进入笔记复盘，不把笔记更新当作新的证据。
上下文整理保留最后一次完整工具回执，避免把“已保存／未变化／引用失败”也随旧笔记一起归档；
较旧的笔记快照仍归档，以当前修订为准。

## 验证引用与重复提交

`record_answer.review.validation_evidence_refs` 优先使用真实调用 ID，也接受该执行原始工具消息的编号
（如 `57`、`msg-57`、`message:57`），以及执行记录中唯一匹配的日志完整路径或文件名。
框架将其归一为调用 ID，并保留原始引用；回读页不是新的验证执行，未知编号不能映射。
同名歧义、失败、截断、
同回合尚未读到或仅帮助查询的记录不能作为验证。验证可以在登记候选之前完成；模型在后续回合
核对其是否支持当前目标与材料后复用，不再把登记顺序当作有效性条件。这里只校验来源和结果，
答案含义与证据是否适用仍由模型判断。

引用失败时逐项返回真实原因，并附最近四条已读到且完整成功的实际回执，让模型检查并复用对应 ID；
不会要求为了获得新 ID 重复已有验证。重复提交同一个失败请求会触发引用复盘，仍由模型决定后续行动。
相同请求与相同失败、笔记未变化的往返也纳入历史折叠，避免大量失败提交在上下文中反复示范；
保留最新回执和全部原始历史，不封禁合法重试，不增加固定回合上限。
连续相同参数得到相同结果，或相同错误再次出现时，下一次请求使用 `revise_step`：模型先填写
原始 `requirement`、差距与调整依据 `adjustment`，再选择工具 `name` 和完整 `arguments`。
框架执行该选择，沿用原授权、沙箱和来源记录。工具用法不清楚仍可选择 `tool_lookup`；
有依据的原样重试也允许，模型的自述不被当作成功验证。不同实际结果不会仅因参数相同而触发该入口。
这是同一模型下一回合的请求契约变化，不额外派生代理或增加一个规划请求；中途用户原话仍保留在请求末尾。
最近一次行动复核写入工作黑板；取消中的复核保持待处理状态。
新执行结果的预览被截断时，回执直接提供 `output_read_call`，无需模型猜消息编号。

终态续聊中，模型通过 `request_execution` 成功提交执行目标后立即交接，不再额外等待一轮
对话模型回复。参数不合法时仍返回错误供模型修正；继续执行的目标仍由模型判断。
轻量 CTF/AWDP 续聊先由意图模型判断任务、规则或对话；继续任务时只提供交接工具，
原文回读留给执行者，避免退回普通模式的多轮记录查询。解释结果仍保留会话读取工具。
只有候选后端均为兼容 Chat Completions 的 llama.cpp 时，交接请求才使用 `tool_choice=required`；
Ollama 或混合候选使用 `auto`，避免协议拒绝。未返回有效交接时保留用户消息，不宣称已执行。

续聊产生新运行/任务 ID 时，轻量执行者从当前会话的工作黑板定位同题、同目标、同实例及同模型配置的
完整检查点，保留历史消息编号、证据笔记、分页位置和未完成候选，载入本轮用户目标与当前世界状态。
新目标不会沿用旧收尾标记；不同题目、模型或现场不接管旧对话。只恢复状态，不重放历史工具。
轻量续聊的纯文字回复也进入既有工具动作恢复，修复“只能口述计划、却持续等不到动作”的分支遗漏。
用户消息确认送达后，最近收到的原文仍保留在工具恢复请求及后续请求末尾，标记为已接收的当前约束，
不再次确认投递。新一轮续聊按新目标重新载入，避免已处理的旧消息覆盖当前要求。

## 验证边界

定向测试覆盖游标推进、重复请求不暗中跳页、搜索后的连续阅读、来源变化、旧消息中的预览与完整日志
区分、Unicode 输出预算、文件丢失/链接替换、实际沙箱 API/CLI 帮助及日志页的证据引用。
同时覆盖真实引用归一、空可选指纹、笔记无变化、重复错误复盘，以及续聊请求的立即交接和失败保留。
本轮累计通过 138 项相关测试，包括实际 bubblewrap 工具执行、本地 HTTP 的 LiteLLM/OpenAI SDK 往返、
Ollama 原生适配器请求和错误路径；后两者使用本地测试服务，不等同于真实模型推理。修改的 Python 文件
通过 ruff。本轮未跑全量回归。
