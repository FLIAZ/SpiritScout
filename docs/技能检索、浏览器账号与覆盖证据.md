# 技能检索、浏览器账号与覆盖证据

本批功能用于常规部署。轻量模式的模型调用、上下文压缩和执行流程不作调整；浏览器账号和覆盖页入口在轻量界面隐藏。

## Skill 的检索与分级

Skill 管理页和 Agent 的 `skill_search` 共用相关性检索：名称、描述、别名、标签、领域参与加权，支持中英文安全术语的同义匹配。例如“对象级越权”可以发现 IDOR/BOLA 参考。完整 Skill 标识精确命中优先，空查询仍可分页浏览。检索在本地完成，不调用嵌入模型或外部服务；这是词项与同义概念检索，不保证理解任意自然语言。

编辑 Skill 可设置以下分级，以及用逗号分隔的别名和标签；压缩包内 `SKILL.md` 的 frontmatter 也支持 `tier`、`aliases` 和 `tags`。

| 分级 | 值 | 用途 |
| --- | --- | --- |
| 核心技能 | `core` | 高频基础参考，优先出现在紧凑发现摘要中 |
| 领域技能 | `domain` | 按具体技术、任务和对象检索 |
| 参考资料 | `reference` | 规范、报告、对照资料等按需查询 |

分级不代表可信度或能力权限，所有启用技能均可检索。旧技能自动获得默认分级，不重写已有用户配置。发现摘要限制预览数量，并提供总数、分级计数和修订摘要；目录增至数千项也不会把所有正文塞进提示词。选中技能后仍需 `skill_open` / `skill_read` 读取实际内容。

## 浏览器账号

在侧栏“浏览器账号”中添加名称、身份说明和网站地址，可选择保存用户名、密码，以及 Cookie/localStorage 缓存。密码留空保留已有值，清除凭据需勾选对应选项；修改凭据会丢弃旧缓存，防止沿用原身份。页面和列表接口只返回脱敏提示、配置状态和缓存统计，不提供密码读取接口。

二次验证方式可选“无二次验证”“短信验证码”“邮箱验证码”“验证器动态码”。手机号或邮箱只作为接收位置提示保存，Agent 不会把它当成任意发送接口。验证码实际发送由 Agent 操作当前平台的发送按钮完成；验证器动态码由用户的手机 App 生成。

新任务页面不再提供账号选择，也不预加载账号列表或自动附带账号标识；打开“浏览器账号”管理页时才读取公开摘要。常规部署默认使用会话隔离、未登录的浏览器，Agent 应先判断任务是否确实依赖某种登录身份。遇到登录页、401/403 或已存账号本身，不构成申请理由；一般任务继续使用匿名方式。

只有特殊步骤确实需要账号时，Agent 才通过内置 Chrome 的 `account_request` 提交平台地址、必要性和现场依据。按规范化后的 HTTP(S) origin 精确匹配账号；存在多个账号时先返回名称及身份，由 Agent 选择相关账号后再申请。会话提示展示具体平台、账号名称、身份和理由，只有用户点击“仅本次使用此账号”才加载该站点登录态并提供隔离的账号浏览器。拒绝、取消、自由文本或停止等待均不授权；Agent 不应自动换账号重复申请。无人值守模式不提供此申请工具。

新申请仅在当前运行中有效，停止或重启后需重新确认；等待期间账号发生变化时旧确认失效。原有会话绑定及接口显式传入账号标识保持兼容。凭据不写入任务请求、共享黑板或 RAG，平台匹配和账号使用确认均不扩大测试授权范围。

Agent 在登录页面定位输入框后可调用对应账号的 `account_login`：服务端解密并直接填写，模型收到的是操作结果。平台登录态失效后，可再次使用这个工具登录，是否成功由 Agent 检查当前页面与实际身份。工具不会把缓存存在或填写成功解释为已经登录。

出现二次验证时，Agent 调用 `account_verify`，按需点击平台发送按钮，然后等待会话里的私密验证输入框。答复直接交给浏览器填写，不进入模型上下文、共享黑板或审计原文；不同挑战不会合并。用户可取消，失败不会自动重发验证码。无人值守的 competition 模式不会询问用户，需要二次验证时返回受阻；可提前在管理窗口完成登录并保存缓存。

需要手工扫码或登录时，使用“打开登录窗口”，完成后点击“保存登录态”。本机需有可用 Chrome 和桌面，远程环境沿用已有 `src-browser` 桌面访问方式。关闭管理窗口不会自动保存，避免误覆盖；任务使用过的账号在正常回收浏览器时尝试保存，失败会留下不含凭据的生命周期事件。

### 缓存与加密边界

- Cookie/localStorage 和账号凭据沿用资源库的 Fernet 加密，数据库为 `resources/catalog.db`，密钥为 `resources/catalog.key`。目录及密钥权限分别限制为 `0700`、`0600`（支持这些权限的平台）。这保护磁盘数据，不意味着主机或当前用户被控制后仍无法读取。备份须同时保护密钥和数据库，不要提交到 Git。
- 仅缓存声明网站的 Cookie 与 localStorage，不保存 sessionStorage、IndexedDB、浏览器密码库或完整用户配置。若登录依赖父域 Cookie 或单独的 SSO 站点，须明确加入对应父域或登录站点地址，不自动扩大保存范围。
- 缓存有效期为 1–365 天，不延长平台自身的 Cookie 或服务器会话寿命。过期缓存不会加载；可主动清除磁盘中的已保存缓存。关闭缓存开关也会清除已保存登录态，账号密码可独立保留。
- Linux 向 MCP 提供初始登录态时使用匿名内存文件；其他平台使用受限临时文件并在连接结束时删除。账号浏览器关闭代码回显，不加载外部 MCP 录制配置；登录工具只回传不含凭据的结果，后续文本快照也遮蔽已知凭据和验证码。网页本身及用户显式导出的浏览器内容仍须按敏感资料处理。
- 修改、清除或删除账号后，旧上下文不能继续操作或覆盖新缓存；需要重新打开管理窗口或启动新会话。同一账号同时被不同会话保存时，旧版本不会覆盖较新的缓存。这不会注销平台服务器上的会话。

## 覆盖与证据

会话内“覆盖与证据”按“资产/接口 × 实际身份 × 测试方向”列出探索记录。Agent 可在 `exploration_write` 中填写 `identity` 与 `test_type`；身份建议使用账号标识并注明角色，不能填写密码、Cookie 或验证码。旧记录没有这些字段时显示“未标注”，资产没有关联探索时显示“未见尝试”。

状态区分未见尝试、进行中、受阻、待验证、本次未复现、已独立确认。`supported` 或 `closed` 不会直接变成已确认。只有显式关联到独立复核通过的漏洞记录，且证据状态仍有效，才显示已独立确认；同资产的其他身份不会继承这个结论。不根据 URL、时间或邻近记录猜测关联。

展开记录可以检查原因、探索原文和证据引用。执行记录、黑板记录和工作区文件按已有证据机制定位；引用缺失、版本变化与私密记录分别提示，不把“可定位”当作证据已经证明结论。页面支持搜索、身份/方向/状态筛选和分页；超过读取窗口时明确显示截断，不计算暗示全覆盖的百分比。

覆盖接口为只读：`GET /api/sessions/{id}/coverage` 和 `/coverage/evidence?ref=...`，不修改规划、审批或黑板结论。

## 本批验证范围

定向回归涵盖检索与目录兼容、凭据加密及脱敏、Cookie 站点过滤、缓存过期、并发撤销、验证码隔离、探索字段及证据状态。真实固定版本 Playwright MCP 已在本地测试页验证同一 Chrome 的账号上下文隔离、Cookie/localStorage 恢复、关闭后重开、密码填写、拒绝向其他网站填写密码，以及验证码请求/答复/填写链路，未使用真实账号或付费模型。账号管理、Skill 筛选、覆盖证据及手机尺寸弹窗也经过实际浏览器交互验证。

当前环境无图形桌面，以上浏览器检查使用无头 Chrome；可见的人工登录窗口未实测。真实平台的短信、邮件投递、风控和登录有效期仍需在实际使用中验证。
