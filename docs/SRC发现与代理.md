# SRC 资产发现、脚本情报与代理池

代理池在控制台独立页面管理。可以粘贴 Clash/Mihomo 的内联节点 YAML，或添加
公网 HTTPS 订阅并手动刷新。节点、认证信息和订阅链接保存在资源库密文中；
列表接口不回显密码或订阅链接。手动导入拒绝远程 provider、脚本、TUN 和外部控制器；
订阅响应仅提取内联 `proxies`，忽略其他客户端配置，不加载远程 provider。
支持 HTTP/SOCKS5、SS、VMess、VLESS、Trojan、AnyTLS、Hysteria2 和 TUIC；VMess/VLESS/Trojan
的常见 WS、gRPC 与 TLS 参数可以从 URI 导入，其他自定义传输需用 YAML。
导入成功不代表节点可连接。

节点卡片提供「测延迟」「测网速」，工具栏可测试当前来源、搜索与协议筛选后可见
的节点。延迟通过临时 Mihomo 固定单节点出口，对 Cloudflare 测速端点发起三次
独立 HTTP 连接请求，取成功样本的中位数（ms）；包含代理协议握手、目标 TLS 与
响应时间，不使用本机到代理服务器的 TCP Ping 替代。失败显示请求失败或超时，
不伪造为 0 ms；端点不可达也会导致失败，因此这不是对所有网站可达性的保证。
下载测试实际下载最多 10 MB，以收到的字节数除以整个请求耗时展示 MB/s
（1 MB = 1,000,000 字节）。该数值是「下载源 → 节点 → 本机」完整代理链路的
端到端吞吐，不冒充无法从本机单独观测的「节点 → 下载源」分段带宽。下载超时但
收到至少 64 KiB 时保留部分采样结果并标注，不足时显示下载失败。批量测试会为
当前筛选出的所有节点同时启动独立 Mihomo 出口，支持逐卡查看状态和停止。
测试记录含时间，刷新页面保留；仅重测延迟时保留此前网速及其单独测试时间。
节点配置或凭据变化后旧结果失效。测试使用独立进程与配置，不修改运行中会话。

代理页左侧按订阅来源分组，右侧支持节点名称/服务器搜索及协议筛选；导入配置和
添加订阅通过弹窗完成，固定方案单独展示。订阅来源提供「更新配置」按钮，会重新
从远端获取节点并更新节点列表。若响应包含 Clash 生态的 `subscription-userinfo`
响应头，页面显示已用、剩余、总流量和到期时间；服务商未提供该响应头时明确显示
额度未知，不从节点名称猜测。订阅使用 Mihomo 格式请求；流量、到期
或客户端兼容提示若指向本机回环地址，会单独归入不可选的「订阅提示」。只返回这类
提示的刷新会报错并保留原有节点，不把提示条目作为出口。刷新下架的节点若仍被方案
引用，会移入「历史保留」，已有方案不静默改用其他节点。节点保留服务商声明的
`skip-cert-verify` 设置，关闭 TLS 校验时卡片会明确标注，不能将其误认为已验证出口。

页面独立实现，只参考通用的订阅分组与节点网格交互，没有复制 Clash Verge Rev 的
源码、图标或品牌素材。Clash Verge Rev 当前使用
[GPL-3.0](https://github.com/clash-verge-rev/clash-verge-rev/blob/dev/LICENSE)，本项目使用
Apache-2.0；复制并分发形成的派生代码需要遵循 GPL 相应义务，不能仅保留本项目许可。
参见 [GNU 兼容性说明](https://www.gnu.org/licenses/gpl-faq.en.html#v3Compatible)。

选择节点的先后顺序就是链路顺序，最后一个节点是目标出口。创建固定方案后，
在新建 SRC 任务时选择它。会话保存独立的加密快照，后续刷新订阅或修改代理池
不会替换这个快照。HTTP/SOCKS5 单节点使用本机录制网关；其他协议及多跳需要
本机安装 Mihomo，通过 `dialer-proxy` 连接固定链路。开工前通过网关访问
`https://api.ipify.org?format=json` 核实公网出口并保存 IP，续传时出口变化会拒绝开工。
这不是对供应商 IP 永不变化的保证；页面状态标明的是开工时的验证结果。

原生 Linux 可运行 `.venv/bin/python scripts/setup-mihomo.py`，优先将本机 Mihomo 或
Clash Verge 内核复制到项目 `.tools/mihomo`；没有现有内核时，从 MetaCubeX 官方发布
下载匹配架构的内核并核对发布资产 SHA-256。也可用 `--version v1.19.33` 指定官方下载
版本；此脚本仅准备代理运行时，不启动任务或系统代理。
代理页与会话使用同一个查找函数：优先使用 `SPIRITSCOUT_MIHOMO` 指定的可执行文件，
其次使用项目 `.tools/mihomo`，最后查询 `PATH` 中的 `mihomo` 或 `verge-mihomo`。
显式路径无效时不回退到其他内核。
下载、校验或启动检查失败时保留原有内核；二进制不进入 Git。

当前内置 HTTP、JS 抓取和发现基线接入会话代理，内置 DNS 在代理模式下经 DoH
请求解析；代理失效不会自动回退直连。原始 TCP 扫描尚不支持此出口，会返回明确错误。
后台本地命令、沙箱和本地 stdio MCP 在独立网络命名空间内运行，经私有 Unix
socket 桥接到录制网关。普通直连 IP 网络不可达；遵守代理的工具仍能请求目标。
浏览器通过隔离进程启动会话独立实例，使用相同网关，不复用可直连的共享 CDP。
远程 HTTP/SSE MCP 的上游连接经过代理，但无法证明其服务端的下游出口；工具
目录保留，代理会话中的未验证远程调用返回明确错误。应改用可隔离的本地 stdio 服务。
网络命名空间约束 IP 网络，不将其表述为对所有恶意本机 IPC 绕行的完整防御。
用户消息和模型请求使用现有控制面连接，不默认复用目标代理。

扫描者支持 `asset_discover` 派遣：DNS 记录、被动证书子域发现及 URL 的 HTTP
基线并行执行，不依赖 Nuclei。主控结合用户规则显式派遣后与其他工作并行，
不会在用户禁止扫描时自行开始，主控的首轮提示明确提供只读基线派遣方式。
仅同时符合会话明确范围和本次派遣范围的发现进入资产层。精确域名不授权子域，
通配域名才允许子域产出；URL 按同 origin 的路径边界匹配。解析 IP、外部 DNS
记录仅作为证据，不自动成为独立扫描目标。CNAME 与 HTTP 头可产生 CDN/WAF
候选特征，标记为未验证，不将其等同于防护能力，不自动探测源站。

SRC 新增 `JS-REVERSE` 战术和 `js_reverse` 角色，读取授权内页面关联脚本，
将脚本 URL、哈希、静态接口线索、source map 引用和敏感常量引用写入 `js_intel`。
授权内 source map 的内联源码也可分析，但不按照其中任意 sources 路径继续联网。
原脚本加密保存，其他角色可用 `js_source_read` 按 `script_ref` 分页读取脱敏源码。
启用模型规划时，角色对脱敏脚本归纳算法流程、假设与缺口；算法调用的静态线索
与模型解释分开保存。不执行不可信 JS。敏感常量识别是启发式匹配，不保证发现
所有秘密，也不代表凭据有效。
范围外脚本不抓取。

秘密保存在会话的 `private-secrets` 加密库中，黑板仅保留 `secret_ref`、类型和指纹。
后续内置 `http_probe` 可使用 `secret_headers: {"Authorization": "secret-引用"}`，
需要 Bearer 前缀时可用 `{"Authorization": {"secret_ref": "secret-引用", "prefix": "Bearer "}}`。
执行时核对当前授权和来源 origin 后注入；该请求不自动跟随重定向。不要将秘密
明文复制到模型参数、普通报告或审计。`secret_cookies` 和 `secret_params` 分别支持
Cookie 名、查询参数名到引用的映射，已知秘密在响应预览、源码副本和普通流量
索引中继续替换为引用。录制代理的私有取证原文仍遵循原有显式读取契约。
Web 会话的「JS 情报」页独立展示结果，用户可显式查看秘密明文；该操作记录引用
审计，关闭弹窗或切换会话后清除明文显示。
