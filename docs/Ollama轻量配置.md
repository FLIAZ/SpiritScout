# Ollama 轻量配置

面向 16GB 系统内存、8GB 显存的独立部署，基于本机已下载的 `qwen3.5:9b`。
它不替换 `configs/system.yaml`、正常模型注册表或原始 Qwen 模型。

## 初始化与启动

在仓库根目录执行：

```bash
./launch.sh start --offline
```

首次启动在缺少轻量配置时自动调用 `scripts/setup_ollama_light.py`；已有配置直接复用。
需提前准备 `.venv`、项目依赖、正在运行的 Ollama 和本机 `qwen3.5:9b` 权重。
启动脚本不安装依赖、不下载模型，也不会重启 Ollama。可用 `--port 8101` 覆盖监听端口。

```bash
./launch.sh stop --offline
./launch.sh restart --offline
```

停止与重启默认定位轻量端口 8001，检查 `.spiritscout-ollama/` 中的运行中会话；
有活跃会话时拒绝停止，显式 `--force` 才放弃现场。自定义端口时同步指定，例如
`./launch.sh stop 8101 --offline`。普通 `./launch.sh` 仍启动正常配置。

如需自定义 Ollama 地址或提前初始化，也可单独运行
`.venv/bin/python scripts/setup_ollama_light.py --base-url <Ollama地址>`；
原有 `bash scripts/run_ollama_light.sh` 入口继续可用。

初始化会创建 `spiritscout-qwen35-9b-light:latest` 别名与
`.spiritscout-ollama/` 下的独立系统、模型和指派配置。已存在的配置不会覆盖。
轻量控制台默认使用 `127.0.0.1:8001`；正常模式仍使用原配置和端口。
不要同时让两个部署及其他 Ollama 任务争用同一张 GPU。

模型不在本机时，初始化会报错，不会自动联网下载。Ollama 地址可通过
`setup_ollama_light.py --base-url` 指定。

## 模型参数

| 参数 | 轻量默认值 |
| --- | --- |
| 基础模型 | `qwen3.5:9b`，沿用现有 Q4_K_M 权重 |
| 实际与登记上下文 | 16384 |
| temperature | 0.3 |
| top_p / top_k | 0.9 / 20 |
| repeat_penalty / presence_penalty | 1.05 / 0.0 |
| num_thread | 8 |
| 默认思考 | 关闭 |
| 驻留时间 | 30 分钟 |
| 输出上限 | 4096；调用点的显式参数仍优先 |

默认关闭思考以减少常规调用等待。模型的 `low/high` 分别对应关闭/开启
Ollama 原生思考，复杂任务可由已有派发决策选用 high。不会通过字符串提示词
模拟思考开关，也不会改变原模型权重或给模型写固定题型解法。

参数以请求级 `options` 发到 `/api/chat`，不需要假的 OpenAI API Key。
上下文减小不保证必然全 GPU；需在无其他任务时检查实际 CPU/GPU 分担与正确率。

## 与正常配置的区别

- Ollama 原生 JSON/NDJSON 协议，保留工具调用、思考字段和用量；不经过 OpenAI SDK 的隐式重试。
- 同一 Ollama 推理资源共享一个异步槽，不同 Agent 仍可维护任务与并行执行工具。
- 一个持久执行者、一条持续工具循环；不运行主控规划、督导、专项派遣或独立验证队列。同一会话的多题由同一执行者顺序处理，方法仍由模型按证据选择。
- 轻量执行使用紧凑角色与任务契约，实际工具以调用目录为准；授权和用户规则仍完整保留。
- 自动会话命名、秘书咨询、自动经验提炼关闭；既有经验仍可读取。
- 不额外自动抽取平台档案。需要托管平台时显式提供档案，不按关键词猜解题流程。
- 保留本地报告生成与消息附件能力；轻量报告不额外调用另一个模型，不添加固定回合上限或预算熔断。
- 公网检索关闭、本地 hash 知识检索；MCP 默认不启用，按需配置已准备好的本机服务。

此配置仅改变灵枢部署，不修改正在运行的 Ollama 服务环境。若要设置
`OLLAMA_NO_CLOUD`、Flash Attention 或 KV cache 类型，应先停止其他推理任务，
针对安装版本验证后再重启 Ollama。离线比赛前仍需断公网演练、准备依赖和工具；
空 MCP 列表不代表 IDA、浏览器等服务已经配置完成。

## 补偿启用边界

专属提示、历史整理、输出限幅、持久 `/tmp` 和额外传输重试，只有以下条件
**同时满足**才启用：独立部署 `gateway.lightweight_local: true`；当前会话为
CTF 或 AWDP；本次运行所有候选（包含备份）均为原生 `provider: ollama`，且各模型
显式配置 `ollama_lightweight: true`。切换到云端、混合候选或未标记模型时保守关闭；
正常部署、SRC 与智能体模式不启用这些补偿。只改编队显示名称不能启用补偿。

旧轻量配置不会被初始化脚本覆盖，需在其 `.spiritscout-ollama/models.yaml` 的
目标模型条目补上 `ollama_lightweight: true`。配置在新运行时生效；不要中断运行中的
任务来重载。工具开关随每次调用传递，不使用进程全局变量，模型参数不能覆盖它。

轻量 `/tmp` 在本题内持久、不同题目隔离，宿主 backing 位于不可见的控制目录；
普通调用仍使用每次新建的 tmpfs。工作目录和挂载身份拒绝符号链接并固定目录描述符。
重复完整命令仅附提示、仍真实执行，不按命令前缀硬阻断或回放可能过期的结果。
无工具回复恢复保留当前可用工具目录，由模型选择动作，不强制改成 shell。

长会话发送视图按完整 assistant/tool 往返归档较早历史，原始消息和代码不改写。
单执行者先感知当前沙箱的可用命令，工具仍按需选择，不把探测当附件分析。
当前授权、用户原话、规则和世界状态保留；近期往返优先完整保留，预算不足时也可
按完整配对归档最近往返，而不是因此放弃调查。真正无法容纳的保护契约报告为失败/
阻塞，不记录成任务完成，也不派另一个执行者重新开始。旧指令编号与回执保留，
重复正文合并，窗口紧张时较早模型指令只展示明确标注的摘要。历史索引同时展示早期
与近期已执行动作和输出片段，避免只剩路径而无法判断做过什么。即使命令不同，若
实际退出码与 stdout/stderr 完全相同，也会提供重复结果的事实提醒，仍不阻断必要对照。
`history_read` 可按
`message_index` 或本题当前 `instruction_id` 分页读取原文。普通调用和恢复调用都
重新校验输入预算；保护契约本身无法容纳时报告上下文阻塞，不向端点发送超窗请求，
也不把它判断为赛题无解。这是单次请求容量检查，不是任务回合或 Token 总量熔断。

单执行者不启动主控督导。`steering_feedback`、黑板读取与技能搜索/打开/读取入口
保留作兼容，但不会不断生成新的自动指令。新用户消息及附件直接并入当前执行者，
在下一工具回合处理；暂停时不另起模型回答。技能目录按需查询，不再每次灌入通用目录。
单执行者使用编队的 `ctf_misc` 模型绑定；这是内部角色键，不是自动题型分类。
界面以“单执行者”标识身份，单独显示用户给定的方向提示（例如 Reverse）；方向不锁死工具或方法。
需要 MCP 时须将其能力授权给该角色。

公开正文随实际模型文本流展示，本地答案模式不再过滤单执行者的正文；已经流式展示的文本
不会重复追加同内容的进展事件。模型没输出正文时不编造分析。

所有工具的重复空查询、重复失败与相同观察结果均纳入单执行者的证据复盘。复盘替换下一回合
的发送视图，以原始用户目标、授权、近期实际结果和未验证判断重新选择动作，不另起代理、
不额外增加规划调用，也不硬封禁合法重试。成功写入可能没有输出，不据此认定没有推进。

`binary_inspect` 是仅单执行者提供的静态读取接口，在现有 bwrap 沙箱内调用已安装的 r2，
不会执行附件程序。模型自行选择 info/functions/strings/xrefs/disasm；参数引用真实文件和地址，
不提供固定题解。工具保持 JSON 完整，返回分页游标；较大的 limit 请求按展示窗口自动分页，
不把期望读取更多记录当成接口故障。反汇编保留真实函数身份、符号化指令及跳转信息。
证据复盘保存早期实际观察，发送时压缩重复字段，但保留二进制名称、地址和分页状态，
原始参数及结果仍可按引用读回。

轻量 shell 启用 `pipefail`，中间命令失败不再被管道末尾的成功退出码遮蔽。
工具额外记录管道各段状态：上游仅出现 SIGPIPE（141）、末端成功且有输出时，展示为
“已获得部分输出”，不当成完整成功或基础设施故障。直接退出 141、缺少管道状态、
真实非零失败等不会被统一忽略；仍须核对 stderr 与输出完整性。
模型环境事实明确区分只读附件目录、可写工作目录与 artifacts，不自动改写命令或放宽权限。

## AWDP 修补提交

轻量控制台提供 CTF 与 AWDP（fix）。AWDP 以修补提交件为目标，不用 Flag 登记接口。
当前提交格式为真实 gzip 压缩的 tar 归档，例如 `tar czf fix.tar.gz attachment/app.rb`；
**这不是所有比赛的统一规则**，现场平台另有要求时须以其规则为准。

归档只含被修改文件，其内部相对路径必须与原始附件完全一致。`submit_fix` 接受
`archive`、字符串数组 `files` 与 `description`，检查 gzip/tar、原始路径、清单与
实际内容、字节变化，并拒绝跨题路径、目录穿越、链接和特殊文件。提交件快照验证后
复制到会话 `artifacts/`，界面提供下载；不覆盖已有产物。

归档校验与登记**不能证明漏洞已经修复**，也不是比赛平台接收回执。应提供正常功能
与漏洞回归的实际测试证据；只做语法检查不够。无法完成时如实记录缺口。

## 诊断

审计可记录 `queue_duration_ms`、`load_duration_ms`、`prompt_eval_duration_ms`、
`eval_duration_ms` 和 `eval_tokens_per_second`。总等待时间不等于纯生成耗时，
不能把客户端前缀重复字节计作服务端真实缓存命中。

性能基准必须在没有其他 Ollama 任务争用模型、显存和推理槽时进行。
