# 本地轻量配置：Ollama / llama.cpp

面向 16GB 系统内存、8GB 显存的独立部署，基于本机已下载的 `qwen3.5:9b`。
它不替换 `configs/system.yaml`、正常模型注册表或原始 Qwen 模型。

Ollama 与 llama.cpp 统一从 `--offline` 启动，共用 `.spiritscout-ollama/` 中的配置与会话；
目录沿用旧名，后端由 `models.yaml` 与模型指派决定。Windows Docker 部署见
[Windows 轻量测试](Windows轻量测试.md)。

## 初始化与启动

在仓库根目录执行：

```bash
./launch.sh start --offline
```

首次启动在缺少轻量配置时自动调用 `scripts/setup_ollama_light.py`；已有配置直接复用。
这条默认初始化路径需提前准备 `.venv`、项目依赖、正在运行的 Ollama 和本机
`qwen3.5:9b` 权重。若使用 llama.cpp，先用已有模型初始化，再从同一入口启动：

```bash
.venv/bin/python scripts/setup_local_light.py --backend llama_cpp --model qwen35-9b --context 16384
./launch.sh start --offline
```

模型名、地址与上下文需对应已运行的 llama-server；可用 `--base-url` 指定地址。
已有轻量配置时，初始化脚本不会覆盖文件；切换后端请修改同目录的 `models.yaml`
与模型指派，保留 `system.yaml` 的工作区路径。启动脚本不安装依赖、不下载模型，
也不启停推理服务。可用 `--port 8101` 覆盖控制台监听端口。

```bash
./launch.sh stop --offline
./launch.sh restart --offline
```

停止与重启默认定位轻量端口 8001，检查 `.spiritscout-ollama/` 中的运行中会话；
有活跃会话时拒绝停止，显式 `--force` 才放弃现场。自定义端口时同步指定，例如
`./launch.sh stop 8101 --offline`。普通 `./launch.sh` 仍启动正常配置。

如需自定义 Ollama 地址或提前初始化，也可单独运行
`.venv/bin/python scripts/setup_ollama_light.py --base-url <Ollama地址>`；
启动、停止和重启统一使用 `./launch.sh … --offline`。

默认 Ollama 初始化会创建 `spiritscout-qwen35-9b-light:latest` 别名与
`.spiritscout-ollama/` 下的独立系统、模型和指派配置。已存在的配置不会覆盖。
轻量控制台默认使用 `127.0.0.1:8001`；正常模式仍使用原配置和端口。
不要同时让两个部署及其他 Ollama 任务争用同一张 GPU。

模型不在本机时，初始化会报错，不会自动联网下载。Ollama 地址可通过
`setup_ollama_light.py --base-url` 指定。

## 模型参数

| 参数 | 轻量默认值 |
| --- | --- |
| 基础模型 | `qwen3.5:9b`，沿用现有 Q4_K_M 权重 |
| 实际与登记上下文 | 16384 |
| temperature | 0.3 |
| top_p / top_k | 0.9 / 20 |
| repeat_penalty / presence_penalty | 1.05 / 0.0 |
| num_thread | 8 |
| 默认思考 | 关闭 |
| 驻留时间 | 30 分钟 |
| 输出上限 | 4096；调用点的显式参数仍优先 |

默认关闭思考以减少常规调用等待。模型的 `low/high` 分别对应关闭/开启
Ollama 原生思考，复杂任务可由已有派发决策选用 high。不会通过字符串提示词
模拟思考开关，也不会改变原模型权重或给模型写固定题型解法。

参数以请求级 `options` 发到 `/api/chat`，不需要假的 OpenAI API Key。
上下文减小不保证必然全 GPU；需在无其他任务时检查实际 CPU/GPU 分担与正确率。

## 与正常配置的区别

- Ollama 原生 JSON/NDJSON 协议，保留工具调用、思考字段和用量；不经过 OpenAI SDK 的隐式重试。
- 同一 Ollama 推理资源共享一个异步槽，不同 Agent 仍可维护任务与并行执行工具。
- 一个持久执行者、一条持续工具循环；不运行主控规划、督导、专项派遣或独立验证队列。同一会话的多题由同一执行者顺序处理，方法仍由模型按证据选择。
- 轻量执行使用紧凑角色与任务契约，实际工具以调用目录为准；授权和用户规则仍完整保留。
- 自动会话命名、秘书咨询、自动经验提炼关闭；既有经验仍可读取。
- 不额外自动抽取平台档案。需要托管平台时显式提供档案，不按关键词猜解题流程。
- 保留本地报告生成与消息附件能力；轻量报告不额外调用另一个模型，不添加固定回合上限或预算熔断。
- 公网检索关闭、本地 hash 知识检索；MCP 默认不启用，按需配置已准备好的本机服务。

此配置仅改变灵枢部署，不修改正在运行的 Ollama 服务环境。若要设置
`OLLAMA_NO_CLOUD`、Flash Attention 或 KV cache 类型，应先停止其他推理任务，
针对安装版本验证后再重启 Ollama。离线比赛前仍需断公网演练、准备依赖和工具；
空 MCP 列表不代表 IDA、浏览器等服务已经配置完成。

## 补偿启用边界

专属提示、历史整理、输出限幅、持久 `/tmp` 和额外传输重试，只有以下条件
**同时满足**才启用：独立部署 `gateway.lightweight_local: true`；当前会话为
CTF 或 AWDP；本次运行所有候选（包含备份）均为显式授权的本地模型：原生
`provider: ollama` 加 `ollama_lightweight: true`，或 OpenAI Chat Completions 端点加
`local_runtime: llama_cpp` 与 `local_lightweight: true`。切换到云端、含未标记候选时保守关闭；
正常部署、SRC 与智能体模式不启用这些补偿。只改编队显示名称不能启用补偿。

旧轻量配置不会被初始化脚本覆盖，需在其 `.spiritscout-ollama/models.yaml` 的
目标模型条目补上 `ollama_lightweight: true`。配置在新运行时生效；不要中断运行中的
任务来重载。工具开关随每次调用传递，不使用进程全局变量，模型参数不能覆盖它。

轻量 `/tmp` 在本题内持久、不同题目隔离，宿主 backing 位于不可见的控制目录；
普通调用仍使用每次新建的 tmpfs。工作目录和挂载身份拒绝符号链接并固定目录描述符。
初始任务的 `execution_environment.default_workdir` 给出当前题的具体可写目录，shell/python
默认已位于此处；会话根目录仅用于定位附件和产物，本身只读。每次调用新建进程，
`cd`、shell/Python 变量不会跨调用继承，文件仍持久保留。旧检查点在发送视图补充当前路径，
不改写历史或自动重写命令；证据复盘也保留这些事实。
重复完整命令仅附提示、仍真实执行，不按命令前缀硬阻断或回放可能过期的结果。
无工具回复恢复保留当前可用工具目录，由模型选择动作；收到后续工具结果后，过期提醒退出发送视图。
连续纯文本、空回复或恢复失败均不作为任务结束信号；继续调查须实际调用工具，
完成目标须按答案/补丁契约登记，无法继续须显式调用 `finish_challenge(complete=false)` 说明缺口。
恢复调用未取得工具时的正文也保留在原始历史中，避免回读遗漏模型实际说过的内容。

单执行者每轮只携带常用工具的参数声明；HTTP、MCP、流量、后台任务、CVE、技能读取和
CyberChef 等能力通过 `tool_lookup(name)` 按需读取完整契约，再用
`tool_invoke(name, arguments)` 调用。`tool_lookup()` 可列出当前目录，所有工具继续
走原执行、授权和审计通道，不按题型裁掉能力。窗口紧张时进一步将常用工具转为按需
入口，把空间留给完整用户要求；普通调用、无工具回复恢复和证据复盘使用同一预算口径。

`view_image` 在常用和最小工具集合中直接可见，将真实图片发送给当前角色模型，
用于附件、截图的视觉观察；Python 仍用于需要的像素统计、解码等计算。模型和服务必须
实际支持视觉输入，文件路径或文件元数据不代表已经看图；失败会保留原图快照并返回原因。

本地知识、技能与 CVE 情报沿用正常部署的资源，无需为轻量会话复制整库或将正文塞进
系统提示。`cve_lookup` 可查询已观察产品/版本或 CVE，`action=status` 检查收录状态；
合格轻量 CTF/AWDP 会话只读本地记录及已有缓存，即使全局 CVE 配置允许联网也不触发
在线补全。收录规模、关键词命中和版本横幅都不是漏洞已成立的证据，仍需现场验证。

长会话发送视图按完整 assistant/tool 往返归档较早历史，原始消息和代码不改写。
请求与可验证结果均相同的较早往返即使未达到窗口阈值也会折叠，只保留最新完整往返和重复计数，
避免旧助手分析反复占据上下文。AWDP 修补会话连续使用相同参数时，即使时间戳等输出变化也提示行动复核；
最近两次不同结果保留全文，较早往返按原始编号归档并明确标记结果可能不同，不把正常轮询判成失败。
窗口紧张时再归档较早的不同观察，为近期证据留位；
仍真实执行每次调用，不使用有损预览相同来认定结果相同，也不拆分并发工具批次。
单执行者以输入预算的 80% 为软整理阈值，先为当前笔记与工具原文留位，再用剩余空间补历史目录，
在硬预算内为最近两个完整工具往返留位，不为达到软阈值丢弃可容纳的证据。重复出现的长任务原文仅在逐字相同
时改成视图内引用，保留一份完整正文及所有声明编号、顺序和不同的授权边界。
旧技能正文及 MCP 查询结果也可成对归档；技能是否仍在上下文以本次实际发送视图为准，
已归档资料可以重新打开，不会误报“已经提供”。每次投影缓存逐消息计量，减少长历史
重复序列化；不新增摘要模型调用。单执行者使用与普通模式相同的公开探索约定：开始新意图、
改变验证方法或更新结论时，在当前公开说明中声明 `intent`、`attempt`、`state` 和转向原因；
有实际依据的发现、突破或方向变化才声明 `milestone`，普通执行继续归入已有尝试。
旧会话在下一回合补充同一约定，不改写历史，也不额外调用绘图模型。
轻量请求末尾另带简短格式提醒，每轮用同一公开 JSON 结构更新当前意图和尝试，避免小模型在长历史中
退回纯文本而遗漏黑板更新；普通执行沿用已有节点，不按回合制造里程碑。提醒只进入发送视图，途中用户原话仍放在最后。
初次感知摘要和后台通知也可归档。历史目录保留工具返回的函数身份、缩略查询条件和各页原始结果编号；
未展示的条目用 `history_read(view="index", find="原文片段")` 在完整工具参数及结果中检索，
再按命中的 `message_index` 用 `view="content"` 回读。检索覆盖未展示的中段，支持分页，
不把历史回读或笔记再次当作独立来源；旧检查点也可直接使用，原始编号不变。

`evidence_memory` 由模型按需保存事实判断（fact）、待验证假设或缺口（hypothesis）、
已排除路径（rejected）；`read` 获取当前修订，`update` 携带 `base_revision` 更新或删除条目。
事实判断与排除路径须引用原始工具结果编号和逐字原文，拒绝虚构引用、助手正文和笔记自证。
最新笔记在归档与检查点恢复后持续可见，旧笔记往返可归档，来源内容变化会标为 stale；
matched 只表示引用匹配，不证明模型判断正确或现场仍有效。容量不足或与用户契约无法共存时，
更新失败并保留原修订，由模型合并或缩短笔记，不静默删除。记录笔记不是完成任务的前置流程。
即使模型没有调用笔记工具，运行时也会从真实工具回执生成紧凑工作黑板，保留早期与近期的不同观察、
原文编号、重复计数及工具实际返回的分页位置；空笔记与观察目录分别展示，不自动生成假设或已排除结论。
早期观察优先保留成功回执，最近失败照常保留，避免最初的路径错误挤掉后来实际可用的读取方式；
未展示的观察仍可通过历史目录回读。
工作黑板随对话检查点恢复，并在 topology 层以 `working-memory:<task_id>:<route_id>` 保存当前快照；
它是工具观察与模型笔记的目录，不能作为独立验证或替代完整原文。
模型明确声明的意图和尝试另存为现有探索节点，同题同路线的稳定标题更新同一记录，
失败、阻塞和排除原因持续保留；只有明确且归属唯一的 `from` 才建立转向关联。
最新探索状态和关键发现会回读到工作黑板，后续回合可沿用。`graph_read`、`exploration_write`、
`blackboard_write` 和 `asset_link` 通过按需工具入口提供；有依据的事实可用 `exploration_refs`
关联产生它的尝试。模型声明的 supported、里程碑或路径关闭都不会自动升级为已验证事实。

单执行者先感知当前沙箱的可用命令，工具仍按需选择，不把探测当附件分析。
ZIP 附件会额外给出有限目录和小文本预览，帮助模型看见原始说明与数据的关系；不自动
执行或解码文件，不按文件名认定题面。预览标明来源与截断状态，原文按需读取。
当前授权、用户原话、规则和世界状态保留；近期往返优先完整保留，预算不足时也可
按完整配对归档最近往返，而不是因此放弃调查。真正无法容纳的保护契约报告为失败/
阻塞，不记录成任务完成，也不派另一个执行者重新开始。旧指令编号与回执保留，
重复正文合并，窗口紧张时较早模型指令只展示明确标注的摘要。历史索引同时展示早期
与近期已执行动作和输出片段，避免只剩路径而无法判断做过什么。即使命令不同，若
实际退出码与 stdout/stderr 完全相同，也会提供重复结果的事实提醒，仍不阻断必要对照。
输出相同比较使用完整捕获的 stdout/stderr 原始字节摘要，避免不同二进制字节解码成相同
替换字符、或未展示的中段变化被误判为相同。工具记录各流的字节数、捕获完整性、
UTF-8 有损状态与预览截断；含 NUL 的轻量输出显示有限十六进制预览，原始日志仍按
引用回读。旧记录缺少原始摘要时只说明展示预览相同，不宣称完整输出一致。
复盘分别保留 stdout 与 stderr 的首尾预览及输出日志引用；截断、有损、超时或捕获不完整
的回执标为部分结果，不能作为完整成功验证。历史引用指向实际工具结果，并发结果分别编号；
旧检查点只有能够确定配对关系时才补正引用，归档索引另外列出结果消息编号。
`history_read` 可按
`message_index` 或本题当前 `instruction_id` 分页读取原文，分页 JSON 不再二次截断。普通调用和恢复调用都
重新校验输入预算；保护契约本身无法容纳时报告上下文阻塞，不向端点发送超窗请求，
也不把它判断为赛题无解。这是单次请求容量检查，不是任务回合或 Token 总量熔断。

单执行者不启动主控督导。`steering_feedback`、黑板读取与技能搜索/打开/读取入口
保留作兼容，但不会不断生成新的自动指令。用户原话、授权与规则在轻量请求中直接提供正文，
不要求模型另行发现并读取黑板引用。新用户消息及附件在下一工具回合并入当前执行者，原话放在请求末尾；
当前模型或工具调用仍按原执行边界完成，不强行取消。模型请求成功返回后才记录 `user.feed_delivered`，
事件包含消息编号与回合；这表示请求已携带原文，不表示模型已正确理解或执行。
失败、取消或上下文超窗时消息保持待处理，调用期间到达的新消息留给下一回合。暂停时不另起模型回答。
技能目录按需查询，不再每次灌入通用目录。
单执行者使用编队的 `ctf_misc` 模型绑定；这是内部角色键，不是自动题型分类。
界面以“灵枢”（英文 SpiritScout）标识身份，单独显示用户给定的方向提示（例如 Reverse）；方向不锁死工具或方法。
需要 MCP 时须将其能力授权给该角色。

公开正文随实际模型文本流展示，流结束后仍保存完整公开进展事件，供探索图和刷新后回放；
界面把事件的语义信息补入同一消息，不重复展示流式正文。结构化正文只显示公开说明，
探索链路复用普通模式的意图、尝试、关键进展和事实关系；工具回合保留在尝试详情中。
模型没有明确声明关系的旧日志不补造意图或因果，已有执行记录仍可查看。

所有工具的重复空查询、重复失败与相同观察结果均纳入单执行者的证据复盘。复盘从完整历史生成下一回合
的发送视图，以原始用户目标、授权、近期实际结果和未验证判断重新选择动作，不另起代理、
不额外增加规划调用，也不硬封禁合法重试。成功写入可能没有输出，不据此认定没有推进。
相同参数连续得到相同结果，或相同错误持续返回时，下一回合加入行动复核提示，保留真实工具及完整参数：
模型对照原始要求、实际差距和调整依据，自主选择动作，直接走原执行与授权链路。
不再用只有泛型参数的 `revise_step` 包装器替换工具目录；旧会话中的合法包装调用仍兼容，
不存在的工具名会返回真实目录入口。可以查询用法、换输入、读取原文或有依据重试。
不额外调用另一个规划模型，不以重复次数直接判定失败或终止调查。
行动复核及实际执行来源保留在审计和工作黑板，选择动作的说明本身不算新证据。
连续使用相同工具参数但返回变化时也提供复盘提醒，明确区分参数重复与结果重复；
日志数量或时间变化不能让重复调用失去可见性，不同结果仍按不同观察保留。
复盘对相同观察去重，对结构化大页保留函数身份、地址、页范围和续读游标，减少重复正文
挤掉其他证据；索引与模型说法都不代表独立验证，实际结果仍须回读核对。
复盘保留预算内的跨文件证据、后续用户要求与技能引用，先为最近完整工具往返留位，再缩减
复盘摘要；只有完整结果确实无法容纳时才退回引用，文本摘要同时保留首尾。最新世界状态和
当前指令在短请求中也会进入发送视图。`binary_inspect` 信息查询没有
识别到二进制结构时明确返回失败与空观察，文件存在或全空字段不视为解析成功。

轻量单执行者的 `record_answer` 首次调用暂存候选，不立即完成；同一执行者在后续正常
回合核对原始题面/附件说明、完整推导与实际验证后，携带 `review.requirements`、
`review.derivation`、`review.validation` 和 `review.validation_evidence_refs` 再登记。
验证引用必须来自实际执行、成功返回且已读到结果的完整工具记录；登记候选之前完成的验证也可复用，
由模型核对是否仍适用于当前目标与材料，不因 API 调用顺序要求重跑。失败或仅有部分输出的检查、
仅帮助查询、同回合未读结果及虚构编号均不接受；文字声称“符合格式”不能代替
工具验证。待复核候选不能通过 `finish_challenge` 直接完成。发现缺口时继续调查或更换候选。
待复核状态继续保留重复结果复盘；发送视图保留再次登记所需的复核字段和真实验证引用要求，
避免旧工具说明归档后只剩反复核对的提示。成功检查后是否登记仍由模型结合具体缺口判断。
模型仍负责判断答案，不使用后端格式正则或固定解码链判题；本地复核没有平台判对回执，
不能保证小模型不会误判。单答案在复核登记后完成，多答案仍逐个登记后确认覆盖。
相同请求、相同失败或笔记未变化的历史往返会折叠，最新回执仍可见；原始历史与审计保留，
不同参数或不同结果不会混为同一次失败。引用错误逐项说明原因，不只返回一个空的可用引用列表。
工作黑板同时展示原始消息编号和执行 ID；验证引用也接受能唯一映射到实际执行的消息编号，
回读页、未知编号或未通过完整性检查的记录不会因此成为有效验证。

上述历史与参考资料管理借鉴了 [Qwen-Agent 的整轮裁剪](https://github.com/QwenLM/Qwen-Agent/blob/main/qwen_agent/llm/base.py)、
[Goose 的提前整理](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/sessions/smart-context-management.md)
和 [OpenHands SDK 的原始事件与发送视图区分](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/context/condenser/README.md)。
这里只接入适合现有执行循环的机制，不引入整套代理框架，也不截断唯一用户契约。

`binary_inspect` 是仅单执行者提供的静态读取接口，在现有 bwrap 沙箱内调用已安装的 r2，
不会执行附件程序。模型自行选择 info/functions/strings/xrefs/disasm；参数引用真实文件和地址，
不提供固定题解。工具保持 JSON 完整，返回分页游标；较大的 limit 请求按展示窗口自动分页，
不把期望读取更多记录当成接口故障。反汇编保留真实函数身份、符号化指令及跳转信息。
`disasm` 从请求地址处开始返回；同一地址用 `next_offset` 续读，或换成 `next_address`
并从 `offset=0` 继续，不会因 r2 返回整函数而反复展示第一页。返回地址同时给出十六进制
表示；有未读数据时还返回可直接复用的 `next_call` 参数，增大 `limit` 不会绕过单页展示预算。
`query` 为字面子串，不接受 `|` 正则分支。`binary_inspect` 可读取本题持久 `/tmp`
中的真实文件，无需先猜测其他路径或重复解压。
证据复盘保存早期实际观察，发送时压缩重复字段，但保留二进制名称、地址和分页状态，
原始参数及结果仍可按引用读回。

轻量 shell 启用 `pipefail`，中间命令失败不再被管道末尾的成功退出码遮蔽。
工具额外记录管道各段状态：上游仅出现 SIGPIPE（141）、末端成功且有输出时，展示为
“已获得部分输出”，不当成完整成功或基础设施故障。直接退出 141、缺少管道状态、
真实非零失败等不会被统一忽略；仍须核对 stderr 与输出完整性。
模型环境事实明确区分只读附件目录、可写工作目录与 artifacts，不自动改写命令或放宽权限。

## AWDP 修补提交

轻量控制台提供 CTF 与 AWDP（fix）。AWDP 以修补提交件为目标，不用 Flag 登记接口。
提交格式以原始题面和现场平台规则为准，常见为 `.sh` 修补脚本，也支持 gzip 压缩的
tar 归档。模型提示词及 `submit_fix` 契约均说明这两类提交件，不强制改成压缩包。
脚本应自包含，遵循平台的解释器、工作目录、权限和调用约定，不依赖本机会话临时文件。

`submit_fix` 接受 `archive`（兼容字段名，填 `patch.sh` 或 `fix.tar.gz` 路径）、字符串
数组 `files` 与 `description`。脚本的 `files` 声明将修改的原始目标文件，不填补丁脚本自身。
`.sh` 须为 UTF-8、无 NUL 的文本，最多 4 MiB；shebang 指定 sh/bash（支持
`/usr/bin/env sh` 或 `bash`），仅执行对应 shell 的 `-n` 语法检查，不运行脚本。
声明的目标文件须来自原始附件；语法检查不能证明脚本实际修改的文件范围或字节变化。
tar.gz 仍只含被修改文件，其内部相对路径须与原始附件一致，检查实际清单与字节变化。
两类提交件均拒绝跨题路径、目录穿越、链接和特殊文件；校验后的同一份快照复制到
会话 `artifacts/`，保留 `.sh` 或 `.tar.gz` 后缀供下载，不覆盖已有产物。

归档校验与登记**不能证明漏洞已经修复**，也不是比赛平台接收回执。应提供正常功能
与漏洞回归的实际测试证据；只做语法检查不够。无法完成时如实记录缺口。

## 诊断

审计可记录 `queue_duration_ms`、`load_duration_ms`、`prompt_eval_duration_ms`、
`eval_duration_ms` 和 `eval_tokens_per_second`。总等待时间不等于纯生成耗时，
不能把客户端前缀重复字节计作服务端真实缓存命中。

性能基准必须在没有其他 Ollama 任务争用模型、显存和推理槽时进行。

可用现有会话检查点离线回放上下文归档、工具配对、原文检索和笔记恢复：

```bash
.venv/bin/python scripts/replay_light_context.py --session /path/to/session --find main --output /tmp/light-context-report.json
```

脚本只读会话数据库和本机执行密钥，不修改原始历史、不执行历史工具、不调用模型。
报告的 Token 数是投影估算值，笔记恢复使用明确标记的测试笔记；通过不等同于模型已续跑解题成功。
